# Functional Content Brief: Goals List (Mission Board)

## 1. Purpose
Serves as mission control, providing a single, scannable view of all user missions organized by type, status, and priority. Enables users to check overall board momentum, track progress, identify chain sequences, and act on urgent next steps.

## 2. Entry and Exit Paths
*   **Entry Paths:**
    *   Bottom tab bar (Goals root, stack depth 0).
    *   Home Screen [12] via "view all missions" link.
*   **Exit Paths:**
    *   Mission Detail [14] (stack push via tapping a mission card).
    *   Create Mission [15] (modal present via FAB or Day-1 CTA).
    *   Life Areas Overview [16] (stack push via radar preview card).
    *   Mission Journal [73] (stack push via header journal icon).

## 3. Information Architecture (Top-to-Bottom)
1.  **Screen Header:** Title ("your missions") + Header Icons (Journal, Filter).
2.  **Type Filter Chips:** Horizontal scrollable row for scope filtering.
3.  **Status Segmented Control:** 3-segment pill for completion status filtering.
4.  **Board Summary Band:** High-level metrics (KPI tiles + MomentumBar). *(See contradiction flag #1)*
5.  **Life Areas Radar Preview:** Gateway card to holistic domain view.
6.  **Pinned Missions Section:** Conditional top-priority missions (max 3).
7.  **CIA Suggestions Section:** Conditional, collapsible AI recommendations.
8.  **Mission Card List:** Primary flatlist of all non-pinned missions.
9.  **Board Consistency Heatmap:** Ambient grid at the foot of the list showing trailing activity.
10. **Floating Action Button (FAB):** Persistent "+" creation button.

## 4. Features and Capabilities
*   **Two-Tier & Domain Filtering:** Filter missions by scope (type), completion (status), and specific life domains (via bottom sheet).
*   **Mission Tracking:** View progress rings, next actions, CIA coaching notes, XP, streaks, difficulty tiers, and chain positions.
*   **Inline Action Completion:** Complete the next actionable step directly from the list without navigating to detail screen.
*   **Quick Actions Menu:** Long-press a mission to pin/unpin, pause/resume, archive, or edit.
*   **CIA AI Suggestions:** Accept or dismiss AI-generated mission recommendations.
*   **Holistic Data Visualization:** View daily XP momentum, active/done/streak counts, quantified value-vs-targets, and historical consistency heatmaps.
*   **Motivation Adaptation:** Screen complexity dynamically scales between Low, Medium (default), and High motivation tiers.

## 6. Data Fields and Metrics
*   **Mission Progress (%):** *Source: Missions system.* Rendered in central GaugeRing.
*   **Mission Name, Next Action, CIA Note:** *Source: Missions system.*
*   **Mission Type (Life/Main/Side/Weekly/Daily):** *Source: Missions system.*
*   **Domain Assignments:** *Source: Missions system.* Used for filtering and identity tinting.
*   **Active / Done Today / Streak Counts:** *Source: `missions[]` (status, progress) and `board.streakDays`.* Displayed in Board Summary KPI tiles. Deltas calculated against `board.lastWeek`.
*   **Daily XP vs. Daily Goal:** *Source: `board.dailyXp` / `board.dailyXpGoal`.* Displayed in MomentumBar.
*   **Quantified Value vs. Target:** *Source: `mission.metric` (current, target, unit).* Displayed as MacroBar on quantified missions.
*   **Board Consistency History:** *Source: `board.advanceHistory` (date → count).* Displayed in CalendarHeatmap.
*   **Life Area Balance:** *Source: `domainStats`.* Displayed in mini ConstellationRadar.
*   **Lead Mission Trajectory:** *Source: `mission.progressHistory` (7 values).* Displayed as Sparkline on lead pinned mission.

## 7. Screen States
*   **Default (Medium Motivation):** Full visual complexity; all filters and metrics visible.
*   **Low Motivation:** Simplified view. Hides Type/Status filters, Board Band, Radar, CIA suggestions. Mission cards reduce to ring, name, and next action only.
*   **High Motivation:** Expanded CIA notes (2 lines). Type chips show count badges (e.g., "main (3)"). CIA suggestions auto-expand. Adds MacroBar, Sparkline, and sort options.
*   **Cold-Start / Day-1:** Centralized empty state. Hides all filters, metrics, and lists. Shows illustration, heading, CTA, and 3 tappable CIA starter chips.
*   **Filtered Empty:** List disappears, replaced by contextual empty message.
*   **Loading:** Radial sweep skeleton shimmers morphing into data.
*   **Partial / Syncing:** Structure preserved; missing data rendered as ghosted/dashed UI (never a silent zero).
*   **Error / Offline:** Cached data displayed with persistent banners/toasts and disabled refresh controls.
*   **Card Variants:** Default, Completed (green ring, reduced opacity), Paused/Overdue (desaturated ring, constructive copy), Pinned (pin icon visible).

## 8. Interactions, Gestures, Motion Intents
*   **Taps:** Open mission details; toggle inline actions; change filters; expand/collapse CIA suggestions; accept/dismiss suggestions; open quick-actions menu.
*   **Long-press (>500ms):** Trigger floating Quick Actions menu for a specific mission.
*   **Pull-to-refresh:** Force fetch/sync data.
*   **Motion Intent:** A "draw-first" choreography. The screen leads with the Board Summary Band filling L→R, followed by the Radar drawing in, then mission cards cascading downward (80ms stagger). The FAB hides on continuous downward scroll and reappears on upward scroll. Respects `prefers-reduced-motion` by rendering final static states instantly.

---
### ⚠️ Source Contradictions Flagged
1.  **Information Architecture Hierarchy:** The "Information Architecture" section lists "Mission cards... as the dominant visual pattern (1)." However, the "Visualization" and "Premium Craft" sections explicitly state the "Board summary band is the one above-fold focal viz" and that mission cards are deliberately "uniform secondary instruments." **Resolution applied:** The functional IA treats the Board Summary Band as the primary focal anchor above the fold, with mission cards serving as the primary scrolling content.
2.  **Decorative vs. Real Data Charts:** Early ASCII implies the Mini Radar is a decorative non-data element (`aria-hidden`, fake polygon). Later sections explicitly flag this as a violation and mandate it be upgraded to a real, data-bound `ConstellationRadar`. **Resolution applied:** Treated as a real-data visualization per the Visualization mandate.
3.  **Color-as-Verdict for Difficulty:** ASCII wireframes show "hard" difficulty as an alarm `error-red` dot. Visualization/Color Map sections explicitly ban this. **Resolution applied:** Difficulty is treated functionally as a neutral glyph + label (never red/alarm).
