## Test contracts

**dto.satisfies.test.ts**: for every fixture, unwrap the envelope (`fixture.data`) and assert assignability to its DTO via typed helper `function expectType<T>(v: T): T` (compile-time) + runtime smoke (key fields present). Envelope fields (`success === true`) asserted too. `error-401.json` asserts the error body shape (`success:false`, `code:'UNAUTHORIZED'`, string message).

**Adapter tests** — for each adapter:
1. Accepts its recorded fixture without throwing; snapshot-free structural asserts (explicit expects on key fields — NO `toMatchSnapshot`).
2. **Anti-fabrication invariants** (the batch's core):
   - overview (fresh fixture): `lifePower.value === null` AND `lifePower.provenance.kind === 'null'`; every pulse metric with fixture-null value stays `value:null`; NO metric in the whole VM has a non-null value where the fixture had null (write a recursive walker `collectMetrics(vm)` that finds `{value, display, provenance}` shapes and asserts the rule).
   - fitness: `score/recovery/weeklyMinutes` are ALWAYS null-kind even when plans exist (feed a synthetic plans array too); `planCount` equals array length.
   - missions: tier rule table-tested — `[{isPrimary:true, source:'life'} → 'life'; {isPrimary:true, source:'health'} → 'main'; {isPrimary:false, ...any} → 'side']`; status map `paused→blocked` etc.; empty goals → empty missions + zero summary.
   - life-areas: snake_case mapped (`display_name`→`name`); `momentum:null` → null-kind score; no `trend`/`drivers` keys exist on the VM (assert `'trend' in area === false`).
   - gamification: real fixture numbers map through (xp 1200 → 1200); no `lifePower` key (assert absent).
   - cia: `toCiaMessage` maps the fixture reply; `classifyCiaError` table-tested with synthetic `ApiError`s: (402,'FEATURE_DISABLED')→feature_disabled; (402,'CREDITS_EXHAUSTED')→credits_exhausted; (402,'PLAN_UPGRADE_REQUIRED')→plan_upgrade_required; (400,'MISSING_IDEMPOTENCY_KEY')→client_error; (500,undefined)→null gate; each userMessage distinct; copy uses 'Cia' casing where present.
   - trust: `toExportSummary` on the export fixture — table rows built from `counts`, `truncated === (exported < total)`, `anyTruncated` correct; synthetic truncated case tested.
3. Purity: adapters called twice with the same input give deeply-equal results.

**session-machine.test.ts**: transition table —
`booting --HYDRATED--> authenticated(user)`; `booting --NO_SESSION--> unauthenticated`;
`unauthenticated --SIGN_IN_START--> authenticating --SIGN_IN_SUCCESS--> authenticated`;
`authenticating --SIGN_IN_FAILURE--> unauthenticated(error set)`;
`authenticated --REFRESH_START--> refreshing --REFRESH_SUCCESS--> authenticated`;
`refreshing --REFRESH_FAILURE--> expired`; `authenticated --SIGNED_OUT--> unauthenticated(user null)`;
`authenticated --USER_UPDATED--> authenticated(new user)`; irrelevant events → state unchanged (e.g. REFRESH_SUCCESS while unauthenticated).

**keys.test.ts**: factory shapes (`overview()` = `['balencia','overview']`), missions filter defaulting, referential stability of `all`.

Rules: import fixtures ONLY via `@/services/adapters/__fixtures__`; no network, no mocks of fetch (adapters are pure); no `any` (narrow `unknown` fixtures with the DTO types); every test file runs in `node` env.
