# Functional Content Brief: Privacy Consent

## 1. Purpose
The legal gateway requiring explicit, non-shaming acceptance of Terms of Service and Privacy Policy before onboarding can proceed. Account already exists at this stage; progression is strictly gated by explicit user consent.

## 2. Entry and Exit Paths
*   **Arrives from:** 
    *   OTP Verification [03b] via stack push (email registration path)
    *   Complete Profile [03d] via stack push (social auth path)
*   **Primary Exit:** CIA Onboarding [07] via stack push upon API success
*   **Abandonment:** Force-quitting the app returns the user to this screen on next launch (no back button, as the account is already created).

## 3. Information Architecture
**Scroll Behavior:** None (fixed view fitting all device sizes). 
**Tab Bar:** Hidden (pre-auth).

**Layout Regions (Top to Bottom):**
1.  **Status Bar Zone:** System default.
2.  **Brand Anchor:** Balencia symbol (48x48pt). 
3.  **Header Zone:** Heading and supporting subtitle (center-aligned).
4.  **Required Consents Card:** Container for two mandatory legal gating rows, separated by a divider. 
5.  **Optional Consents Card:** Container for optional marketing opt-in. 
6.  **Acceptance Read:** Progress indicator (2-of-2) and success/error messaging.
7.  **Primary CTA:** Full-width submission button.
8.  **Spacer & Home Indicator:** Bottom safe area.

## 4. Features & Capabilities
*   **Explicit Legal Consent:** Mandatory acceptance of Terms of Service and Privacy Policy. Defaults to unchecked (zero dark patterns).
*   **Granular Row Interaction:** The non-link portion of a consent row toggles the checkbox, while the policy link itself is an independently tappable target.
*   **In-App Policy Viewer:** Direct, frictionless access to read the real legal policies via an in-app browser without losing screen state.
*   **Optional Marketing Opt-in:** Non-gating toggle for email marketing.
*   **Gate-State Visualization:** A "2-of-2" visual acceptance read that confirms when the user has met the requirements to proceed.
*   **Auto-Latching CTA:** The primary button automatically transitions from disabled to enabled the moment the 2-of-2 requirement is met.

## 6. Data Fields & Metrics
*   **Terms of Service Consent** (Data Source: Local State -> `POST /api/auth/consent`) - Boolean.
*   **Privacy Policy Consent** (Data Source: Local State -> `POST /api/auth/consent`) - Boolean.
*   **Email Marketing Opt-in** (Data Source: Local State -> `POST /api/auth/consent`) - Boolean (Default OFF).
*   **Acceptance Counter** (Data Source: Derived Local State) - Counts the number of checked required consents (0, 1, or 2).

## 7. Screen States
*   **Cold Start / Day-1 (Canonical):** Both required boxes unchecked. Optional toggle OFF. Acceptance read shows "0 of 2 required". CTA is disabled (opacity reduced).
*   **Partial Accept:** One required box checked. Acceptance read shows "1 of 2 required". CTA remains disabled.
*   **Gate Ready (Pre-submit):** Both required boxes checked. Acceptance read shows "2 of 2 · ready" with color shift. CTA becomes fully opaque and interactive.
*   **Loading:** API POST is in flight. CTA text crossfades to a spinner. CTA becomes non-interactive.
*   **Success:** Brief success flash, then stack push navigation.
*   **Inline Error:** Triggered if CTA is tapped while gate is incomplete (or if checkbox is unchecked while CTA is active). Displays validation error text.
*   **Network Error (Toast):** Triggered on 5xx or network loss during POST. Reverts CTA to default state.
*   **Server Error (Toast):** Triggered on 400 validation fail during POST. Reverts CTA to default state.
*   **Offline:** Device loses connection. CTA text changes; CTA disabled.

## 8. Interactions & Motion Intents
*   **Tap (Consent Row):** Toggles checkbox state. Expands 44pt touch target around visual element.
*   **Tap (Policy Link):** Opens system webview over the screen.
*   **Tap (Optional Toggle/Row):** Slides toggle thumb left/right. 
*   **Motion (Screen Entrance):** Staggered fade-in moving downwards (Logo first, CTA last).
*   **Motion (Checkbox/Toggle):** Snappy fill animations and thumb slides. 
*   **Motion (CTA Enable/Disable):** Smooth opacity crossfade based on gate state.
*   **Motion (Error Messaging):** Slide down when appearing; slide up when dismissed.
*   **Motion (Success):** Brief flash before navigation.
*   *Accessibility note: All touch targets expand to a minimum of 44x44pt.*

## 10. Cross-Domain Hooks
*   **CIA Onboarding (Screen 07):** The successful POST /api/auth/consent updates the user's backend `onboarding_status` to `assessment_pending`. This serves as the direct hook that unblocks the CIA persona from initializing the user's life-area assessment flow on the next screen.
*   **Settings (Screen 21):** The Optional email marketing toggle establishes a core data point that hooks directly into the app's broader notification/user preferences domain, reusable in global settings.
