# 2. Purpose
A secure, functional destination for users tapping a password reset email link. It validates the token on mount and enables the user to securely establish a new password, routing them to sign-in upon success. 

# 3. Entry & exit
- **Entry Paths:** Deep-linked via email (`balencia://reset-password?token=xxx`). No back button is rendered.
- **Exit Paths:** 
  - **Success:** Root reset navigation to Sign In [04].
  - **Manual Escape:** Sign In [04] via secondary links.
  - **Recovery:** Forgot Password [05] via "request new link" to generate a new token.

# 4. Layout anatomy
**Regions (Top-to-Bottom):**
1. **Atmosphere / Status Zone:** Blank dark space with the mandatory warm top-glow to anchor the screen visually.
2. **Brand Zone:** Center-aligned Balencia wordmark/brand mark.
3. **Messaging Zone:** Hero heading and instructional subtext.
4. **State Zone:** 
   - *Default:* Password creation form and real-time requirement cluster.
   - *Terminal:* Success checkmark or warning glyph.
5. **Action Zone:** Full-width primary CTA.
6. **Secondary Action Zone:** Text link for manual escapes (visible only in terminal/expired states).

- **BtnGhost**: Used for the secondary "back to sign in" text link.

# 8. Data & honesty states
Per the canon, metrics must be honest. Security flows lack standard data sync metrics, but we enforce the 3-state invariant on the **Token Validation metric**:
- **Real:** Green checkmark + provenance chip text: `verified · via auth provider`.
- **Low-confidence:** N/A (Token validation is binary; it cannot be estimated).
- **Honest-null (Terminal Error):** Warning glyph + Body-light line: `Not a valid link — request a new one to reset your password`.

# 9. All states
- **Cold-Start / Loading:** Centered `SkeletonState` shimmer blocks (masking form layout) + spinner. Instructional copy reads: "Checking your reset link…"
- **Default (valid token):** Form inputs rendered, CTA structurally disabled until all 5 requirements + match conditions are met.
- **Match (inline):** 150ms transition to green 1px border on confirm field.
- **Mismatch (inline):** 150ms transition to red 1px border on confirm field, error text appears below.
- **Submit Loading:** Inputs lock, CTA text swaps for spinner, width locked.
- **Error / Expired:** `ErrorState` terminal screen fades in statically.
- **Success:** `SuccessCard` scales from 0.5 → 1.0 with continuous-stroke line motif drawing the checkmark.
- **Offline:** Form dims to 40% opacity, `OfflineBanner` drops down: "You're offline — connect to the internet to continue".

# 10. Motion & interaction
- **Staggered Entry:** Form elements rise and fade in sequentially (280ms) using physical easing `cubic-bezier(0.16, 1, 0.3, 1)`.
- **Glow Breathe:** The `--glow-you` container radial gently breathes (4s ease) to signify active, secure state. 
- **Haptics:** Light impact haptic on requirement condition met; medium impact haptic on successful password reset submission.
- **Continuous-Stroke Splash:** On Success state, the checkmark glyph draws itself over 520ms while the radial glow intensifies. Warning state omits scale and drawing—pure crossfade to respect the passive, non-urgent tone.
- **Reduced Motion:** All staggered entries and stroke motifs snap instantly to final state. Glow breathe halts. Spinners remain active but static.

# 12. Accessibility
- **Contrast:** Paper-100 (#FEFAF3) over `--bg-base` (#0A0A0F) exceeds 16:1 (WCAG AAA). 
- **Targets:** The "eye" icon inside `GlassPillInput` has a 44x44px invisible tap boundary expanding past its 24x24px glyph. BtnPrimary height is 52px.
- **Screen Reader:** Glyph-only toggles are fully mapped. Eye icon label: "Hide password" / "Show password". The requirement cluster is grouped as an `update` live region; it announces: "Password requirements: 5 of 5 complete" without reading all 5 individually on every keystroke.
