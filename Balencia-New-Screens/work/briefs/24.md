### 1. Purpose
A scrollable log of past notifications grouped by date, allowing users to revisit dismissed insights, reminders, and check-ins. It also acts as a passive signal of CIA’s (Coach Persona) activity, reinforcing that the AI is continuously working behind the scenes on the user's behalf.

### 2. Entry and exit paths
*   **Entry Paths:**
    *   Stack push (depth 1) from the Me Main screen [17] via the quick link grid.
*   **Exit Paths:**
    *   **Primary:** Deep-link navigation to relevant screens via tap (CIA Chat [09], Goal Detail [14], Home Screen [12], Community [40]).
    *   **Secondary:** Stack pop back to Me Main [17] via back button or edge swipe.

### 3. Complete information architecture
**Top-to-bottom hierarchy:**
1.  **Navigation Header:** Back chevron, "Notifications" title, "Mark all read" action (right-aligned).
2.  **Summary Band (Focal Point):** 
    *   *Count Chips:* 4 category tiles (CIA, Reminder, Check-in, Social) with icon, label, and count.
    *   *Frequency Pulse:* 7-point curved sparkline showing daily notification count.
    *   *Caption:* Summary text (e.g., "last 7 days").
3.  **Date Group Headers:** Sticky, temporally grouped labels (Today, Yesterday, This week, Earlier, or specific dates).
4.  **Section Group Containers:** Rounded cards holding the notification rows, separated by thin dividers.
5.  **Notification Rows:** Individual tap targets containing unread dot, category icon, title, preview text, and relative timestamp.
6.  **Tab Bar:** Global navigation (Me tab active).

### 4. Features and capabilities
*   **Deep-link Navigation:** Tapping any notification row routes the user to the specific originating screen (e.g., CIA Chat for insights).
*   **Optimistic Mark-as-Read:** A utility action to instantly clear all unread indicators across the screen.
*   **In-Place Category Filtering:** Tapping a count chip in the summary band filters the list to that specific category. Tapping it again clears the filter.
*   **Frequency Scrubbing:** Long-pressing the frequency sparkline reveals the exact per-day count at the finger's position.
*   **Pull-to-Refresh:** Standard gesture to fetch the latest notification data from the API.
*   **Live Push Ingestion:** If a new notification arrives while the user is actively on the screen, it slides in at the top of the "Today" group automatically.

### 6. Data fields and metrics
*   **Notification Category:** Derived from Notifications API (CIA insight, Reminder, Check-in, Social).
*   **Title & Preview Text:** Pulled directly from the Notifications API payload.
*   **Timestamp:** ISO format from API, computed to relative time (e.g., "2h ago") or absolute date.
*   **Read/Unread Status:** Boolean from Notifications API.
*   **Deep-link Target:** URL/Route string defined in the API payload.
*   **By-Type Counts:** Computed locally by tallying the loaded notifications per category over a fixed 7-day window.
*   **Frequency Pulse (frequency7d):** Array of 7 daily counts computed from notification timestamps, visualized as a sparkline.

### 7. All screen states
*   **Cold-start / Day 1:** Summary band is entirely suppressed. Displays a warm empty state with a bell glyph and CIA's onboarding promise. "Mark all read" is disabled.
*   **Established (All Read):** No unread dots visible. "Mark all read" action is disabled. 
*   **Loading / Skeleton:** Summary band shows skeleton bars instead of numbers; sparkline shows a flat baseline that morphs into the drawn line. Notification rows show standard skeleton shimmers preserving layout.
*   **Empty / Sparse (< 3 days history):** Summary band shows populated categories (0-count chips omitted). Sparkline shows individual dots without a connecting line and the caption "Building your activity trail".
*   **Error (Failed Load):** Summary band is suppressed. Centered text: "Couldn't load notifications. Pull to refresh."
*   **Error (Mark-as-Read Fail):** Unread dots remain visible. Toast: "Couldn't mark as read. Try again".
*   **Error (Deep-link Target Unavailable):** Notification routes, but the target screen handles displaying its own error state.
*   **Offline:** Cached list remains visible. Banner below header: "You're offline. Some notifications may be outdated".

### 8. Interactions, gestures, motion intents
*   **Taps:** 
    *   Row: Deep-links + triggers optimistic read status sync.
    *   "Mark all read": Triggers atomic simultaneous fade-out of all unread dots (280ms) + haptic.
    *   Category Chip: Filters list in-place; active state shows a 2pt orange ring.
*   **Long-press:** Sparkline scrub to reveal per-day data points.
*   **Swipes:** Right-from-edge to navigate back.
*   **Pull:** Standard pull-to-refresh mechanic.
*   **Scroll:** Vertical scroll; sticky date headers activate background backdrop-blur on scroll.
*   **Motion Choreography:** On entry, the summary band settles first (count-up numbers). Next, the sparkline draws itself left-to-right via stroke-dashoffset (1200ms). Finally, the notification rows stagger in (fade + slide up 12pt).
