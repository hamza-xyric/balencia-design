# Packet V4 — CIAPresenceOrb (the ONE purple-sanctioned component)

## Objective

Create **`CIAPresenceOrb`** — a standalone, non-interactive presence indicator: a breathing purple-core orb that is the visual signature of Cia (Balencia's AI coach) wherever she appears. It renders three states (`idle` / `listening` / `thinking`), each a distinct Reanimated animation, with a reduced-motion static fallback. This is the **only** component in the BIOS-004 viz kit permitted to use royal purple as its primary color (canon: purple is reserved for Cia/AI surfaces only — everywhere else in this batch, purple usage is a bug).

This packet builds the **leaf component only**. It is consumed by the Today screen's CIA coach card (architecture-plan.md §4.1, row 2: `GlassCard.hero + CIAPresenceOrb + mood chips`) in a **separate, later packet** (wave 4a, "Today recompose") — wiring it into any screen is explicitly out of scope here.

```typescript
 * drift across GLM-authored components").
 *
 * Framework-agnostic ON PURPOSE — this file exports only plain numbers,
 * tuples, and objects. It does NOT import 'react-native' or
 * 'react-native-reanimated'.
 *
 * Verified live 2026-07-09: `import { Easing } from 'react-native-reanimated'`
 * throws during Vitest collection under this project's test config
 * (vitest.config.ts -> environment: 'node'):
 *   "Cannot find module '.../react-native-worklets/lib/module/initializers/
 *    initializers' imported from .../react-native-worklets/lib/module/index.js"

 * does not exist under plain Node. src/**\/*.test.ts (vitest.config.ts
 * `include`) collects ANY test that transitively imports this file, so a
 * top-level reanimated import here would break every future test that
 * touches motion.ts. Component files that actually animate (running under
 * Metro/the RN runtime, never under Vitest) build the real Reanimated easing
 * curve at the call site:

 *   import { Easing } from 'react-native-reanimated';
```

```typescript
import { useEffect, useRef, useState } from 'react';
import type { JSX } from 'react';
import {
  AccessibilityInfo,
  Animated,
  Easing,
  LayoutChangeEvent,
  LayoutRectangle,
  Pressable,
  StyleSheet,
  Text,
  TextInput,
  View,
  ViewStyle,
} from 'react-native';

import { BalenciaColors, Radius, Spacing, TouchTarget } from '@/constants/theme';

// ─── Hook: useReducedMotion ─────────────────────────────────────────────
export function useReducedMotion(): boolean {
  const [reduceMotion, setReduceMotion] = useState(false);
  useEffect(() => {
    const handle = (isReducedMotion: boolean) => setReduceMotion(isReducedMotion);
    AccessibilityInfo.isReduceMotionEnabled().then(handle);
    const sub = AccessibilityInfo.addEventListener('reduceMotionChanged', handle);
    return () => sub.remove();
  }, []);
  return reduceMotion;
}
```

This is a 4-layer stack (outer soft wash → pulsing mid halo → solid glowing core → bright white specular highlight). RN has no CSS `blur()` filter for arbitrary content (no `expo-blur`/`BlurView` in this batch's dependency list — do not add one; ADR-7 authorizes exactly three new deps and neither is a blur module). Approximate the soft-edge look with **stacked semi-transparent circles of decreasing opacity/increasing inset** (the same structural trick the web reference already uses — its "blur" is a `filter: blur()` on top of *already-layered* circles, so the layering alone reads correctly without a true blur primitive) plus an iOS shadow for the glow. Use `expo-linear-gradient`'s `LinearGradient` (see API embedded above) for the innermost core layer to create the "solid orb with a bright highlight" read (e.g. a short diagonal gradient from a lighter purple/white-tinted stop near one corner to the base purple, clipped to a circular `View` via `borderRadius: size/2, overflow: 'hidden'`) — this satisfies ADR-1's "soft radial via expo-linear-gradient" requirement literally (the component must actually render a `LinearGradient`, not just plain-color circles).

**Idle-breathe timing conflict — resolved (flagged for the record):** the web reference's own CSS (`globals.css` line 562: `.quiet-pulse { animation: quiet-pulse 8000ms var(--ease-in-out-brand) infinite; }`) uses **8000ms**, not 4s, and animates `transform: scale(0.96↔1.04)` + `opacity: 0.78↔1`. This contradicts both the canon catalog text ("idle breathe **4s** ease") and ADR-6/`MotionBreathe` (`durationMs: 4000, opacityMin: 0.55, opacityMax: 1`). **ADR-6 + the live `motion.ts` constant govern this packet** (source hierarchy: architecture-plan.md ADRs are binding for BIOS-004; the web prototype's raw CSS number is informative-layering-reference only, not a motion-duration authority for this batch). **Listening / thinking timing — underspecified, implementer judgment (flagged, not fabricated as canon):** no source document gives an exact duration or easing for the "listening ring pulse" or "thinking slow rotation shimmer" states. Canon only names the *shape* of each ("ring pulse", "slow rotation shimmer"). Reasonable choices consistent with the rest of this system: listening — an additional ring element (not present in idle) pulses opacity/scale on its own faster loop (e.g. ~1200–1600ms) to read as "actively receiving," distinct from the calmer 4000ms idle breathe; thinking — a highlight/gradient layer rotates or sweeps continuously (`Easing.linear` is an accepted, conventional exception to "physical easing, never linear" specifically for constant-speed rotation loops — a non-linear infinite spin reads as mechanically wrong) at a "slow" pace (≥1500ms per revolution). These are non-binding implementation defaults; acceptance below checks that the three states are *visually distinct and each respects reduced-motion*, not exact millisecond values.
