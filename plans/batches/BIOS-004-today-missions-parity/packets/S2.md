## Objective

literally saying "INTERIM (BIOS-004 mid-batch)... until then these map to the existing chip

## Design requirements

Section order (architecture-plan.md §4.2, scope-hifi §"Screen 13"):

**1. TopBar.** `BalenciaScreen` `eyebrow="Mission board"` `title="your missions"` (sentence case,
exact copy from the hi-fi wireframe) `subtitle="Missions are mapped from unified goals when signed
in."` (unchanged carryover). **Known simplification (document, don't silently deviate):**
`screen.tsx`'s header has no action-glyph slot, so the 44px filter-toggle glyph renders as the
FIRST row inside the body (`children`), right-aligned, immediately under the title — not literally
inside the title row. It toggles the tier-filter-chip row's visibility (local `filtersOpen` state).
Glyph: `▤` character, hidden from screen readers (`accessibilityElementsHidden` +
`importantForAccessibility="no"`) with the meaning carried by the parent `Pressable`'s
`accessibilityLabel` ("Show mission filters" / "Hide mission filters"). Journal glyph: **do not
render** (A2 — hidden this batch, S73/BIOS-005).

**2. Summary band.** Three `GlassStatCard` (`variant` defaults to `'metric'`), each wrapped in its
own `<View style={{flex:1}}>` (the component has no style/flex prop) inside a horizontal row:
- **Active**: `realMetric(data.summary.active, {source:'server', label:'via missions sync'})`, `glow="you"`.
- **Done**: `realMetric(data.summary.completed, {source:'server', label:'via missions sync'})`, `glow="done"`.
- **Streak**: gated on the INDEPENDENT `useGamification()` query — `gamificationStatus === 'success' && gamification !== undefined` → `realMetric(gamification.streak, {source:'server', label:'via gamification stats'})`, else `nullMetric('Not enough data yet')`. Always `glow="you"`.

ACTIVE/DONE are never null (they come from the already-gating missions query — by the time this
section renders, `status` is `'success'`). STREAK independently degrades to honest-null if the
gamification query hasn't resolved, without blocking the rest of the screen.

Below the three tiles, one `MomentumBar` for "XP to next level": `value={levelProgress?.currentXP ?? 0}`,
`max={levelProgress?.xpForNextLevel ?? 100}`, `state={xpLabel === null ? 'null' : 'real'}`,
`label={xpLabel ?? 'Not enough data yet'}`, `glow="you"`, where `levelProgress` is
`gamification.levelProgress` when the gamification query succeeded, else `null`, and
`xpLabel = xpToNextLabel(levelProgress)`. The band-fill entrance (S13: "Board Summary Band fills
L→R (250ms)") is **already implemented inside `MomentumBar`** via `MotionDuration.bandFill` — do
not add a second animation around it.

**3. Status tabs + tier filter chips.** `SegmentedTabs` with `options={[{key:'active',label:'active'},{key:'done',label:'done'},{key:'all',label:'all'}]}`,
controlled by local `statusTab` state (default `'active'`), `accessibilityLabel="Filter missions
by status"`. Below it, when `filtersOpen`, render a local `TierFilterRow` subcomponent: one
`ChipDomainTag` per `ALL_TIERS` entry (all six, including `group` — it will just never have a
matching mission this batch, which is honest and adapter-driven, not hidden), `label={tierLabel(tier)}`,
`active={tierFilter.includes(tier)}`, `onPress` toggles that tier in/out of the local `tierFilter`
array (multi-select; empty array = no tier filtering, per `filterMissions`'s contract).
`TierFilterRow` reveals with a `useSharedValue`-driven opacity+translateY fade using
`MotionDuration.accordion` (200ms) + `Easing.bezier(...MotionEasing.physical)`, gated on
`reduceMotion` (instant to final state when true) — mirrors `momentum-bar.tsx`'s exact
`if/else`-inside-`useEffect` shape, shared value included in the deps array. Closing
(`filtersOpen` → false) unmounts the row instantly (no exit animation) — this is an accepted,
documented simplification (no `LayoutAnimation`/`entering`/`exiting` API is introduced; only the
reveal animates, matching the one Reanimated pattern already established in this codebase).

**4. Life-areas radar — honest ghost (ADR-10, deferred).** A `GlassCard` containing: `CardTitle`
"Life areas"; a static `View` styled as a 96×96 circle with `borderWidth:2`,
`borderStyle:'dashed'`, `borderColor: BalenciaColors.hairlineStrong` (no data, no draw animation —
animating a "draw" on a placeholder would imply real data that doesn't exist, so it is
deliberately static); `CardBody` "Constellation radar arrives with life areas" (exact copy, no
period needed to match the sentence-case/no-exclamation copy rule literally as an honest-null
label). Wrap the whole card in an outer `<View accessible accessibilityRole="text"
accessibilityLabel="Life areas radar, arrives with life areas">` for a single screen-reader stop.

**5. Mission list.** `filteredMissions = filterMissions(data.missions, statusTab, tierFilter)`
(memoized). If empty: `HonestNullState` — `title="No missions yet"` /
`detail="Create your first mission with Cia."` when `data.missions.length === 0` (genuinely no
missions at all), else `title="No missions here yet"` / `detail="Try a different status or tier
filter."` (filtered-empty, a different honest state — the board isn't empty, the current filter
combination just matches nothing). Otherwise render one local `MissionRow` per mission:
- Outer `Animated.View` = the tier metal accent: `borderLeftWidth:3`, `borderLeftColor:
  MissionMetalColors[mission.tier].solid`, `borderRadius: Radius.lg`, `overflow:'hidden'` — plus the
  cascade animated style (opacity + translateY, see below).
- Inner `Pressable` (`accessibilityRole="button"`, `accessibilityLabel` = `"{title}, {tierLabel},
  {rounded progress} percent complete"`, `onPress={() => router.push(\`/mission/${mission.id}\` as Href)}`)
  wraps a `GlassCard` (`tone={mission.status === 'complete' ? 'green' : 'default'}`) containing a
  horizontal row: a 36px/4px-stroke `ProgressRing` (`glow={mission.status === 'complete' ? 'done' :

```typescript
/**
 * Pure logic for the missions board (S13 parity, packet S2). No
 * react-native / reanimated / '@/constants/theme' imports — this file must
 * stay safely importable under Vitest's node environment (see
 * constants/motion.ts header: any transitive react-native-reanimated import
 * breaks src/**\/*.test.ts collection). Only TYPES are imported from
 * services/adapters/missions (a type-only import erases at compile time, so
 * it pulls in no runtime react-native dependency).
 */
import type { MissionTier, MissionVM } from '@/services/adapters/missions';

export type StatusTab = 'active' | 'done' | 'all';

/** Canon tier order — matches `MissionMetalColors` key order in
 *  `constants/theme.ts` (life/main/side/weekly/daily/group). The screen
 *  renders one ChipDomainTag per entry, including 'group' — ADR-4: no
 *  mission ever maps to 'group' this batch (no server squad/group signal),
 *  so the chip renders honestly inert rather than being hidden or faked. */
export const ALL_TIERS: readonly MissionTier[] = [
  'life',
  'main',
  'side',
  'weekly',
  'daily',
  'group',
] as const;

const TIER_LABELS: Record<MissionTier, string> = {
  life: 'Life mission',
  main: 'Main mission',
  side: 'Side mission',
  weekly: 'Weekly mission',
  daily: 'Daily mission',
  group: 'Group mission',
};

/** Sentence-case RPG tier label (canon copy rule: sentence case, no
 *  exclamation marks). Pure lookup — never guesses a tier outside the map. */
export function tierLabel(tier: MissionTier): string {
  return TIER_LABELS[tier];
}

/**
 * Status-tab + tier-chip filter, applied together (AND).
 *
 * Status:
 * - 'active' matches VM status 'active' OR 'blocked' (missions.ts mapStatus:
 *   'blocked' means paused-but-still-on-board, not done).
 * - 'done' matches VM status 'complete' only.
 * - 'all' passes every status.
 *
 * Tier: an EMPTY tierFilter means NO tier filtering (every tier passes) —
 * that is the default/unfiltered state, never "match nothing".
 */
export function filterMissions(
  missions: readonly MissionVM[],
  statusTab: StatusTab,
  tierFilter: readonly MissionTier[],
): MissionVM[] {
  return missions.filter((mission) => {
    const statusMatch =
      statusTab === 'all' ||
      (statusTab === 'done' && mission.status === 'complete') ||
      (statusTab === 'active' && (mission.status === 'active' || mission.status === 'blocked'));
    if (!statusMatch) {
      return false;
    }
    return tierFilter.length === 0 || tierFilter.includes(mission.tier);
  });
}

export interface LevelProgressInput {
  currentXP: number;
  xpForNextLevel: number;
}

/**
 * Honest "XP to next level" copy for the MomentumBar label.
 *
 * `null` input (the gamification-stats query has not resolved) returns
 * `null` — the caller renders the MomentumBar honest-null state. NEVER
 * fabricates a number when the source query has not confirmed one.
 */
export function xpToNextLabel(levelProgress: LevelProgressInput | null): string | null {
  if (levelProgress === null) {
    return null;
  }
  const remaining = Math.max(0, levelProgress.xpForNextLevel - levelProgress.currentXP);
  return `${remaining} XP to next level`;
}
```

```typescript
function TierFilterRow({
  tierFilter,
  onToggleTier,
  reduceMotion,
}: {
  tierFilter: MissionTier[];
  onToggleTier: (tier: MissionTier) => void;
  reduceMotion: boolean;
}) {
  const progress = useSharedValue(reduceMotion ? 1 : 0);

  useEffect(() => {
    if (reduceMotion) {
      progress.value = 1;
    } else {
      progress.value = withTiming(1, {
        duration: MotionDuration.accordion,
        easing: Easing.bezier(...MotionEasing.physical),
      });
    }
  }, [reduceMotion, progress]);

  const animatedStyle = useAnimatedStyle(() => ({
    opacity: progress.value,
    transform: [{ translateY: (1 - progress.value) * -6 }],
  }));

  return (
    <Animated.View style={[styles.tierRow, animatedStyle]} testID="missions-tier-filter-row">
      {ALL_TIERS.map((tier) => (
        <ChipDomainTag
          key={tier}
          label={tierLabel(tier)}
          active={tierFilter.includes(tier)}
          onPress={() => onToggleTier(tier)}
          testID={`missions-tier-chip-${tier}`}
        />
      ))}
    </Animated.View>
  );
}
```
