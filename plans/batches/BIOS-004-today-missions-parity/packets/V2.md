import { useEffect, useState } from 'react';
import { AccessibilityInfo } from 'react-native';

// ─── Hook: useReducedMotion ─────────────────────────────────────────────
export function useReducedMotion(): boolean {
  const [reduceMotion, setReduceMotion] = useState(false);
  useEffect(() => {
    const handle = (isReducedMotion: boolean) => setReduceMotion(isReducedMotion);
    AccessibilityInfo.isReduceMotionEnabled().then(handle);
    const sub = AccessibilityInfo.addEventListener('reduceMotionChanged', handle);
    return () => sub.remove();
  }, []);
  return reduceMotion;
}

## Behavior specification (fills in what the terse inline contract comments leave implicit — binding)

1. **Coordinate mapping.** Use an internal virtual coordinate space (suggest `300` wide) and let SVG's `viewBox` + `width="100%"` scale it to the actual rendered width — do not hand-measure the container for the geometry itself (only for scrub touch mapping, point 6). Map each point's index across the available point count to X, and its `y` value across the plotted set's `[min, max]` to Y (inverted, since SVG Y grows downward). Leave inset padding on all four edges so stroke width and dot radii never clip.

2. **Line vs. dots-only threshold.** Count only points where `(kind ?? 'actual') === 'actual' && y !== null`. If that count is `< 3`, render each as a standalone `Circle` (orange fill) — **no connecting `Path`/line** at all. At `>= 3`, render one continuous `Path` through them in index order (straight `L` segments — no curve smoothing; the source specs never describe curve interpolation, so do not invent one).

3. **Honesty-state rendering (`state` prop, default `'real'`).**
   - `'real'`: full-opacity geometry as described above.
   - `'low'`: same geometry, but the actual-line/actual-dots render at reduced opacity (muted) to signal "estimated · low confidence." Do not change color or invent a new token for this — opacity only.
   - `'null'`: render **only the gridlines** (see point 5) — no actual line/dots, no projected line, no marker dots, regardless of what `points` contains. Per the contract's inline comment, the honest-null copy ("Not enough data yet — N more days") is the **caller's** responsibility (rendered by the composing screen/card around this chart, e.g. inside the same frame per COMPONENT-CATALOG's "HonestNullState inside chart frame" note) — TrendChart itself never renders text and never fabricates a line through absent data.
   - Defensive case: if `state !== 'null'` but `points` has zero eligible values, degrade gracefully to the same "gridlines only" appearance rather than throwing or dividing by zero.

4. **Projection line (`showProjection`, default `false`).** Purple is reserved for Cia/AI surfaces (COMPACT-CANON §4: "Royal Purple ... projected/AI data"). Only render points with `kind === 'projected' && y !== null`, and only when `showProjection` is `true` — this is the caller's explicit "this is a Cia surface" opt-in; never render a purple line just because projected points exist in the array. Render as a dashed stroke (visually distinguishable from the solid actual line — a static dash pattern is fine, e.g. `"6 6"`). If there are prior actual points, anchor the projected line's first segment to the last actual point so the two lines appear continuous; if there are no actual points, the projected line starts from its own first point.

5. **Gridlines.** Always render (in every state, including `'null'`) a small number of horizontal reference lines using `BalenciaColors.chartGridline` (`rgba(255,255,255,.05)`, already in `theme.ts` — confirmed added specifically for this component per its comment: "BIOS-004 ADR-2, component contracts §3 — ProgressRing track, TrendChart gridlines"). 3 evenly-spaced lines across the plot height is sufficient; do not draw a border/frame rectangle.

6. **No area fill — resolved conflict, plan wins.** The architecture-plan.md contract line is explicit and unqualified: *"no area fill."* COMPONENT-CATALOG.md's TrendChart entry has looser wording ("No area-fill gradients beyond single-color 12% fade") that would technically permit a subtle fill. **Follow the plan, not the catalog, for this packet** — per this task's binding source hierarchy (architecture-plan.md §component contracts, with §11 amendments, is the exact-verbatim authority for this packet). Do not add any `Path`/`Polygon` fill under the line, gradient or otherwise.

7. **Milestone/marker dots.** Points with `kind === 'marker' && y !== null` render as small filled circles in `BalenciaColors.green`, plotted on the same value scale as the actual/projected points (i.e., compute `min`/`max` across all eligible actual+projected+marker values together, not per-series), regardless of the line-vs-dots threshold in point 2 (markers are independent of the actual-line decision). Suppressed entirely in `'null'` state per point 3.

8. **Animation — SVG stroke-reveal is the one documented exception to "transform/opacity only."** ADR-1 explicitly assigns this technique to this exact component: *"animate SVG geometry via Reanimated `useAnimatedProps` on `Animated.createAnimatedComponent(Circle|Path|Line)` (ring sweep and line-draw = animated `strokeDashoffset`)."* Use `Animated.createAnimatedComponent(Path)` from `react-native-svg` + Reanimated's `useAnimatedProps`/`useSharedValue`/`withTiming` to animate the **actual** line's `strokeDashoffset` from its full computed path length down to `0` over `MotionDuration.draw` (400ms), eased with `Easing.bezier(...MotionEasing.physical)`. Since the path is straight-line segments only (point 2), the true path length is exactly the sum of Euclidean distances between consecutive plotted points — compute it directly in JS rather than calling a native `getTotalLength()`. Set a static `strokeDasharray` of `[length, length]` on the same `Path` so the offset animation reveals it left-to-right with no repeating dash artifact. If a projected line renders, fade its opacity in from `0` to `1` (transform/opacity path — no dash-offset needed for a dashed line) starting after the actual line's draw completes (`withDelay(MotionDuration.draw, withTiming(1, ...))`), matching spec S14's "solid orange L→R, dashed purple after." Dots-only mode and marker dots do not need bespoke draw-in motion (not specified in any source spec) — render them without extra animation.

9. **Reduced motion.** When `useReducedMotion()` is `true`, skip straight to the final drawn state — `strokeDashoffset` at `0` and projected opacity at `1` immediately, no timing/delay calls at all (ADR-6: "skip to final static state").

10. **Scrub (`onScrub`).** When provided, wire touch handling so dragging across the chart calls `onScrub` with the nearest `TrendPoint` (by X position) among all points with `y !== null` (actual + projected combined; markers are point-in-time annotations, not scrub targets — exclude `kind === 'marker'`). Use core `View` gesture-responder props (`onStartShouldSetResponder`, `onResponderGrant`, `onResponderMove`) — no new dependency needed (`react-native-gesture-handler` is present in the repo but not required for this simple case). Capture the rendered width via `onLayout` for the touch-to-index ratio (this is the one place actual measured width matters — the SVG geometry itself always uses the virtual coordinate space per point 1). No-op (do not attach responder handlers) when `onScrub` is undefined or in `'null'` state.

11. **44px touch target.** The chart's own `height` defaults to 160 (well over 44), but a caller could pass a smaller `height`. When `onScrub` is provided, apply a `hitSlop` on the responder `View` that pads the touchable region up to at least `TouchTarget` (44, from `theme.ts`) tall, so the scrub target is never smaller than 44px regardless of the visual chart height. No touch target is needed when `onScrub` is absent (the chart is then purely decorative/read-only).

12. **No axis tick labels.** Neither the contract's props nor `TrendPoint` carry axis-label data or typography instructions beyond "gridlines" — do not render X/Y tick text. This stays purely geometric (gridlines + line/dots), consistent with what the contract mechanically specifies.

13. **A11y.** Set `accessible`, a generic `accessibilityRole="image"`, and an `accessibilityLabel` (e.g. `"Trend chart"`) on the outer container — the component has no metric name/label prop to build a more specific label from; that's the caller's responsibility if a richer label is needed (compose it externally via a wrapping `accessibilityLabel` on the parent, not by adding an undocumented prop here).

## Design spec (verbatim excerpts governing this packet)

**COMPACT-CANON.md §7 — data-viz + honesty invariant (verbatim):**
> Past/user = **solid orange** line · projected/AI = **dashed purple** · milestones = **green dots**. No 3-color gradients, no dark chart gradients.
> Every metric ships 3 states:
> 1. **Real** — value + provenance chip (`via WHOOP`, `you logged`).
> 2. **Low-confidence** — muted value + `estimated · low confidence` label.
> 3. **Honest null** — designed empty state, e.g. `Not enough data yet — 3 more days`. Never invent a number.

**COMPACT-CANON.md §4 — color roles (verbatim, relevant lines):**
> **Burnt Orange `#FF5E00` (60)**: primary CTA, user's line on charts, streaks/effort, active nav, hero accents.

## Acceptance criteria (mechanically checkable)

1. File exists at exactly `src/components/balencia/trend-chart.tsx`; no other file is created or modified (no `index.ts` edit, no `package.json` touch).
2. Exports `TrendChart` (function component), `TrendChartProps`, `TrendPoint`, and `Honesty` (locally declared per the Contract section's duplication decision) — all matching the verbatim contract's field names/types/optionality/defaults.
3. Imports only from `react`, `react-native`, `react-native-svg`, `react-native-reanimated`, `@/constants/theme`, `@/constants/motion`, `@/components/balencia/auth-inputs` — no import from any other new-in-batch viz file.
4. `npm run typecheck` (from `yhealth-app/mobile`) passes with this file included (worker output must be syntactically/typewise correct; the lander runs the actual repo-wide gate — this packet's job is to make that pass, not to run it itself).
5. Honesty states are mechanically distinguishable in the render output: `state='null'` renders no `Path`/marker/actual `Circle` elements (gridlines only) even when `points` is non-empty; `state='low'` renders the actual geometry at reduced opacity vs. `state='real'`/default.
6. `points.filter(p => (p.kind ?? 'actual') === 'actual' && p.y !== null).length < 3` renders standalone `Circle` elements only — asserting no `Path` element with the actual-line stroke color exists in that case.
7. `showProjection` defaults to falsy — no purple stroke renders when omitted, even if `points` contains `kind:'projected'` entries.
8. No `Path`/`Polygon`/fill geometry under either line — solid/dashed strokes only, `fill="none"` on both line paths.
9. Reduced motion: when `useReducedMotion()` returns `true`, the component renders in its fully-drawn final state without depending on a timer/animation callback having fired (no flash-then-jump on test render).
10. `onScrub`, when provided, is invoked with a `TrendPoint` object drawn from `points` on touch interaction; when omitted, the component attaches no responder handlers (`onStartShouldSetResponder` returns falsy or is not set).
11. When `onScrub` is provided and `height < 44`, the effective touch region (via `hitSlop`) is padded to at least 44px tall.
12. `BalenciaColors.chartGridline`, `BalenciaColors.orange`, `BalenciaColors.purple`, `BalenciaColors.green` are the only color tokens used for chart geometry (no new hex literals introduced).
13. `testID` prop, when provided, is applied to the outer container.
