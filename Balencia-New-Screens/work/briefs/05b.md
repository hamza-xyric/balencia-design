# FUNCTIONAL CONTENT BRIEF: Reset Password [05b]

## 1. Purpose (2 lines)
The destination screen when a user taps a password reset link from their email, presenting a simple form to set a new password. It validates the reset token on mount, handles expired/invalid states gracefully, and routes the user to Sign In upon success.

## 2. Entry and Exit Paths
*   **Entry Paths:** 
    *   Deep-linked from the password reset email (`balencia://reset-password?token=xxx`). No back button is present.
*   **Exit Paths:**
    *   **Success:** Navigates to Sign In [04] via root reset.
    *   **Manual Escape:** Navigates to Sign In [04] via "back to sign in" links.
    *   **Recovery:** Navigates to Forgot Password [05] via "request new link" to generate a new token.

## 3. Complete Information Architecture
**Global Navigation:** Status Bar (top), Home Indicator (bottom). No tab bar visible. Content is fixed and non-scrolling.

**Layout Regions (Top-to-Bottom):**
1.  **Brand Zone:** Center-aligned brand symbol.
2.  **Messaging Zone:** Center-aligned screen heading and instructional subtext.
3.  **Form Zone (Default State Only):** 
    *   New Password input field (with visibility toggle).
    *   Confirm Password input field.
    *   Requirements status-dot cluster (5 rows).
4.  **Feedback/Icon Zone (Terminal States Only):** Center-aligned 56pt icon (Success checkmark or Warning exclamation).
5.  **Action Zone:** Primary Call-to-Action (CTA) button, full width.
6.  **Secondary Action Zone (Expired State Only):** Center-aligned secondary text link.

## 4. Every Feature and Capability
*   **Token Validation:** Automatic background validation of the URL token upon screen mount.
*   **Password Creation:** Secure text entry for a new password.
*   **Password Masking Toggle:** Ability to temporarily reveal the typed password text.
*   **Password Confirmation:** Secondary field to verify the new password.
*   **Real-time Requirements Engine:** Dynamic validation of the password string as the user types, updating the visual status of the checklist.
*   **Form Validation Lock:** The primary action button is structurally disabled until all validation criteria (match + requirements) are objectively met.
*   **Connectivity Handling:** Detects offline status, caches input, and disables submission to prevent data loss.

## 6. Data Fields and Metrics
| Field / Metric | Data Source & Logic |
| :--- | :--- |
| **Reset Token** | URL Parameter (`balencia://reset-password?token=xxx`). Validated against auth API on mount. |
| **New Password Value** | User input via keystroke. |
| **Confirm Password Value** | User input via keystroke. Matched against New Password Value. |
| **Requirement: Length** | Derived logic: `password.length >= 8` |
| **Requirement: Uppercase** | Derived logic: `password.contains(/[A-Z]/)` |
| **Requirement: Lowercase** | Derived logic: `password.contains(/[a-z]/)` |
| **Requirement: Number** | Derived logic: `password.contains(/[0-9]/)` |
| **Requirement: Special Char** | Derived logic: `password.contains(/[^a-zA-Z0-9]/)` |
| **Match Status** | Derived logic: `newPassword === confirmPassword` |

## 7. All Screen States
*   **Cold-Start / Loading (on mount):** Spinner present while token validates.
*   **Default (valid token):** Standard form view.
*   **Match (inline):** Transient green border flash on confirm field.
*   **Mismatch (inline):** Persistent red border and error text on confirm field.
*   **CTA Loading:** Form locked, spinner replaces CTA text.
*   **API Error / Network Error:** Toast slides up, CTA reverts to enabled.
*   **Rate Limited:** Toast appears, CTA disabled for 60s.
*   **Success:** Terminal screen confirming reset.
*   **Expired / Invalid Token:** Terminal screen offering recovery routes.
*   **Offline:** Form dimmed, offline banner displayed.

## 8. Interactions, Gestures, and Motion Intents
**Gestures & Inputs:**
*   **Tap (Input Field):** Focuses field, raises keyboard.
*   **Tap (Eye Icon):** Toggles password masking/unmasking.
*   **Tap (Primary CTA):** Validates and submits request.
*   **Tap (Links):** Navigates to specified exit routes.
*   **Keyboard (Enter):** Moves focus between fields; submits form on final field if valid.
*   **Keyboard (Escape):** N/A (user must complete or use links).

**Motion Intents:**
*   **Staggered Entry:** Form elements rise and fade in sequentially (280ms).
*   **Continuous-Stroke Splash (Success):** Success icon scales from 0.5 to 1.0 while its radial glow intensifies over 520ms.
*   **Static Fade (Warning):** Expired icon fades in without scale to denote a passive, non-urgent error.
*   **Real-time Micro-transitions:** Checklist icons crossfade (160ms) as logic conditions are met.
*   **Reduced Motion:** All animations instantly snap to final state; spinner remains static.

## 11. Critical Contradictions & Flags
*   **CONTRADICTION (Screen ID):** The source `Audit Feedback Integration` section states that resolved decisions include "Q07 social auth profile completion must not block first SIA value" and "Q08 move first-name collection into SIA onboarding." This directly contradicts the system prompt to rename the coach persona to **CIA**. The brief explicitly enforces **CIA** and ignores the SIA references as legacy errors.
*   **CONTRADICTION (Instructional Text):** The layout wireframe contains an instructional typo: *"This reset link has expired. Request a new one to reset your password."* However, the Error Handling table lists a different copy variant for the expired state: *"This link has already been used. Request a new one if you still need to reset your password."* Designers must clarify which specific copy string applies to the generic "expired" state vs the "already used" state.
*   **NOTE (Accessibility Labels):** The spec asks to map the instructional text to `text-h1 28pt` and `text-h3 17pt`, but the main component table lists `Heading: 24pt` and `Instructional text: 15pt`. The brief sides with the system scale upgrade (28/17pt) as it is documented as an intentional remediation.
