# Functional Content Brief: Settings Screen

## 1. Purpose
The Settings screen acts as the centralized control panel for account security, CIA communication preferences, notifications, localization, and privacy. It is a utility hub designed for fast scannability and precise adjustments rather than content consumption.

## 2. Entry and Exit Paths
**Entry Paths:**
*   **Me Main [17]:** Stack push via the gear icon (top-right) or a quick link grid.

**Exit Paths:**
*   **Me Main [17]:** Stack pop via back button or edge swipe.
*   **Change Password:** Modal present (bottom sheet).
*   **Connected Services [22]:** Stack push.
*   **Subscription & Billing [23]:** Stack push.
*   **Sign In [04]:** Full root reset (triggers after Sign Out or Delete Account confirmation).
*   **Legal Views:** In-app webviews (Terms of Service, Privacy Policy) or stack push (Licenses).

## 3. Complete Information Architecture
The screen is composed of grouped sections inside containers, structured top-to-bottom:

1.  **Navigation Header:** Back button, "Settings" title.
2.  **Account Section:** Email, Change Password, Biometric Auth, Manage Subscription, Connected Services.
3.  **CIA Preferences Section:** Coaching Style, Coaching Intensity, AI Persona, Formality Level, Emoji Usage, Encouragement Level, Check-in Times, Check-in Frequency. Followed by the "CIA Note".
4.  **Notifications Section:** CIA Insights, Reminders, Check-ins, Social, Coaching, Achievements, Quiet Hours, Channels.
5.  **Appearance & Locale Section:** Theme, Language, Units, Time Format, Date Format.
6.  **Privacy Section:** Health Profile Visibility, Leaderboard Visibility, Data Retention, Background Sync.
7.  **Emergency Section:** Emergency Resources.
8.  **About Section:** App Version, Terms of Service, Privacy Policy, Licenses.
9.  **Destructive Actions:** Standalone, separated rows for Sign Out and Delete Account.

## 4. Features and Capabilities
*   **Account Management:** View email, change password (via secure bottom sheet with real-time validation), manage subscription/billing, and connected services/integrations.
*   **Biometric Auth:** Toggle Face ID/Touch ID/Biometric login for fast access.
*   **CIA Personalization:** Adjust how the AI coach communicates (style, intensity, persona, formality slider, emoji frequency, encouragement level).
*   **CIA Scheduling:** Set specific times and frequencies for CIA check-ins.
*   **Notification Controls:** Binary toggles for 6 distinct categories (CIA insights, Reminders, Check-ins, Social, Coaching, Achievements).
*   **Notification Rules:** Set "Quiet Hours" (time ranges) and configure Channels (push, email, WhatsApp, SMS).
*   **Localization:** Select language, units of measurement (weight, distance, temp), and time/date display formats.
*   **Privacy Configuration:** Control health profile visibility, leaderboard participation, data retention understanding, and background sync behavior.
*   **Crisis Support:** Access curated emergency resources and hotlines.
*   **Destructive Actions:** Securely sign out or permanently delete the account and associated data.

## 7. Screen States
*   **Cold-start / Day-1:** Fully populated from onboarding defaults (e.g., Face ID off, notifications on, theme dark, CIA style "supportive"). No blank rows.
*   **Loading:** When saving preferences, a subtle skeleton shimmer appears over the affected section. The toggle switch thumb is replaced with a 12pt spinner.
*   **Empty / Partial:** Rows are never truly blank; unconfigured rows display ghosted text (e.g., "not configured yet").
*   **Error:** Failed syncs cause the toggle track to flash red for 400ms and revert to its previous state. Red text appears below with recovery actions.
*   **Offline:** Sticky banner below the header: "You're offline. Changes will sync when you're back online." Controls remain fully interactive (saving to local cache).
*   **Disabled:** Rows that require hardware not present on the device (e.g., Biometrics) are hidden entirely. 

## 8. Interactions, Gestures, and Motion
*   **Navigation:** Stack push/pop animations (280ms). Swipe-right-from-edge acts as back button.
*   **Toggles:** Tapping the *entire* 52pt row toggles the switch (thumb slides 160ms, track color crossfades). Triggers medium haptic on successful state change.
*   **Sheets/Modals:** Change password, pickers, and delete account slide up from the bottom (520ms complex ease).
*   **Staggered Entrance:** Section groups fade-in/translateY on screen mount, staggered by 80ms per section.
*   **Motion Preferences:** All animations (fade-ups, slide-ins) are instantly bypassed if `prefers-reduced-motion` is enabled.

## 9. Free vs. Premium Gating
Based on the audit integration, premium exploration features are distinctly tiered. However, on the Settings screen itself, standard account, notification, appearance, and basic CIA preference controls are universally accessible to all users (free and premium). Subscription state management is handled via the routed [23] screen.

## 10. Cross-Domain Hooks
*   **CIA Adaptive Memory:** The CIA note establishes a hard link between the user's conversational inputs and the AI's tone. Adjusting formal settings here overrides CIA's learned behavior globally.
*   **Notification Ecosystem:** Toggling categories (Social, Achievements, Coaching) directly drives cross-domain events (e.g., Leaderboard updates in Goals/Social, CIA check-ins).
*   **Battery/Hardware Constraints:** Background sync provides a hardware hook (device battery trade-off vs. data freshness).

---
### ⚠️ Source Contradictions Flagged
1.  **Red Discipline:** The `Accessibility` section allows red text for error states at `3.3:1` contrast, rationalizing it via glyph pairing. However, the `Audit Feedback Integration` enforces strict "Red Discipline" stating red is reserved EXCLUSIVELY for operational/destructive surfaces, bypassing standard accessibility rationalizations. **Resolution:** Follow the strict Audit Integration—use red only for destructive actions and hard sync errors.
2.  **Theme/Light Mode:** The Layout wireframe implies light mode is merely "deferred" to V2, whereas the Audit and Microcopy sections firmly lock V1 to "Dark only" with a specific help text override ("Light mode coming soon."). **Resolution:** Treat V1 as strictly dark mode only, rendered as a display-only row.
3.  **Theme Display vs. Toggle:** The component list and wireframe ASCII originally placed `[██]` (a toggle indicator) next to the theme, but later audit resolutions explicitly demand it be a *display row* with no toggle. **Resolution:** Theme must be a non-interactive display row.
