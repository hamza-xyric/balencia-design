# 2. Purpose
A single-purpose utility allowing users to securely request a password reset link. Designed to be quick and reassuring, guiding the user from email entry to a calm confirmation state without friction.

# 3. Entry & exit
*   **Entry:** Stack push (depth 2) from Sign In [04] via the "Forgot password?" link.
*   **Primary Exit:** Stack pop back to Sign In [04] via the top-left back chevron, the "back to sign in" CTA, or the iOS screen-edge swipe-right gesture.

# 8. Data & honesty states
Applying the 3-state honesty invariant to the User Email Address.

1.  **Real (Validated):** 
    *   Value: `j***@email.com` (dynamically masked on success screen).
    *   Provenance chip text: `you logged` (from input).
2.  **Low-confidence:** 
    *   *Not Applicable.* Email strings are either entered by the user or not. They cannot be "estimated."
3.  **Honest-null (Empty):** 
    *   Value: `[empty]`
    *   Designed empty state: Placeholder text reads "email address". No fabricated domains or auto-filled guesses.

*Rate Limit Data (System Metric):*
1.  **Real:** 60-second countdown timer `[60..0]s`.
2.  **Low-confidence:** *Not Applicable.* 
3.  **Honest-null:** If no rate limit is hit, the countdown does not render (absence of metric is honest).

# 9. All states
*   **Default:** Centered heading, empty input with placeholder, full-width CTA (disabled).
*   **Skeleton (Submit in flight):** Input field transforms into a skeleton (preserving borders and depth, body pulses). CTA label hides, replaced by an inline spinner. Width locked.
*   **Empty:** Disabled CTA button (40% opacity) when input is empty.
*   **Error:** 
    *   *Format/Not Found:* Input border swaps to error red; error text appears directly below.
    *   *Network/Rate Limit:* Form persists. Glass-pill toast appears at the top, auto-dismisses after 4s. If rate limited, "send again" is replaced by the countdown timer.
*   **Success:** Crossfade from form. SuccessCircleIndicator scales from 0.5 to 1.0 with slight overshoot. Displays masked email text and "back to sign in".
*   **Disabled:** BtnPrimary is visually dimmed (40% opacity) and non-interactive when input is empty.

# 10. Motion & interaction
*   **Easing & Timing:** Physical easing only (never linear). 150-250ms for feedback (button presses, input focus).
*   **Entrance Motion:** Staggered fade-in of elements on screen mount (Brand -> Heading -> Form, each offset by ~50ms).
*   **State Transition:** Form fades out (150ms). Confirmation content fades in (250ms). SuccessCircleIndicator scales from 0.5 to 1.0 with a spring/overshoot curve.
*   **Glow behavior:** Upon reaching Success state, the `--glow-done` radial bleeds in over 250ms, anchored to the bottom of the implicit success card region.
*   **Haptics:** Light impact haptic on successful submission and on error bounce.
*   **Reduced Motion:** All animations are bypassed. Elements appear instantly in their settled state. Success circle renders at scale 1.0 with glow fully applied without scaling.

# 11. Motivation-tier adaptation
*   **Low Density:** Form elements retain generous spacing; instructional text is center-aligned and visually separated from the input. (This is the default execution).
*   **Medium Density:** Standard layout.
*   **High Density:** *Not Applicable.* This screen has a strictly fixed set of required elements for task completion. Condensing the layout vertically would harm the premium, breathable nature of the pre-auth flow.

# 12. Accessibility
