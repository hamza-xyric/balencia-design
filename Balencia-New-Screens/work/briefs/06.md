# Functional Content Brief: Guest Mode Preview

## 1. Purpose
Lets hesitant users experience a fully populated app environment with realistic, illustrative demo data before committing to an account. It requires zero friction (just a name and 1-3 interests) to answer the core pre-signup hesitation: "what would this app actually look like for me?"

## 2. Entry and Exit Paths
*   **Entry Points:** Stack push from Welcome/Sign Up [03] via the "Try without an account" route.
*   **Primary Exit:** Converts to registered user by pushing to Welcome/Sign Up [03] via the persistent "sign up" banner or session-end overlay (carrying the user's entered name).
*   **Secondary Exit:** Exits to Sign In [04] via stack push using the "sign in" link.
*   **System Exit:** Standard iOS edge swipe or back button to return to [03].

## 3. Complete Information Architecture
The experience operates in two distinct phases:

**Phase 1: Entry Form (Fixed viewport, no scrolling, no tab bar)**
1.  **Navigation Row:** Back button (top-left).
2.  **Brand Anchor Area:** Balencia logo symbol.
3.  **Contextual Copy Block:** Heading and supporting text.
4.  **Data Entry Field:** Name input field.
5.  **Preview Visualization:** Illustrative, ghosted radar that reacts to chip selections.
6.  **Selection Module:** Eyebrow label ("LIFE AREAS") + Domain Interest Picker (3x3 grid of 9 life areas).
7.  **Primary Action Area:** "explore" CTA button.
8.  **Escape Hatch:** "Already have an account? sign in" navigation link.

**Phase 2: Demo Browsing (Persistent overlay applied to standard app screens)**
1.  **App Content Layer:** Active screen content (Today, CIA, Goals, Me tabs) rendered with seed data.
2.  **Conversion/Persistent Layer (Z-30):** Sign-up banner hovering directly above the tab bar.
3.  **Global Navigation Layer (Z-40):** Bottom tab bar (All 4 tabs active: Today, CIA, Goals, Me).

## 4. Every Feature and Capability
*   **Micro-Onboarding:** Captures user's first name and 1-3 domain interests to inject into the demo environment.
*   **Live Preview Radar:** An illustrative chart that draws/brightens a star for each selected domain interest, showing the user a piece of the app's visualization capabilities.
*   **Frictionless Demo Initialization:** Generates a full app experience with medium-density, pre-populated realistic data (greetings, goals, dashboards, RPG stats).
*   **Demo Browsing:** Unlocks navigation across all 4 main app tabs to explore the simulated environment.
*   **Simulated AI Interaction:** Users can view pre-scripted CIA (coach) conversations, including cross-domain insights, inline cards, and suggestion chips.
*   **Passive Conversion Mechanism:** A persistent, always-visible banner prompting account creation. Can be minimized into a floating pill.
*   **Active Conversion Gating:** Blocks core app actions (CIA chat input, goal creation, logging data) to trigger signup prompts.
*   **Session Timer Limit:** Tracks browsing time to trigger an escalating conversion overlay.

## 7. Screen States
*   **Cold-start / Empty (Entry Form):** Empty name field (placeholder visible), all 9 domain chips unselected, preview radar shows "(0 selected)", "explore" CTA disabled (0.5 opacity).
*   **Validation / Disabled:** "explore" CTA remains disabled until name contains ≥1 character AND ≥1 domain chip is selected. 4th chip tap triggers a shake animation and toast.
*   **Loading:** "explore" CTA shows inline spinner and loading text. Name and chips are disabled.
*   **Error (Network/Init Failure):** "explore" CTA reverts to default, toast appears with recovery copy.
*   **Success / Demo Transition:** Entry form fades out; standard app UI, sign-up banner, and tab bar fade in via crossfade. (Welcome toast appears).
*   **Soft-Prompt (Interaction Boundary):** Bottom sheet (40% height) slides up over a dimmed (60% opacity) backdrop. (Max 2 times per session).
*   **Max Soft-Prompts Reached:** Subsequent blocked actions trigger a 3-second inline toast instead of the bottom sheet.
*   **Session-End Overlay:** Full-screen (90% opacity gradient) takeover triggered at 5 minutes.

## 8. Interactions, Gestures, Motion Intentions
*   **Entry Form Mount:** Staggered fade-in (opacity 0→1 + translateY 12→0) sequenced back button → logo → heading → text → input → chips → CTA → link.
*   **Chip Selection/Deselection:** Tap triggers scale oscillation (1→1.05→1 select, 1→0.95→1 deselect) and background/border crossfade to domain color tint.
*   **Banner Minimization:** Swipe left on the full banner causes it to slide right, shrink, and dock as a floating pill in the bottom-right corner.
*   **Banner Expansion:** Tap on the minimized pill expands it back to full width.
*   **Blocked Action Motion:** Soft-prompt sheet slides up (translateY 100%→0) with internal content stagger.
*   **Session-End Motion:** Overlay fades in (opacity 0→1) with staggered content (symbol → heading → text → CTA).
*   **Continuous-Stroke Aesthetic:** The demo transition relies on drawing the new UI into view smoothly (parallel fading and sliding) rather than a hard screen swap. *(Motion intent falls back to instant transitions for reduced-motion preferences).*

## 9. Free vs. Premium Gating
*   **Guest Tier (Free/Unregistered):** Permits full read-only navigation of the 4 primary tabs populated with seed data. Permits selecting up to 3 domain chips on the entry form.
*   **Hard Gates (Registered Tier Required):** 
    *   Interacting with the CIA chat input field.
    *   Attempting to create a new goal.
    *   Attempting to log health/wearable data.
    *   Persistence of any generated data (data preservation policy explicitly blocks saving guest data).

## 10. Cross-Domain Hooks
*   **CIA Conversations Tab:** The pre-scripted demo seed data specifically showcases a cross-domain insight generated by the CIA, demonstrating how the AI correlates different life areas.
*   **Life Area Radar (Entry Form):** Visually links user-selected domains (e.g., Fitness, Finance) into a unified "ConstellationRadar," hinting at the app's holistic life-integration philosophy.

## ⚠️ Source Document Flags & Contradictions
1.  **Persona Renaming:** Source document refers to the coach persona as "SIA". Per system instructions, all occurrences have been explicitly renamed to **CIA** in this brief.
2.  **Launch-Critical Scope Discrepancy:** The `Audit Feedback Integration` notes a critical finding (B03-F01) stating the "full browsable demo tabs can wait" for the production prototype, whereas the rest of the spec details the Demo Browsing Phase exhaustively. *Flagged for product team: the functional requirement of the fully browsable demo may be scoped down to just the entry form for MVP launch.*
3.  **Touch Target Violation:** The spec explicitly flags a Medium accessibility finding: Domain chips are specified at 36pt height, which falls below the standard 44pt iOS touch target. Visual design must pad the touch area without necessarily expanding the visual surface.
4.  **Visualization Placement:** The spec includes a `## Design Elevation` section rather than a standard `## Visualization` section because this is technically an Auth/Onboarding screen. The chart elements (Radar, GaugeRings, MomentumBars) are additive, illustrative UI previews rather than canonical user data maps.
