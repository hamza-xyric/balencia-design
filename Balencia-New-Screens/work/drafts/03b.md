# Balencia Screen Spec: 03b-otp-verification

## 1. Header
*   **Screen ID:** 03b-otp-verification
*   **Name:** OTP Verification
*   **Route(s) covered:** `/auth/verify-otp`
*   **Tab:** Hidden (Pre-auth flow)
*   **Source:** Functional Content Brief (OTP Verification)
*   **Batch:** 2

## 2. Purpose
Completes the user registration process by collecting a 4-digit numeric code. Verifies the code to create the account and advance to the consent screen, ensuring a quick, frictionless, and secure authentication experience.

## 3. Entry & exit
*   **Entry Path:** Welcome / Sign Up screen [03] via stack push (triggered after the user submits the sign-up form).
*   **Primary Exit Path:** Consent screen [03c] via stack push (triggered upon successful OTP verification).
*   **Secondary Exit Path:** Welcome / Sign Up screen [03] via stack pop (triggered by tapping the back button or iOS screen-edge swipe).

## 4. Layout anatomy
The screen is a fixed, non-scrolling canvas (height 844px, safe-area respected) divided vertically into four distinct regions:
1.  **Navigation Zone (Top):** Transparent floating back chevron.
2.  **Brand & Context Zone:** Centered Balencia wordmark, followed by the hero Display heading and masked email subtitle.
3.  **Verification Zone:** The OTP input cluster, dynamic status text, and the resend countdown module.
4.  **Action Zone (Bottom):** Primary CTA pinned safely above the system home indicator, raised slightly by the system keyboard.

## 5. Components
*   **TopBar:** Variant: transparent, single leading chevron (44px target). No title or trailing actions.
*   **Text Elements:** 
    *   Display (Hero Title): "Verify your email"
    *   Body-light (Subtitle): Masked email context.
*   **NEW: OTPCluster:** 
    *   *Rationale:* The catalog does not contain an OTP input component. This is a bespoke cluster of 4 custom input fields. Each field is a 56x64px `.glass-pill` square (radius 14). Focus state triggers a 1.5px burnt orange border. Error state applies a 2pt border using the `Fitness #ef4444` domain tag color (avoids harsh system red, maintains premium palette).
*   **MomentumBar:** Variant: depleting countdown. Tracks the 60-second cooldown. Fill is `--glow-you` (Burnt Orange). Flips to `--glow-done` (Forest Green) on "Code sent" success.
*   **BtnPrimary:** Orange fill, label "verify.". Disabled state (40% opacity) until 4 digits are present.

## 6. Visual treatment
*   **Background Atmosphere:** Soft warm radial glow top-center (`radial-gradient(90% 60% at 50% -10%, rgba(255,94,0,.18), transparent 60%)`) over `--bg-base`. A 3% soft-light grain overlay is applied globally. 
*   **Glass Tiers:** Selective glass usage. OTP input boxes utilize `.glass-pill` to sit elegantly over the warm atmosphere without clashing. No SolidCards or FrostCards are used, preserving an immersive, lightweight auth feel.
*   **Semantic Inner-Glow:** 
    *   **BtnPrimary on Success:** Radiates `--glow-done` (#34A853) outward for 600ms to signify completion and account creation.
    *   **OTPCluster on Focus:** A very subtle, soft `--glow-you` bleed emits from the bottom of the active input box, symbolizing user effort and active engagement.
*   **Hero Type Moment:** The screen title "Verify your *email*" uses Neue Medium 500 at 34px. The word "*email*" is wrapped in asterisks, rendered in Tiempos Medium italic, providing the single editorial premium moment.

## 8. Data & honesty states
*Every metric ships 3 states: real, low-confidence, honest-null. Never a fabricated number.*

This screen evaluates local user input against a server-generated value. It does not display health/lifestyle metrics, but applies the honesty invariant to system states:

*   **Masked Email Address:**
    *   *Real:* `j***@email.com` (Provenance: Passed dynamically from Sign Up [03]).
    *   *Honest-null (Missing email payload):* `We sent a 4-digit code to your email.` (Never fabricates a fake email string).
*   **Resend Cooldown Timer (60s):**
    *   *Real:* `Resend code (0:59)` with depleting orange bar (Provenance: Local System Clock).
    *   *Low-confidence:* Not applicable (system clock is deterministic).
    *   *Honest-null:* Timer remains hidden until the API confirms the email has dispatched.
*   **Rate Limit Cooldown Timer (5m):**
    *   *Real:* `Too many attempts. Your code will be ready again in 4:32.` (Provenance: Server Response/API).

## 9. All states
*   **Default (Cold-start):** First box auto-focused, numeric keyboard raised. Inputs empty. Resend countdown active. CTA disabled.
*   **Partial Entry:** Digits visible (scale up from 0.5 to 1.0). CTA disabled.
*   **Loading (Verify API Pending):** CTA label swaps to inline spinner, width locked. Inputs remain interactive but keyboard dismisses on tap.
*   **Error (Invalid Code):** 2pt red borders applied to inputs. Shake animation (3 oscillations) *only* on 3rd attempt. Inputs clear, focus returns to box 1. Status text turns red.
*   **Error (Expired Code):** 2pt red borders (NO shake). Inputs clear. Momentum bar completes instantly. Resend link turns orange.
*   **Error (Too Many Attempts):** Top-of-screen toast blocks UI. CTA, OTP boxes, Resend link drop to 0.4 opacity and non-interactive. Live countdown in toast.
*   **Error (Network/Offline):** Top-of-screen glass-pill banner (`offline — showing last sync`). CTA reverts to default. Entered digits preserved.
*   **Resend Success:** Resend text changes to "Code sent". Cooldown progress bar fills green (`--glow-done`) momentarily, then reverts to 60s orange countdown.
*   **Success (OTP Verified):** Green glow radiates from CTA. Instant navigation to [03c].
*   **Skeleton:** *N/A.* Auth screens rely on local state and immediate server handshakes; a skeleton layout is not applicable.

## 10. Motion & interaction
*   **Easing & Feedback:** Physical easing (`cubic-bezier(0.22, 1, 0.36, 1)`). Input focus and digit scaling occur in 150-200ms.
*   **Glow Behavior:** OTP focus glow breathes subtly (4s ease). Success state triggers a 600ms outward radiation of the `--glow-done` fill.
*   **Haptics:** 
    *   Light selection tick on digit auto-advance.
    *   Heavy warning vibration on Error (Invalid/Expired code).
    *   Success churn vibration on OTP Verified.
*   **Interactions:** Auto-advance on type; backspace clears current/previous; long-press/clipboard read auto-pastes 4 digits; tap-outside dismisses keyboard.
*   **Reduced-Motion (`prefers-reduced-motion: reduce`):** Instant transitions only. The shake animation is completely bypassed. Glows are swapped for solid, static 1.5px borders.

## 11. Motivation-tier adaptation
*   **Low Density (Stressed/Rushed):** The UI naturally handles this by isolating the 4 input boxes and hiding all other chrome. Keyboard auto-opens for immediate, frictionless completion.
*   **Medium Density (Default):** As described in base spec. Cooldown timer provides gentle pacing.
*   **High Density (Curious/Anchored):** *Not Applicable.* Pre-auth security gates require uniform focus. Introducing verbose cross-domain hooks, rich CIA insights, or dense metric cards here would distract from the core security loop and degrade the premium, lightweight feel.

## 12. Accessibility
*   **AA+ Contrast:** Paper-100 (#FEFAF3) text on `--bg-base` (#0A0A0F) exceeds WCAG AAA. The 2pt error border utilizes Domain Fitness `#ef4444`, providing a vibrant but accessible alert contrast over the dark warm atmosphere. 
*   **Targets:** Back button is 44x44px. Primary CTA is 52px tall, full-width (approx 340px target). Individual OTP boxes are 56x64px—highly tactile.
*   **Screen-reader labels:** 
    *   Back chevron: `aria-label="Return to sign up"`
    *   OTP inputs: `aria-label="Digit 1 of 4 verification code"`, etc.
    *   Resend link button is explicitly disabled to VoiceOver during the 60s cooldown.
