# Packet N1 — GlassNavBar + tabs swap (NativeTabs → expo-router JS Tabs)

## Objective

Replace the native `expo-router/unstable-native-tabs` bottom bar with a custom **GlassNavBar** rendered through expo-router's JS `Tabs` navigator (`architecture-plan.md` ADR-5, amended by **A6**: import `Tabs` from `'expo-router/js-tabs'`, not the deprecated path; GlassNavBar's geometry must match the catalog's floating-pill spec exactly, embedded below). This is the component + wiring that:

1. Renders the 4-tab IA — **Today · Cia · Missions · Me** — as a floating glass pill, 16px above the home indicator, active tab = orange filled icon + label, inactive = paper-tinted outline (COMPONENT-CATALOG.md, COMPACT-CANON.md §6, both embedded verbatim below).
2. Uses `expo-glass-effect`'s `GlassView` for the real native material with a plain translucent `View` fallback when the Liquid Glass API isn't available on-device (ADR-5, Risk #2).
3. Fires `expo-haptics` light-impact feedback on every tab press — **including under reduced motion** (ADR-6: "haptics and text updates still occur").
4. Emits the standard React Navigation `tabPress`/`tabLongPress` events and calls `navigation.navigate(route.name)` with focus de-dupe (ADR-5).
5. Swaps `NativeTabs` for `Tabs` in `(tabs)/_layout.tsx`, which — per ADR-5 — is also the fix for the BIOS-002 hidden-route bug (NativeTabs silently swallowed `router.push` to root-level Stack screens; JS Tabs does not). **This packet does not touch that bug's proof or the root `Stack`** — it only removes the component that caused it. Verifying root pushes still work is a later (simulator-smoke) packet's job.

### Plan-vs-live corrections applied in this packet (re-derived from live source 2026-07-09)

1. **`@react-navigation/bottom-tabs` is not an installed package.** The architecture plan's §3 contract snippet reads `import type { BottomTabBarProps } from '@react-navigation/bottom-tabs';`. Verified live: `node_modules/@react-navigation` does not exist, and it is not in `package.json` (direct or peer). `expo-router` (57.0.4) vendors its **own** copy of `@react-navigation/bottom-tabs` internally at `expo-router/build/react-navigation/bottom-tabs`, and re-exports every type from it (including `BottomTabBarProps`, `BottomTabNavigationEventMap`) through the public `expo-router/js-tabs` entry point (`js-tabs.d.ts` → `build/layouts/Tabs.d.ts` → `export * from '../react-navigation/bottom-tabs'`). **Correction: import `BottomTabBarProps` from `'expo-router/js-tabs'`, the same module A6 already mandates for `Tabs`.** This is a single, consistent, public import path — do not import from `@react-navigation/bottom-tabs` (doesn't exist) or reach into `expo-router/build/...` internals directly (unnecessary; the public subpath already re-exports everything needed).
2. **Target path is flat, not `chrome/`.** The plan's packet-decomposition table (§5, row `2a`) lists the target as `components/balencia/chrome/GlassNavBar.tsx`. This packet's actual instructed target is `src/components/balencia/glass-nav-bar.tsx` — flat, kebab-case, no subfolder — matching every existing file in this directory and consistent with how packet V1 already corrected the same plan/live mismatch for `ProgressRing`. Do not create a `chrome/` folder.
3. **No new theme tokens needed.** `.glass-pill`'s two canon literals (`rgba(10,10,15,.55)` background, `rgba(255,255,255,.10)` border) have no matching `theme.ts` token (`chartTrack` is `rgba(255,255,255,0.08)` — close but not the same value, and is documented as viz-chrome-only, not nav chrome). This packet declares the two literals as local `const`s inside `glass-nav-bar.tsx` (see Contract) rather than adding tokens to `theme.ts` — no lander/theme task is in scope for this packet.
4. **Safe-area inset comes from `props.insets`, not a second `useSafeAreaInsets()` call.** The plan's contract comment says "useSafeAreaInsets bottom pad." `BottomTabBarProps` (confirmed live in `types.d.ts`, embedded below) already carries `insets: EdgeInsets`, sourced by `BottomTabView` from the same `SafeAreaInsetsContext`. Use `props.insets.bottom` — functionally identical, avoids a redundant context subscription.
5. **`<Tabs.Screen>` registered explicitly for all 4 routes**, rather than relying on expo-router's implicit file-based screen discovery. This is the literal, verifiable way to satisfy the task's "preserve … the 4 visible screens … exactly" requirement, and mirrors the structure of the `NativeTabs.Trigger` list it replaces (today/cia/missions/me, same order). No `options` are passed on any `<Tabs.Screen>` — `GlassNavBar` owns all tab visual metadata (label/icon) itself rather than reading it off `screenOptions`/per-screen options (ADR-5: GlassNavBar "renders the 4-tab IA" directly).
6. **Active-state label color: orange, not paper100.** The *old* `NativeTabs` config (being replaced) colored the active **icon** orange but kept the active **label** at `paper100` (`labelStyle.selected.color`). The catalog contract for the *new* component is explicit — "active = orange filled icon **+ label**" (COMPONENT-CATALOG.md line 23; COMPACT-CANON.md §6; and the rendered hi-fi reference `chrome.tsx` colors both icon and label orange on the active tab). This packet follows the catalog/hi-fi-reference contract (both recolor orange together), not the old NativeTabs incidental choice being removed.
7. **Inactive color reuses `BalenciaColors.paper55`** (55%), not a new `paper64` token. Canon prose says "outline paper-64%"; no `paper64` token exists in `theme.ts` and this packet adds none (correction 3). The old `NativeTabs` config already made the identical substitution (`iconColor.default: BalenciaColors.paper55`) — reuse it for both inactive icon and inactive label, consistent with existing precedent.
8. **`react-hooks/immutability` ESLint false-positive on `SharedValue.value = ...` writes made from a plain event handler (not inside `useEffect`).** Discovered empirically this session by actually running `npx eslint` against this exact contract's code against the live `eslint-config-expo` flat config: both press-driven `scale.value = withTiming(...)` writes in Contract §1 (`handlePressIn`/`handlePressOut`) trip `react-hooks/immutability`, and this is **not new drift** — `trend-chart.tsx`'s pre-existing, already-landed `onLayout` handler (`measuredWidth.value = e.nativeEvent.layout.width;`) trips the identical rule today, unaddressed. Every OTHER shared-value mutation in this codebase's already-landed viz components happens inside a `useEffect` (verified: `progress-ring.tsx`, `momentum-bar.tsx`, `cia-presence-orb.tsx`), which this rule does not flag — but restructuring a press-feedback micro-interaction into a `useEffect`-driven-by-boolean-state pattern would be worse (extra render, less idiomatic than Reanimated's own documented event-handler-mutation pattern). **Correction: Contract §1 below includes a narrow `// eslint-disable-next-line react-hooks/immutability` directly above each of the two writes**, with a justification comment above `handlePressIn`. Verified live: this reduces the packet's own lint run from 2 errors to 0 (confirmed by actually running `npx eslint` against the exact Contract §1 code this session). **The disable directive must be the single comment line immediately preceding the `scale.value = ...` statement** — a multi-line justification comment placed directly above the directive (not between the directive and the code) is required, or `eslint-disable-next-line` targets the wrong line and the fix silently fails (confirmed by reproducing this exact failure mode this session).

```typescript
import { QueryClientProvider } from '@tanstack/react-query';
import { Stack } from 'expo-router';
import * as SplashScreen from 'expo-splash-screen';
import { StatusBar } from 'expo-status-bar';
import { useEffect } from 'react';
import { SafeAreaProvider } from 'react-native-safe-area-context';

import { SessionProvider } from '@/services/auth/session-provider';
import { onAuthCleared, onSignedIn, queryClient } from '@/services/query/client';

SplashScreen.preventAutoHideAsync();

function secondarySurfaceOptions(title: string) {
  return {
    headerShown: true,
    title,
    headerStyle: { backgroundColor: BalenciaColors.ink900 },
    headerTintColor: BalenciaColors.paper100,
    headerBackTitle: 'Back',
    headerShadowVisible: false,
  } as const;
}

export default function RootLayout() {
  useEffect(() => {
    SplashScreen.hideAsync().catch(() => undefined);
  }, []);

  return (
    <QueryClientProvider client={queryClient}>
      <SessionProvider onSignedIn={onSignedIn} onAuthCleared={onAuthCleared}>
        <SafeAreaProvider>
          <StatusBar style="light" />
          <Stack
            screenOptions={{
              headerShown: false,
              contentStyle: { backgroundColor: BalenciaColors.ink900 },
            }}>
            <Stack.Screen name="index" />
            <Stack.Screen name="(auth)" />
            <Stack.Screen name="(tabs)" />
            {/* Secondary surfaces are stack pushes, NOT hidden tab triggers —
                expo-router NativeTabs silently ignores router.push to hidden triggers. */}
            <Stack.Screen name="life-areas" options={secondarySurfaceOptions('Life Areas')} />
            <Stack.Screen name="fitness" options={secondarySurfaceOptions('Fitness')} />
            <Stack.Screen name="data-controls" options={secondarySurfaceOptions('Data Controls')} />
          </Stack>
        </SafeAreaProvider>
      </SessionProvider>
    </QueryClientProvider>
  );
}
```

```typescript
   *  Summary Band fills L->R (250ms)"). Also used for the S13 Radar draw-in

  bandFill: 250,

   *  in ADR-6 itself — derived from two independent composition specs that
   *  agree on the same value: spec S13 ("Mission cards cascade downward
   *  (80ms stagger)") and the architecture plan's Today composition map
   *  (§4.1: "Motion: staggered entries 80ms"). */
  stagger: 80,
  /** Next Action card swap on completion — old card out, replacement in
   *  (spec S14: "250ms ease-in-out"). */

   *  200ms glow-done swap + success haptic"). */

/**
 * Easing curves as plain bezier control-point tuples — NOT Reanimated
 * `EasingFn` values (see file header for why). Tuple order matches
 * `Easing.bezier(x1, y1, x2, y2)`; spread at the call site.
 */
export const MotionEasing = {
  /** Canon physical easing (COMPACT-CANON §6: "physical easing (never
   *  linear)"; ADR-6: "cubic-bezier(0.32,0.72,0,1)"). Default for
   *  sweeps/draws/entrances unless a spec calls for a different curve. */
  physical: [0.32, 0.72, 0, 1],
} as const;

/**
 * Reanimated `withSpring` config objects — plain data, no reanimated import
 * required to define them. ONLY `badge` has a spec-given physics config:
 * spec S42 "Entrance: spring physics (stiffness 150, damping 15) for badge
 * scale-in" (ADR-6 restates the same pair). Every OTHER "spring Nms" mention
 * in the hi-fi specs (accordion, stalled sheet) gives a settle DURATION, not
 * stiffness/damping — inventing physics values for those would fabricate
 * precision the source docs do not give. Use
 * `withTiming(value, { duration: MotionDuration.accordion, easing: Easing.bezier(...MotionEasing.physical) })`
 * for accordion/sheet, not `withSpring`.
 */
export const MotionSpring = {
  badge: { stiffness: 150, damping: 15 },
} as const;

/**
 * Hero-card glow breathe cycle (ADR-6: "breathe (4s, 55%<->100%)"). Apply to
 * exactly ONE hero card per screen — spec S14 Motion: "Glow breathe: shared
 * 4s cycle across all glows (one rhythm, not five uncoordinated pulses)".
 * NOTE: spec S42's celebration FrostCard breathe is a documented per-screen
 * exception ("glow-done breathes (60%->100% opacity, 3s ease)") — that value
 * belongs to the celebration composition packet (wave 4c), not this shared
 * default; do not overwrite these numbers to match it.
 */
export const MotionBreathe = {
  durationMs: 4000,
  opacityMin: 0.55,
  opacityMax: 1,
} as const;
```

```typescript
import type { JSX } from 'react';
import { Pressable, StyleSheet, Text, View } from 'react-native';
import Animated, {
  Easing,
  useAnimatedStyle,
  useSharedValue,
  withTiming,
} from 'react-native-reanimated';
import { GlassView, isGlassEffectAPIAvailable } from 'expo-glass-effect';
import { SymbolView } from 'expo-symbols';
import type { AndroidSymbol, SFSymbol } from 'expo-symbols';
import * as Haptics from 'expo-haptics';
import type { BottomTabBarProps } from 'expo-router/js-tabs';

import { BalenciaColors, Spacing, TouchTarget } from '@/constants/theme';
import { MotionDuration, MotionEasing } from '@/constants/motion';
import { useReducedMotion } from '@/components/balencia/auth-inputs';

// GlassNavBar — floating glass-pill bottom nav (COMPACT-CANON §6,
// COMPONENT-CATALOG.md "GlassNavBar"; BIOS-004 ADR-5). Rendered as the
// `tabBar` prop of the expo-router `Tabs` navigator in `(tabs)/_layout.tsx`
// (imported from 'expo-router/js-tabs', not the deprecated native-tabs
// path — A6). Consumes `BottomTabBarProps` exactly as React Navigation's
// bottom-tabs would; that type is not installed as its own package here —
// expo-router vendors it and re-exports it from the same 'expo-router/js-tabs'
// module this component's props type comes from.
//
// Hidden-route compatibility note (ADR-5): this migration away from
// `NativeTabs` also fixes the BIOS-002 bug where `router.push()` to a
// root-level Stack screen (life-areas, fitness, data-controls, and future
// modal routes) was silently swallowed by NativeTabs' native trigger list.
// JS Tabs (this component's host navigator) does not intercept `router.push`
// to routes outside its own screen set, so those pushes now work correctly.
// This file does not add or change any root Stack route — see
// `src/app/_layout.tsx` (untouched by this packet).

type TabKey = 'today' | 'cia' | 'missions' | 'me';

type TabMeta = {
  label: string;
  sfSymbol: SFSymbol;
  sfSymbolActive: SFSymbol;
  androidSymbol: AndroidSymbol;
};

// Exact glyph/label set the old NativeTabs config used (embedded above) —
// reused verbatim so the visible IA does not change, only the chrome that
// renders it. Order matches `<Tabs.Screen>` registration in
// `(tabs)/_layout.tsx`: today, cia, missions, me.
const TAB_META: Record<TabKey, TabMeta> = {
  today: {
    label: 'Today',
    sfSymbol: 'sun.max',
    sfSymbolActive: 'sun.max.fill',
    androidSymbol: 'wb_sunny',
  },
  cia: {
    label: 'Cia',
    sfSymbol: 'sparkles',
    sfSymbolActive: 'sparkles',
    androidSymbol: 'auto_awesome',
  },
  missions: {
    label: 'Missions',
    sfSymbol: 'list.bullet.rectangle',
    sfSymbolActive: 'list.bullet.rectangle.fill',
    androidSymbol: 'checklist',
  },
  me: {
    label: 'Me',
    sfSymbol: 'person.crop.circle',
    sfSymbolActive: 'person.crop.circle.fill',
    androidSymbol: 'account_circle',
  },
};

// .glass-pill canon literals (COMPACT-CANON §2) — no matching theme.ts token
// exists yet (`chartTrack` is viz-chrome, a different value); declared local
// to this component rather than adding a token (out of scope, see packet
// "Plan-vs-live correction 3").
const GLASS_PILL_TINT = 'rgba(10, 10, 15, 0.55)'; // = ink900 @ 55% alpha
const GLASS_PILL_BORDER = 'rgba(255, 255, 255, 0.10)';

function isTabKey(name: string): name is TabKey {
  return name === 'today' || name === 'cia' || name === 'missions' || name === 'me';
}

export function GlassNavBar(props: BottomTabBarProps): JSX.Element {
  const { state, navigation, insets } = props;
  const reduceMotion = useReducedMotion();
  const glassAvailable = isGlassEffectAPIAvailable();

  const items = state.routes.map((route, index) => {
    if (!isTabKey(route.name)) return null;
    const meta = TAB_META[route.name];
    const isFocused = state.index === index;

    const onPress = () => {
      Haptics.impactAsync(Haptics.ImpactFeedbackStyle.Light).catch(() => undefined);
      const event = navigation.emit({
        type: 'tabPress',
        target: route.key,
        canPreventDefault: true,
      });
      if (!isFocused && !event.defaultPrevented) {
        navigation.navigate(route.name);
      }
    };

    const onLongPress = () => {
      navigation.emit({ type: 'tabLongPress', target: route.key });
    };

    return (
      <GlassNavBarItem
        key={route.key}
        routeName={route.name}
        meta={meta}
        isFocused={isFocused}
        reduceMotion={reduceMotion}
        onPress={onPress}
        onLongPress={onLongPress}
      />
    );
  });

  const pillContent = <>{items}</>;

  return (
    <View
      style={[styles.wrapper, { bottom: insets.bottom + Spacing.three }]}
      pointerEvents="box-none">
      {glassAvailable ? (
        <GlassView glassEffectStyle="regular" tintColor={GLASS_PILL_TINT} style={styles.pill}>
          {pillContent}
        </GlassView>
      ) : (
        <View style={[styles.pill, styles.pillFallback]}>{pillContent}</View>
      )}
    </View>
  );
}

function GlassNavBarItem({
  routeName,
  meta,
  isFocused,
  reduceMotion,
  onPress,
  onLongPress,
}: {
  routeName: TabKey;
  meta: TabMeta;
  isFocused: boolean;
  reduceMotion: boolean;
  onPress: () => void;
  onLongPress: () => void;
}): JSX.Element {
  const scale = useSharedValue(1);
  const animatedStyle = useAnimatedStyle(() => ({ transform: [{ scale: scale.value }] }));
  const tint = isFocused ? BalenciaColors.orange : BalenciaColors.paper55;

  // Reanimated SharedValue.value assignment from an event handler is the documented
  // mutation API (not a React state write) — the `react-hooks/immutability` ESLint
  // rule does not model SharedValue and false-positives on both writes below. This is
  // pre-existing, identical drift already present in `trend-chart.tsx`'s `onLayout`
  // handler (`measuredWidth.value = e.nativeEvent.layout.width;`, verified live) —
  // suppressed narrowly here with justification (worker-rules.md: "narrowly
  // justify+disable"), not silently left failing.
  const handlePressIn = () => {
    if (reduceMotion) return;
    // eslint-disable-next-line react-hooks/immutability
    scale.value = withTiming(0.96, {
      duration: MotionDuration.feedback,
      easing: Easing.bezier(...MotionEasing.physical),
    });
  };
  const handlePressOut = () => {
    if (reduceMotion) return;
    // eslint-disable-next-line react-hooks/immutability
    scale.value = withTiming(1, {
      duration: MotionDuration.feedback,
      easing: Easing.bezier(...MotionEasing.physical),
    });
  };

  return (
    <Pressable
      onPress={onPress}
      onLongPress={onLongPress}
      onPressIn={handlePressIn}
      onPressOut={handlePressOut}
      accessibilityRole="tab"
      accessibilityState={{ selected: isFocused }}
      accessibilityLabel={meta.label}
      testID={`glass-nav-bar-tab-${routeName}`}
      style={styles.item}>
      <Animated.View style={[styles.itemInner, animatedStyle]}>
        <SymbolView
          name={{
            ios: isFocused ? meta.sfSymbolActive : meta.sfSymbol,
            android: meta.androidSymbol,
            web: meta.androidSymbol,
          }}
          size={22}
          weight={isFocused ? 'semibold' : 'regular'}
          tintColor={tint}
        />
        <Text style={[styles.label, { color: tint, fontWeight: isFocused ? '700' : '600' }]}>
          {meta.label}
        </Text>
      </Animated.View>
    </Pressable>
  );
}

const styles = StyleSheet.create({
  wrapper: {
    position: 'absolute',
    left: 20,
    right: 20,
  },
  pill: {
    height: 60,
    borderRadius: 999,
    borderWidth: 1,
    borderColor: GLASS_PILL_BORDER,
    flexDirection: 'row',
    alignItems: 'center',
    justifyContent: 'space-around',
    paddingHorizontal: Spacing.two,
    overflow: 'hidden',
  },
  pillFallback: {
    backgroundColor: GLASS_PILL_TINT,
  },
  item: {
    minWidth: 64,
    height: TouchTarget,
    alignItems: 'center',
    justifyContent: 'center',
  },
  itemInner: {
    alignItems: 'center',
    justifyContent: 'center',
    gap: 2,
  },
  label: {
    fontSize: 11,
    lineHeight: 13,
  },
});
```

**Notes binding on the worker:**
- `position: 'absolute'` on `styles.wrapper` is **load-bearing**, not decorative — it is what makes `GlassNavBar` float over content instead of reserving flex space in the `Tabs` navigator's column layout (verified live in `expo-router/build/react-navigation/bottom-tabs/views/BottomTabView.js`: the tab bar and the screens container are flex siblings; an absolutely-positioned tab bar contributes zero height to that flex column, so `screens{flex:1}` fills the full height and the pill overlays it — exactly the canon "content scrolls beneath with fade" behavior, and exactly what `BalenciaScreen`'s pre-existing `BottomTabInset` bottom padding was already compensating for). Do not change it to a normal (non-absolute) flex child.
- `pointerEvents="box-none"` on the wrapper lets touches pass through the wrapper's own (mostly empty) bounding box to whatever is beneath it outside the pill itself; the pill and its children remain fully touchable.
- `weight` on `SymbolView` is passed as a bare string (`'semibold' | 'regular'`), which the type accepts uniformly for both platforms (`SymbolWeight | { ios; android }` — the bare-string branch applies to both). Do not switch to the object form; it is not needed here.
- Android has no separate "filled" SF-Symbol-style glyph variant in `expo-symbols`' Material set for these 4 icons — active/inactive Android differentiation comes from `tintColor` + `weight` only (a real platform constraint, not a shortcut). iOS gets the true filled/unfilled swap via `sfSymbol`/`sfSymbolActive`.

```tsx
  { key: 'today', label: 'Today', Icon: Calendar },
  { key: 'cia', label: 'CIA', Icon: MessageCircle },
  { key: 'goals', label: 'Missions', Icon: Flag },
  { key: 'me', label: 'Me', Icon: User },
] as const

export function GlassNavBar({ active = 'today' }: { active?: HifiTab }) {
  return (
    <nav className="shrink-0 px-5 pb-1" aria-label="Primary">
      <div className="glass-pill flex h-[60px] items-center justify-around px-2 shadow-2">
        {navTabs.map(({ key, label, Icon }) => {
          const isActive = key === active
          return (
            <div key={key} className="flex h-11 min-w-[64px] flex-col items-center justify-center gap-[2px]">
              <Icon size={22} strokeWidth={isActive ? 2.4 : 1.6}
                className={isActive ? 'text-brand-orange' : 'text-white/60'} />
              <span className={cx('text-[11px] leading-3', isActive ? 'font-semibold text-brand-orange' : 'text-white/60')}>
                {label}
              </span>
            </div>
          )
        })}
      </div>
    </nav>
  )
}
```
(`px-5` → 20px horizontal margin; `h-[60px]` → 60px pill height; `px-2` → 8px inner horizontal padding = `Spacing.two`; `h-11 min-w-[64px]` → 44px touch height / 64px min width; `gap-[2px]` → 2px icon/label gap; `text-[11px] leading-3` → 11px/13px label; icon `size={22}`. This is the exact geometry embedded in Contract §1's `styles`.)

**Reduced-motion rule (binding, restated from ADR-6):** under `useReducedMotion() === true`, the press-scale animation is skipped entirely (icon/label render at scale 1 always) — but **the haptic still fires and navigation still happens**. Contract §1's `handlePressIn`/`handlePressOut` early-return before touching `scale.value`; `onPress`'s `Haptics.impactAsync(...)` call has no reduced-motion guard, by design.
