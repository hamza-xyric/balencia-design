- All six surfaces are bundled/local visual prototypes. No UI may claim a real provider connection, playback, store review, upload/download/share/delete/report, feedback submission, external navigation, sync, cache mutation, account change, or backend result.
- S67 must keep pagination outside variable sheet overlap, provide a native accessible comparison alternative, announce source/position/privacy, and separate thumbnail/high-resolution/offline/decrypt states. HIFI-67-01 is a privacy-safe code-native abstract/honest-null treatment unless active authority requires raster.
- S69 starts with no selected star. Selection is a native semantic 1–5 choice, public-store access is not sentiment-gated, Not now and Do not ask again have equal reach, and feedback/privacy controls remain scoped and reversible.
- S80 is an accepted pilot sentinel and remains byte-locked. Its accepted DVF-02 frame has active playback, Spotify provenance, a semantic seek range, Manage Spotify, reversible data controls, and the accepted HIFI-80-01 asset. I1 verifies those contracts without inventing alternate provider states or editing the screen/asset. W-TRUNC-80 remains active.
- S81 search, category selection, play/resume, save, retry, See all, and external-search confirmation must be native controls with 44px targets. Progress appears only for playable/resumable bundled fixtures; unavailable/processing/offline states cannot imply playback. HIFI-81-01 is a privacy-safe code-native abstract/honest-null treatment unless active authority requires raster.
- S85 uses `HifiShell` bottom action, renders exactly three blocker rows for the three-blocker fixture, and supports local accept/dismiss/undo plus consent/data/dependency detail without diagnostic certainty or a real generated plan.
- S98 is a review catalog whose examples may coexist only at `/screens/98`; production route fixtures must select exactly one route state. Immediate route copy never shimmers; only unresolved cached/status panels use skeletons. Success and disabled examples, cache/data controls, plain copy, recovery paths, and honest no-ETA/provider capability are required.

## Shared acceptance contract

- 390×844 phone; actual 125% root text; reduced motion; no horizontal overflow; no hidden bottom action; named controls >=44px; inputs >=16px; no nested interactives; semantic selected/pressed/disabled state; modal focus entry/trap/Escape/restore.
- Empty isolated storage/cookies and blocked fetch/XHR/WebSocket/EventSource/beacon/geolocation/media/file/share/clipboard/notification/payment/external navigation.
- Exact I1 product/API/verifier/production-input/100-sentinel start/end fingerprints; zero console/page/capability/external-request events.
- Full data-control states name category, source, scope/audience, freshness, confidence, retention, export, revoke, delete, and correction where applicable.
- Every screenshot context is deterministic, meaningfully distinct, and bound to one explicit `data-i1-state` marker.
