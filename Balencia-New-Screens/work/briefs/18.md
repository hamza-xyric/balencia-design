# FUNCTIONAL CONTENT BRIEF: Explore Section (Screen 18)

## 1. Purpose
Explore is Balencia’s browsable feature discovery catalog, answering "what else can I do in this app?" without requiring the user to ask CIA. It uses AI-driven recommendations at the top, followed by a categorized grid of every life domain, wellbeing feature, and standalone tool.

## 2. Entry and Exit Paths
*   **Entry Paths:** 
    *   Pushed from Me Main [17] via the "see all" link in the Explore preview section.
*   **Exit Paths:**
    *   **Primary:** Tap any module card → pushes specific domain dashboard [26-36], standalone feature [37-41, 45-48, 59, 61-62], or wellbeing feature [44, 49, 52-58, 60, 63] to the stack.
    *   **Secondary:** Tap Back button or screen edge swipe → pops stack back to Me Main [17].
    *   **Tertiary:** Search filter → hides UI to show only matching modules.

## 3. Information Architecture (Top-to-Bottom)
1.  **Sticky Header:** Back button + "explore" title.
2.  **Search Bar:** Pill-shaped controlled input for filtering modules.
3.  **AI Recommendation Rail ("Suggested For You"):** Horizontal scroll. 
    *   *If user has ≥5 active domains:* Features a Hero "Your active domains" recap card containing a micro ConstellationRadar, followed by 2-3 suggested module cards.
    *   *If <5 domains:* Features standard suggested module cards only.
4.  **Domain Sections (Catalog):** Vertical scroll using sticky headers. Contains 9 domain categories:
    *   Fitness and movement
    *   Nutrition and diet
    *   Finance and money
    *   Career and work
    *   Relationships
    *   Spirituality
    *   Learning and growth
    *   Creativity
    *   Wellbeing
5.  **Standalone Features Section ("More Features"):** 2-column grid of non-domain tools (Journal, Habits, Calendar, etc.).
6.  **Bottom Tab Bar:** Global navigation (Me tab active).

## 4. Features & Capabilities
*   **AI Module Recommendations:** Dynamically suggests 2-3 modules based on recent goals, mood, time of day, and underexplored domains.
*   **Cross-Domain Life Balance Visualization:** Displays a 10-domain radar polygon summarizing the user's "Life Power" shape at a glance.
*   **Client-Side Search:** Real-time, live filtering of the catalog by module name or domain. Hides suggestions while active.
*   **Domain Engagement Tracking:** Surfaces XP, stat levels, and progress bars on explored domain dashboards.
*   **Premium Paywall Routing:** Identifies locked modules and routes free users to preview/paywall screens.
*   **Motivation Adaptation:** Dynamically swaps suggested modules based on detected user motivation (e.g., simple journaling for low motivation, data-heavy dashboards for high motivation).

## 6. Data Fields & Metrics
*   **Suggested Modules Array:** *Source: AI Recommendation Engine.* (Context: recent goals, mood signals, time of day, underexplored domains).
*   **Domain Stat (0-99):** *Source: `domainStats[domain]`.* Engagement score.
*   **Domain Level (`Lv.N`):** *Source: `domainStats[domain]`.* RPG-like level.
*   **XP to Next Level:** *Source: `domainStats[domain]` (`currentXP`, `nextLevelXP`).* Used for continuous progress bars and header hairline arcs.
*   **Active Domain Count:** *Source: `domainStats` array.* Gates the visibility of the ConstellationRadar (requires ≥5).
*   **Subscription State:** *Source: User Entitlements.* Gates lock icons and paywall routing.

## 7. Screen States
*   **Cold-start / Day 1:** Full catalog visible. No lock icons. No visualizations. Suggested rail shows 3 "start here" cards. Eyebrow reads "Popular with Balencia."
*   **Loading:** Depth-preserving skeletons maintain layout. Suggested rail shows "CIA is reading your domains..." Radar skeleton shows axis/rings, ghosting into data.
*   **Empty (Search):** All sections hidden. Centered "no modules match..." copy.
*   **Partial (Data Sync):** Stat previews and radar dots appear only for synced domains; ghosted/unexplored domains show plain cards.
*   **Error (Network/Sync):** Surfaces remain navigable. Fallback to static cached catalog. "Couldn't sync..." copy appears.
*   **Error (AI Failure):** Silent UI swap to "Popular with Balencia" static cards.
*   **Offline:** Pull-to-refresh dimmed. Static catalog retained.
*   **Disabled (Premium Lock):** 0.4 opacity card, lock glyph + tier word visible.

## 8. Interactions, Gestures & Motion
*   **Gestures:** 
    *   *Tap:* Module card (navigation), Search bar (focus), Clear X (reset).
    *   *Swipe:* Edge swipe right (stack pop back).
    *   *Scroll:* Horizontal (suggested rail), Vertical (sticky headers/domain catalog).
*   **Motion Choreography:**
    *   *Entrance:* Search bar fades up -> Radar polygon self-draws (`stroke-draw` 1200ms) -> Suggested cards stagger -> Domain sections fade sequentially -> Explored StatBars rise left-anchored (`--dur-slow` 520ms) upon scroll-into-view.
    *   *Search:* Non-matching cards execute 160ms fade-out.
    *   *Reduced Motion:* All elements snap to final state instantly. Radar renders as completed static polygon.

## 9. Free vs. Premium Gating
*   **Entitlement Display:** Locked modules display a lock icon alongside the text label "Plus" or "Pro". Status is never communicated by color or icon alone.
*   **Routing:** Tapping a locked module routes the user to a preview or paywall screen.
*   **Behavior:** Lock badges are dynamically driven by the user's actual subscription state and are completely hidden for users who already hold the required tier (e.g., Plus locks are hidden for Plus users).

## 10. Cross-Domain Hooks
*   **"Life Shape" Navigation:** The "Your active domains" micro-radar serves as a cross-domain hook, allowing the user to visually jump to their weakest or least explored life area.
*   **AI Contextual Suggestions:** Connects distinct life areas based on real data (e.g., "Based on your recent fitness activity, these nutrition modules might help").
*   **Life Power Summation:** The visual stat bars on domain dashboards aggregate visually into the user's overall "Life Power" identity, mirroring data found on the Home and Life Areas screens.

*Note on Contradiction Resolution: The source documents contained a structural conflict regarding the screen's focal hierarchy (IA suggested the horizontal "Suggested For You" scroll was most prominent, while Visualization/Premium Craft specs demanded the micro ConstellationRadar be the sole focal hero). Per the latest audit integration, this brief treats the micro ConstellationRadar as the authoritative single focal point.*
