# FUNCTIONAL CONTENT BRIEF: Social Buddy Profile

## 1. Purpose
The Social Buddy Profile is a trusted-person detail screen for Balencia’s social layer. It displays who the buddy is, shared commitments, privacy controls, and messaging capabilities without exposing a public social feed.
*(Note: Per instructions, all occurrences of the coach persona "SIA" have been renamed to "CIA").*

## 2. Entry and Exit Paths
**Entry Paths (Stack Push):**
*   Direct Chat `[75]`
*   Accountability `[46]`
*   Community `[40]`
*   Leaderboard `[39]`
*   Competitions `[47]`
*   User profile bottom sheet

**Exit Paths:**
*   **Back Chevron:** Returns to origin screen.
*   **Message Button:** Routes to Direct Chat `[75]`.
*   **Shared Mission Card:** Routes to Mission Detail `[14]` (filtered to shared accountability context).
*   **Avatar Tap:** Opens photo preview modal.
*   **Report/Block:** Routes to Report / Block `[64]`.

---

## 3. Information Architecture
**Scroll Behavior:** Vertical ScrollView with fixed sticky header and fixed dual bottom actions (above the global tab bar).

**Top-to-Bottom Layout:**
1.  **Fixed Header:** Back chevron + Screen Title.
2.  **Buddy Hero Card (Focal Point):** Buddy avatar, name, relationship summary, status pills, and a shared-domain radar visualization.
3.  **Shared Missions Section:** Section eyebrow followed by a vertical list of shared mission progress cards.
4.  **Network Controls Card:** Grouped settings for sharing, permissions, and safety.
5.  **Fixed Bottom Actions:** Dual buttons for Privacy and Messaging.
6.  **Global Tab Bar:** Persistent navigation (Me tab active).

---

## 4. Features and Capabilities
*   **Identity & Context:** View buddy's avatar, name, and specific relationship summary.
*   **Relationship Visualization:** Visual radar shape showing shared life domains between the user and buddy.
*   **Shared Accountability:** Track shared missions via continuous progress bars and constructive framing text.
*   **Contact Invitation:** Invite buddies to new missions via a contact/invite sheet.
*   **Granular Permissions:** Manage how data is shared and what specific permissions the buddy holds.
*   **Safety Controls:** Access reporting and blocking capabilities.
*   **Direct Messaging:** Secure, private chat routing.
*   **Photo Preview:** Tap avatar to view an enlarged profile photo.

## 7. Screen States
*   **Default / Active:** Fully populated cards, all actions enabled.
*   **Cold-start / Empty:** Hero rendered; Shared missions replaced by a warm banner prompting an invite.
*   **Loading:** Depth-preserving skeletons for avatar, text, and progress tracks. Fades/morphs into data.
*   **Buddy Request Pending:** Hero rendered; "pending" pill visible; Message button visually dimmed (50% opacity) but explicitly explained via copy.
*   **Removed Buddy:** Warm reconnect banner displayed above hero. Message button remains fully clickable but triggers a helpful toast rather than routing to chat.
*   **Partial Data / Error:** Failed zones show retry banners. Cached data is retained where available. Error borders isolate the failure.
*   **Offline:** Cached data shown. Messaging action dimmed with explanatory tooltip.

## 8. Interactions, Gestures, and Motion Intents
**Interactions & Gestures:**
*   **Tap (Avatar):** Opens larger profile photo preview.
*   **Tap (Mission Card):** Routes to filtered Mission Detail.
*   **Tap (Network Controls):** Opens contact invite sheet, permission toggles, or report/block flows.
*   **Tap (Message):** Routes to Direct Chat (or triggers toast if removed/pending).

**Motion Intents:**
*   **Entrance Choreography:** Hero fades in first. Mission cards rise with a staggered effect (40-80ms delay between each).
*   **Progress Bars:** Animate from 0 to target value (520ms duration) using a continuous easing curve.
*   **Reduced Motion:** All entrances load instantly at final state; progress bars render fully filled without animation.

## 10. Cross-Domain Hooks
*   **Shared-Domain Radar:** A visual instrument mapping the exact intersection of the user's and buddy's shared life areas (e.g., Fitness + Learning), reframing a flat profile into a "relationship shape."
*   **CIA Insights:** The CIA persona provides deep cross-domain observations based on buddy data (e.g., *“CIA spotted you both improved your sleep on run days”*), linking Fitness routines to Sleep health.
*   **Accountability Routing:** Direct, bidirectional hooks from individual Missions to this Social Profile, establishing a shared context for independent goals.

### ⚠️ Source Contradictions Flagged
1.  **Message Button State (Removed Buddy):** The standard interaction table specifies the Message button should be *hidden/disabled* with hero opacity reduced to 70% when a buddy is removed. However, the "Premium Craft" and "Resolved Decisions" sections explicitly mandate that the button *remains clickable* at 100% opacity (triggering a toast) to give the user agency. **Resolution:** The functional brief sides with the latter (keeping the button actionable) as it is explicitly marked as the "current source of truth" under Resolved Decisions.
2.  **Inert Controls:** The original ASCII wireframe implied flat, unactionable text labels. The "Audit Feedback Integration" corrects this as a launch-blocking critical finding, mandating that all controls (Avatar, Missions, Privacy, Message) be fully wired to routes `[75]`, `[14]`, and `[64]`.
