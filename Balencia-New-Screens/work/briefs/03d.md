# FUNCTIONAL CONTENT BRIEF: Complete Profile (03d)

## 1. Purpose
Captures missing user profile data (Date of Birth, Gender, optionally First/Last Name) immediately following a social authentication flow (Google/Apple) where the OAuth provider omitted these fields. This data is required for Balencia to deliver age-appropriate and gender-personalized health coaching. 

## 2. Entry and Exit Paths
*   **Entry Paths:** Stack push directly from Social Auth success on Sign Up [03], triggered automatically when the OAuth callback detects null values for DOB or gender. 
*   **Primary Exit:** Consent [03c] via stack push (profile successfully completed or skipped).
*   **Secondary Exits:** "Skip for now" link navigates directly to Consent [03c] without requiring data entry.
*   **No Back Button:** Account is already created via social auth; users cannot navigate backward.

## 3. Information Architecture
**Layout Structure:** Scrollable view (content scrolls if keyboard active or viewport is small). 
**Top-to-Bottom Component Stack:**
1.  **Status Bar Zone:** Standard mobile status bar.
2.  **Brand Anchor:** Small logo symbol (centered).
3.  **Heading Area:** Screen title.
4.  **Subtitle Area:** Explanatory copy.
5.  **CIA Coaching Note:** CIA avatar + introductory copy.
6.  **Form Fields Group:** 
    *   Date of Birth input.
    *   Gender input.
    *   *Conditional:* First Name + Last Name (split row, only shown if OAuth did not supply them).
7.  **Readiness Indicator:** Continuous progress bar denoting form completion status.
8.  **Primary CTA:** "Continue" button.
9.  **Secondary Action:** "Skip for now" text link.
10. **Home Indicator:** Standard mobile home indicator.

## 4. Features and Capabilities
*   **Form Data Entry:** Native date picker for DOB and bottom sheet selector for Gender.
*   **OAuth Data Gap Filling:** Dynamically renders First/Last name fields *only* if the social auth provider omitted this data.
*   **Progressive Form Readiness:** A non-blocking UI progress indicator that continuously tracks form completion without preventing submission.
*   **Inline Form Validation:** Auto-validates age restrictions (18+) and field minimums as the user interacts.
*   **Deferred Submission:** Users are not hard-blocked by missing data; they can bypass the form entirely to reach the core app value.

## 7. Screen States
*   **Cold-start / Day-1:** Fresh empty form; interactive elements enabled.
*   **Loading / Submitting:** "Continue" CTA shows a spinner; button becomes non-interactive; inputs remain editable.
*   **Success:** Brief success glow on CTA, followed immediately by stack push navigation to Consent [03c].
*   **Error (Validation & System):** Inline red text appears directly below the invalid field. Top-mounted toasts appear for network/server failures. 
*   **Offline:** Top-mounted banner warning of lost connectivity.
*   **Reduced Motion:** All fade-in/stagger entrance animations, error slide-downs, and success glows are instant/bypassed.
*   **Layout Adaptation (Small Screens):** The conditional First/Last name row stacks vertically on viewports < 320pt.

## 8. Interactions, Gestures, and Motion
*   **Taps:** Tap DOB (opens wheel/calendar picker), Tap Gender (opens bottom sheet), Tap Name fields (raises keyboard), Tap "Continue" (validates/submits), Tap outside fields (dismisses keyboard).
*   **Swipes:** Swipe down on Gender bottom sheet to dismiss without selecting.
*   **Motion Intents:** 
    *   *Entrance:* Staggered fade-in and upward translation of modules on screen mount.
    *   *Focus:* Input borders scale depth/change thickness on focus.
    *   *Feedback:* Pressing CTA causes a micro-scale. Successful submission triggers a transient glow flash before navigating away.
