# Functional Content Brief: Transaction / Budget Detail

## 1. Purpose (2 lines)
A dual-purpose detail screen that renders either a single transaction or a budget category drill-down. It enables users to review, edit, and contextualize financial records alongside AI-driven behavioral insights.

## 2. Entry and exit paths
**Entry Paths:**
*   **Transaction View:** Stack push from Finance Dashboard (Screen 30) via tapping a transaction row.
*   **Budget View:** Stack push from Finance Dashboard (Screen 30) via tapping a budget category row.
*   **Internal Navigation:** In Budget View, tapping a transaction in the filtered list pushes to the Transaction View within the same stack.

**Exit Paths:**
*   **Primary:** Back button / swipe-right edge gesture returns to Finance Dashboard (Screen 30).
*   **Secondary:** Tapping CIA Context Card navigates to CIA Chat (Screen 09).
*   **Overlays:** Tapping edit, delete, category, or budget CTAs opens bottom sheet modals (dismissible via drag-down or cancel).

## 3. Information Architecture
The screen operates in two distinct modes driven by route context. 

**Transaction View (Top-to-Bottom):**
1.  **Header Bar:** Back chevron, "Transaction" title, Edit (pencil), Delete (trash).
2.  **Amount Display:** Hero transaction amount and type label.
3.  **Category Chip:** Pill indicating the transaction category.
4.  **Details Card:** Metadata block (Merchant, Date, Notes).
5.  **Receipt Photo:** Conditional visual reference.
6.  **CIA Context Card:** Behavioral insight note.
7.  **Recategorize Button:** CTA to change category.
8.  **High-Motivation Summary:** Conditional inline figure (e.g., monthly category spend).

**Budget View (Top-to-Bottom):**
1.  **Header Bar:** Back chevron, Category name title, Edit (pencil).
2.  **Category Display:** Category icon and name.
3.  **Budget Overview Card:** Container holding:
    *   Allocated amount.
    *   Donut Visualization (Hero).
    *   MacroBar Visualization (Progress + Pace Tick).
    *   Status Read (Burn vs. Time left).
4.  **CIA Insight Card:** Behavioral pattern note.
5.  **Trend Visualization:** Conditional Sparkline.
6.  **Filtered Transaction List:** Scrollable rows.
7.  **Edit Budget Button:** CTA to modify allocation.

## 4. Features and capabilities
*   **Dual-Mode Rendering:** Single screen shell dynamically handling transaction vs. budget data.
*   **Transaction Management:** Inline editing of metadata, note-taking, and receipt scanning/uploading.
*   **Categorization:** Ability to recategorize transactions via a bottom sheet picker.
*   **Secure Deletion:** Destructive action requiring explicit bottom-sheet confirmation.
*   **Honest Budget Tracking:** Visual progress tracking that caps visual fill at 100% even when over-budget (refusing to shame the user).
*   **Micro-Trend Analysis:** High-motivation users unlock a 4-week spend trend line for specific categories.
*   **Data-Driven Coaching:** CIA insights embedded directly into financial context, linking spending to life events.
*   **Interactive Data Filtering:** Tapping a slice in the Budget View donut filters the transaction list below it.

## 6. Data fields and metrics
*   **Transaction Amount:** Scalar value (+/-). *Source: Transaction record.*
*   **Category:** Identity metadata (name, associated color). *Source: Category metadata.*
*   **Merchant, Date, Notes:** String/Date metadata. *Source: Transaction record.*
*   **Receipt Image:** URL / Image blob. *Source: Transaction record.*
*   **Allocated / Spent / Remaining:** Currency totals. *Source: Finance API (budget category detail).*
*   **Budget Percentage:** Calculated metric (Spent / Allocated). *Source: Calculated.*
*   **Pace Tick / Days Remaining:** Integer (Time left in budget cycle). *Source: Finance API.*
*   **Category Breakdown:** Array of sub-totals by merchant. *Source: `budgetDetail.transactions`.*
*   **4-Week Category Trend:** 7-point resampled array of weekly spend. *Source: `budgetDetail.categoryTrend`.*
*   **CIA Suggestion Amount:** Proposed realistic budget limit. *Source: Calculated 3-month average.*

## 7. Screen states mentioned
*   **Transaction Modes:** Full metadata, Partial (no notes/merchant), No receipt.
*   **Budget Health Modes:** Under-budget (≤90%), Near (90-100%), Over-budget (>100%), Complete (Fully spent), Day 1 / Cold-start.
*   **Cross-Component States:** Loading (skeleton/shimmer), Empty, Error (cached data + retry), Offline, Success (brief flash/glow).
*   **Adaptive Motivation States:** 
    *   *Low:* Core data only; CIA hidden; lists collapsed.
    *   *Medium:* Default layout.
    *   *High:* Unlocks 4-week Sparkline and monthly spend summary text.
*   **Delete Confirmation:** Single warning state.

## 8. Interactions, gestures, motion intents
**Gestures:**
*   **Swipe right from edge:** Navigate back.
*   **Tap:** Trigger buttons, open bottom sheets, select inline text inputs.
*   **Drag down:** Dismiss bottom sheets.
*   **Long-press (Receipt):** Open replace/delete options menu.
*   **Pull-to-refresh:** Force reload API data.
*   **Tap Donut Slice:** Filter transaction list below by that merchant/sub-category.

**Motion Intents:**
*   **Screen Enter:** Stack push (slide in from right).
*   **Hero Draw-First (Budget View):** Donut arcs sweep clockwise from 12 o'clock → MacroBar fills 0→% → Sparkline draws L→R.
*   **Count-up:** Budget hub and metrics animate from 0 to final value.
*   **Textual Enter (Transaction View):** Hero amount scales up (0.9→1.0); cards fade and translate upward.
*   **Overlays:** Bottom sheets slide up; backdrop fades in.
*   **Deletion:** Row dissolves (height to 0) before screen pops.

## 9. Free vs premium gating
*Explicit gating is not detailed for core tracking features on this screen.* 
However, high-motivation data visualizations (specifically the 4-week micro-trend Sparkline) follow premium-depth data intelligence profiles. Deep AI behavioral analysis provided by the CIA is a core value proposition of the app's intelligence engine.

## 10. Cross-domain hooks (correlations, AI insights)
The **CIA Context/Insight Card** is the primary cross-domain hook. It correlates financial data with external life variables:
*   *Examples:* Linking dining overspending to "stressful work weeks" or "months with 3+ all-nighters."
*   *Intent:* Transforms flat numbers into behavioral feedback loops, prompting the user to "Breathe, plan meals on stress days." Tapping this hook launches the broader CIA Chat (Screen 09) domain.

## ⚠️ Explicit Contradictions in Source Documents
The source material contained several direct conflicts between legacy specifications and newer premium craft/audit feedback. Per your instructions, these are flagged rather than silently resolved:

1.  **Budget Persona Name:** Source explicitly names the AI persona **"SIA"** in architecture, copy, and wireframes. However, the global product context (and this brief's mandate) requires it to be renamed **"CIA"**. *(Resolved globally as CIA).*
2.  **Over-Budget Visual Treatment:** Legacy components specify turning the progress bar **"alarm-red (#f44336) with a pulsing warning icon."** This directly contradicts the Visualization audit, which mandates a **"non-shaming/loss-aversion"** treatment where the bar never changes color (stays brand accent), caps visually at 100%, and displays a neutral "! $N over" glyph.
3.  **Primary Visualization Focus (Budget View):** Legacy IA states the "Progress bar" is the dominant visual element. The Design Elevation pass explicitly contradicts this, retiring the flat bar in favor of a **"warm-glow Donut composition"** as the single ≥96px hero focal point, reducing the progress metric to a secondary macrobar.
4.  **Empty State Copy vs. Wireframe:** Legacy copy demands mapping the zero-state to a **"100% remaining green progress bar."** The audited empty state explicitly forbids this, requiring **"ghosted full-ring outline + 'No spending...'"** and a 0% fill macro bar with a "budget fully available" status read instead of an inverted green bar.
