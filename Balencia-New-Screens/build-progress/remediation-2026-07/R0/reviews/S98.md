## Dimension notes
1. Spec conformance — issue: spec's States section names six required treatments (Default, Skeleton, Empty, Error, Success, Disabled); the build demonstrates Default/Offline, Skeleton, Empty/Forbidden, Error/Unauthorized plus bonus Maintenance/Coming-Soon route cards, but Success (`--glow-done` reconnect confirmation) and Disabled (40%-dim action with reason) are absent from the page entirely — see Defect #2.
2. Canon fidelity — issue: Offline banner uses `GlassCard tone="you"` (orange glow = "you · effort · streak · active metric" per §3) on a connectivity-error card, not an effort/active-metric moment, with no stated "why" — see Defect #4. Purple `tone="cia"` on Maintenance/Coming Soon is covered by A24-003, not re-filed.
3. Data honesty — issue: the Cached Snapshot card shows fully-resolved values (Steps 8.2k, Sleep 7.5h, Run mission 68%) directly beside a perpetually-animating `.skeleton-block` shimmer bar — an infinite "still loading" signal paired with data already presented as final — see Defect #3.
4. Cross-cutting (§8) — issue: this is a data-touching surface (cached steps/sleep/mission-progress, explicitly flagged "Stale health data") but shows only generic `Provenance` label chips with no retention/export/revoke/delete entry point, despite the screen's own spec explicitly requiring those chips and a canonical `ConsentRail` component already existing and used on 49 other screens in this codebase — see Defect #1.
5. Composition craft — otherwise clean alignment/spacing across the stacked sections, no truncation/overlap visible in the screenshot; see Defect #5 for a hierarchy note.
6. Copy voice — sentence case, no exclamation marks, second person ("your session", "your role", "your missions") throughout — except see Defect #6 (one fabricated, off-register line).
