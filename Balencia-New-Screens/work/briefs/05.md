# Functional Content Brief: Forgot Password

## 1. Purpose
A single-purpose utility allowing users to securely request a password reset link. Designed to be quick and reassuring, guiding the user from email entry to a calm confirmation state.

## 2. Entry and Exit Paths
*   **Entry:** Stack push (depth 2) from Sign In [04] via the "Forgot password?" link.
*   **Primary Exit:** Stack pop back to Sign In [04] via the back button or the "back to sign in" call-to-action.

## 3. Information Architecture
**Global Behavior:** Fixed view (no scroll). Pre-auth (no tab bar visible).

**Region 1: Top Navigation**
*   **Back Button:** Left-aligned, 44x44pt touch target. Performs stack pop to Sign In [04].

**Region 2: Brand & Context (Default & Confirmation States)**
*   **Brand Symbol:** 48x48pt centered. 
*   **Heading:** Center-aligned.
*   **Instructional Text:** Center-aligned, ≤2 lines.

**Region 3: Form (Default State Only)**
*   **Email Input:** Full-width minus margins, 52pt height.
*   **Primary CTA:** Full-width minus margins, 56pt height ("send reset link").

**Region 4: Success (Confirmation State Only)**
*   **Success Icon:** 56pt circle with checkmark glyph.
*   **Primary CTA:** "back to sign in".
*   **Secondary Action:** "send again" text link.

## 4. Features and Capabilities
*   **Email Submission:** Validate email format and trigger a password reset API request.
*   **State Transition:** Crossfade from the input form to a success confirmation view upon API success.
*   **Email Masking:** Dynamically display the submitted email in a masked format (first letter + mask middle + domain) in the confirmation state.
*   **Resend Link:** Capability to trigger the reset API call again if the email fails to arrive.
*   **Rate Limiting (System Protection):** Enforces a 60-second cooldown timer after 2 resend attempts, disabling the function temporarily to prevent spam.

## 5. UI Copy (Verbatim Strings)
*   **Back Button (A11y):** "Go back to sign in"
*   **Default Heading:** "Reset your password"
*   **Default Instruction:** "Enter your email and we'll send you a reset link"
*   **Input Placeholder:** "email address"
*   **Default CTA:** "send reset link"
*   **Confirmation Heading:** "Check your email"
*   **Confirmation Instruction:** "We sent a reset link to [masked email]"
*   **Confirmation CTA:** "back to sign in"
*   **Resend Context:** "Didn't receive it?"
*   **Resend Action:** "send again"
*   **Resend Success (Temporary):** "sent"
*   **Error (Email not found):** "No account found with this email address."
*   **Error (Invalid format):** "Please enter a valid email address."
*   **Error (Network):** "Something went wrong. Please try again."
*   **Error (Rate limited):** "Too many requests. Please wait a few minutes."
*   **Error (Resend failed):** "Could not resend. Try again."
*   **Offline Banner:** "You're offline. Reset link will send when you're back online."

## 6. Data Fields and Metrics
*   **User Email Address:** 
    *   *Source:* User-entered via input field.
    *   *Validation:* Must match standard email format.
*   **Masked Email String:** 
    *   *Source:* Dynamically generated from User Email Address (e.g., `j***@email.com`).
*   **Resend Cooldown Timer:**
    *   *Source:* Local client state / API HTTP 429 response header.
    *   *Metric:* 60-second countdown `[60..0]s`.

## 7. Screen States
*   **Cold-start / Day-1:** Default form state. Centered heading, empty input with placeholder.
*   **Focused / Filled:** Input field contains user text; system keyboard raised.
*   **Disabled:** CTA button visually dimmed and non-interactive. Triggered when the email field is empty or contains an invalid format.
*   **Loading (Submit in flight):** Input field transforms into a skeleton (preserving borders and depth, body pulses). CTA text is replaced by an inline spinner.
*   **Success / Confirmation:** Replaces form view. Displays success icon, masked email text, and primary navigation back to Sign In.
*   **Resend Success:** Temporary 3-second state where "send again" changes to "sent" before reverting.
*   **Error (Email not found):** Input border swaps to error red; error text appears directly below.
*   **Error (Invalid format):** Same visual behavior as "Email not found".
*   **Error (Network):** Form persists. Toast appears at the top, auto-dismisses after 4s.
*   **Error (Rate Limited):** Form persists. Toast appears at top. Resend link is disabled; a countdown timer renders.
*   **Error (Offline):** Form persists. Bottom banner appears with offline messaging.

## 8. Interactions, Gestures, Motion Intents
*   **Tap (Back Button):** Stack pop to Sign In [04].
*   **Tap (Email Field):** Focus input, raise keyboard.
*   **Tap (Send Reset Link):** Validates email, triggers API request.
*   **Tap (Back to Sign In):** Stack pop to Sign In [04].
*   **Tap (Send Again):** Re-triggers reset email API.
*   **Swipe Right (Screen Edge):** iOS back gesture → stack pop to Sign In [04].
*   **Motion (Entrance):** Staggered fade-in of elements on screen mount.
*   **Motion (Default → Confirmation):** Form fades out. Confirmation content fades in. Success circle scales from 0.5 to 1.0 with a slight overshoot (bounce/ease-flow).
*   **Motion (Reduced Motion):** All animations are bypassed. Elements appear instantly in their final settled state. The success circle renders at full scale with its glow applied.

## 9. Free vs. Premium Gating
*   **Not Applicable.** This is a pre-authentication utility screen. All features are accessible to all users attempting to access their account.

## 10. Cross-Domain Hooks
*   **Not Applicable.** As an authentication utility, there are no correlations, CIA insights, or links to other life areas/dashboard domains.

## ⚠️ Critical Source Spec Corrections & Directives
1. **Persona Renaming:** The source spec audit mentions "SIA" (e.g., "first SIA value", "SIA onboarding"). As mandated, **SIA has been permanently renamed to CIA** (Continuous Improvement Architecture / Coach Persona) across this brief. 
2. **Contradiction Resolution (Stale Flat UI):** The original ASCII wireframe drew a "bare" input box on a flat background. The `Premium Craft` and `Audit Feedback` sections explicitly flag this as an error and mandate warm-surface depth (inset top-edge highlights, brown-800 input fill). This brief treats the `Premium Craft` instructions as the single source of truth for functional state behavior.
3. **Visual Styling Exclusion:** Per the core directive, all old visual styling tokens (Sora fonts, ink-900, #34A853, 60/30/10 color ratios, VK-002 GaugeRing primitives) have been intentionally stripped from this brief, leaving only functional content, behaviors, and structural intent.
