# Functional Content Brief: 96-Health-Data-View

## 1. Purpose
Provides a provider-neutral dashboard for users to view wearable recovery, strain, and sleep data. Acts as the central hub for managing device connections, resolving proprietary health metrics into a unified view, and routing insights to the CIA (Coach) for action.

## 2. Entry and Exit Paths
*   **Entry Paths:** 
    *   Primary Navigation: "Health & fitness" tab (`/whoop` route, functionally upgraded to `/health-data`).
    *   Deep Link: OAuth Callback success (`/auth/whoop/callback` or future `/auth/oura/callback`, etc.).
    *   Dashboard Hook: Tapping a syncing/readiness widget on the Today Dashboard.
*   **Exit Paths:**
    *   "Talk to CIA" (navigates to `/ai-coach` with health context attached).
    *   "Manage Devices" (navigates to `/settings` integrations tab).
    *   Standard browser back or bottom navigation.

## 3. Information Architecture (Mobile)
*Inferred from the "Health Connections" wireframe obligations and cross-referenced with current `/whoop` capabilities.*

*   **Header & Title Block**
    *   Dynamic Greeting & Date.
    *   Data Provenance Banner (Source-Aware indicator).
*   **Primary Device Status Module**
    *   Primary device sync status indicator.
    *   "Add new device" shortcut.
*   **Hero Metric: Unified Readiness**
    *   House Recovery Score (composite).
    *   Contributing factors (Sleep, Strain, HRV).
*   **Vital Metrics Grid (Source-Aware)**
    *   Recovery metrics (HRV, RHR).
    *   Strain metrics (Day Strain, Active Calories).
    *   Sleep metrics (Sleep Performance, Time in Bed).
*   **CIA Insight Strip**
    *   AI-generated health insight based on current metrics.
*   **Historical Trends Module**
    *   Interactive charts (Readiness, Sleep, Strain over time).

## 4. Features and Capabilities
*   **Provider-Neutral Device Support:** Capability to connect and ingest data from cloud/OAuth devices (Whoop, Oura, Fitbit) and native bridges (Apple Health, Samsung Health Connect). *(Note: Apple/Samsung require mobile app bridges - see contradictions).*
*   **Source-Aware Metric Display:** Ability to display the raw, proprietary score from the source device (e.g., Whoop Strain, Oura Readiness) alongside Balencia's unified/house score.
*   **Metric Source Prioritization:** User capability to set a "primary device" per metric if multiple devices are connected.
*   **Automated Device Syncing & Backfilling:** Background fetching of new data and historical data upon initial connection.
*   **Data Deletion & Revocation:** User capability to revoke OAuth permissions and delete synced health data from Balencia's servers.

## 6. Data Fields and Metrics
| Field / Metric | Data Source | Context |
| :--- | :--- | :--- |
| **House Recovery Score** | Balencia Algorithm | Normalized 0-100 score blending all connected sources. |
| **Device Recovery Score** | Source Device (Whoop/Oura) | Provider-specific proprietary score. |
| **Heart Rate Variability (HRV)** | Wearable | Milliseconds. |
| **Resting Heart Rate (RHR)** | Wearable | Beats per minute. |
| **Day Strain / Body Battery** | Wearable | Scale depends on provider (e.g., Whoop 0-21, Garmin 0-100). |
| **Sleep Performance** | Wearable | Percentage of optimal sleep. |
| **Respiratory Rate** | Wearable | Breaths per minute. |

## 7. Screen States
*   **Loading / Syncing:** "Syncing..." animation when fetching initial data or manual refresh.
*   **Empty (No Connections):** Prompt to connect first health device.
*   **Disconnected / Expired Token:** Warning state prompting user to "Reconnect" device.
*   **Error / Sync Failure:** "Sync failure" message when API limits are hit or cloud sync fails.
*   **Partial Data:** State showing some metrics but flagging missing data (e.g., "Strain synced, Sleep pending").
*   **Stale Data:** Warning when last successful sync was > 12 hours ago.
*   **Multi-Device Active:** UI variant showing overlapping data or source toggles when >1 device is connected.

## 8. Interactions, Gestures, and Motion
*   **Pull to Refresh:** Triggers manual background sync from connected providers.
*   **Swipe (Left/Right):** On historical charts to scrub through previous days' data.
*   **Tap (Metric Cards):** Expands to full-screen detail view showing data provenance and raw vs. normalized breakdowns.
*   **Tap (CIA Insight Strip):** Opens the `/ai-coach` interface with the specific health context pre-loaded.
*   **Motion Intent:** Subtle "breathing" or pulsing animation on the unified readiness score to indicate live status.

## 9. Free vs. Premium Gating
*   **Free Tier:** Basic connection to one device. Display of raw, provider-native scores only.
*   **Premium Tier:** Multi-device connections. House Readiness Score (normalized), historical trends beyond 7 days, and CIA insights/correlations.
*   **Upsell / Locked State:** When a free user connects a second device or attempts to view the unified score, trigger the standard `/locked` upgrade flow.

## 10. Cross-Domain Hooks & AI Insights
*   **CIA (Coach) Integration:** The CIA proactively analyzes health data. Example: if Recovery is low, CIA suggests modifying today's workout intensity in the `/workouts` domain.
*   **Wellbeing / Sleep:** Deep links between sleep metrics and the `/wellbeing/sleep` sub-page to correlate sleep quality with evening journal entries or stress levels.
*   **Knowledge Graph:** Health metrics become entities in the `/knowledge-graph`, allowing users to trace how a specific strain score impacts their overall "Life World."
*   **Goals:** Automatic adjustments to Fitness or Wellbeing goals based on physiological readiness.

---
### ⚠️ Explicit Contradictions & Source Flags
1.  **Branding vs. Route:** The source document states the product is moving toward a "provider-neutral" approach, but the actual backend route remains `/whoop` and contains provider-specific callbacks (`/auth/whoop/callback`). *Design must completely abstract the "Whoop" name from the UI while supporting the legacy route under the hood.*
2.  **Platform Capabilities vs. Feature:** The source explicitly states "Apple Watch/Apple Health and Samsung/Health Connect require a native or hybrid mobile app bridge; web alone cannot read those stores." *Designing this UI for mobile web must include an error/limitation state if a user attempts to connect Apple/Samsung without the native wrapper, whereas Oura/Fitbit/Whoop will work via cloud OAuth.*
3.  **Naming Inconsistency:** The source mentions both "SIA", "Sage", and "AI life coach". *Per instructions, "SIA" has been universally renamed to **CIA** for this brief.*
