## Design requirements

### Section order (architecture-plan.md §4.1, scope-hifi-today-missions.md Screen 12)

1. **TopBar** — greeting + level chip. Not wrapped in the entrance stagger (renders immediately,
   no animation).
2. **Cia coach card** (`FrostCard glow="cia" breathe` — **the one hero breathe on this screen**) —
   `CIAPresenceOrb` + static coach prompt + `TodayVM.dailyBrief.headline` (real/honest-null) + 3 local
   mood chips.
3. **Vitals** — 3× `GlassStatCard` from `TodayVM.pulse.metrics`.
4. **Life areas** (domain carousel) — `ChipDomainTag` × N from `TodayVM.domains` + a trailing "View
   all" chip → `router.push('/life-areas')`.
5. **Today's actions** — `MomentumBar` (local completion ratio) + action rows from
   `TodayVM.priorities`.
6. **Pinned missions** — top 2 via `pickPinnedMissions`, each a local row with `ProgressRing` + title,
   tap → `router.push(\`/mission/${id}\`)`.
7. **Persistent**: `FABQuickLog` → `router.push('/mission-create')`. **Do not render `GlassNavBar`** —
   it is already the `tabBar` of the `(tabs)` layout (`src/app/(tabs)/_layout.tsx`, already landed);
   rendering it again here would duplicate the bottom nav.

Sections 2–6 are each wrapped in a local `StaggerSection` (index 0–4) that fades/slides in with an
`index * MotionDuration.stagger` (80ms) delay — see "Motion" below.

### Exact copy strings (sentence case, no exclamation marks — with one documented literal-copy exception)

- Greeting core phrase: **`"Good Morning"` / `"Good Afternoon"` / `"Good Evening"`** (capital second
  word). This is a deliberate, documented override of the general sentence-case convention: both
  architecture-plan.md (`'Copy (exact): greeting "Good Morning, {name}"'`) and
  scope-hifi-today-missions.md (`greeting "Good Morning, Amira"`) quote this capitalization verbatim
  as **exact** copy — verbatim-quoted spec text wins over the general default. Full greeting = phrase
  + `", {firstName}"` when a real, non-empty `user.firstName` is available, otherwise the phrase alone
  (never invent a name).
- Level chip: `` `Level ${level.display}` `` (e.g. `"Level 14"` when real, `"Level —"` when
  `level.provenance.kind === 'null'` since `nullMetric()`'s `display` is already `'—'`).
- Coach prompt (static, always shown): `"What needs your "` + italic `"attention"` + `" today?"` —
  one word of Tiempos-style emphasis per canon, rendered as a nested `<Text style={styles.emphasis}>`
  with `fontStyle: 'italic', fontWeight: '600'` (matches the existing house pattern in
  `src/features/auth/sign-in-screen.tsx`'s `titleEmphasis` style — no Tiempos font file exists in this
  RN app yet, this is the established fallback).
- Coach headline: real → render `TodayVM.dailyBrief.headline` verbatim; honest-null →
  `"Cia doesn't have a briefing for you yet."` (write the apostrophe as `&apos;` in JSX text, matching
  house convention in `sign-in-screen.tsx` / `forgot-password-screen.tsx`).
- Mood chip labels (lowercase, matches the quoted hi-fi bracket text `[steady] [low] [wired]`):
  `"steady"`, `"low"`, `"wired"`. Local UI state only — **no write this batch** (no mood-log endpoint
  wired here; this is a documented, intentional gap, not an oversight).
- Section titles: `"Vitals"`, `"Life areas"`, `"Today's actions"` (apostrophe as `&apos;`), `"Pinned
  missions"` — small uppercase overline style, drawn directly from the composition map's own section
  names (normalized to sentence case).
- Vitals empty: `HonestNullState title="No pulse metrics available"` (verbatim reuse of the current
  file's existing copy — no detail text).
- Life areas empty: `title="No life areas yet"`, `detail="Cia will map these as you track more."`
- Today's actions empty (both the `MomentumBar` label and the list): `MomentumBar label="No actions
  logged yet"` with `state="null"`; `HonestNullState title="No priorities yet" detail="Cia will map
  them soon."` (verbatim reuse of the current file's existing priorities-empty copy).
- Today's actions non-empty: `MomentumBar label={\`${doneActions} of ${totalActions} done\`}` with

### Motion (ADR-6 keys; reduced-motion variant stated for every animation)

- **Entrance stagger** (the only new animation this packet introduces): a local `StaggerSection`
  component wraps sections 2–6 (index 0–4). Each instance holds `useSharedValue(reduceMotion ? 1 : 0)`
  and in a `useEffect` (deps `[index, progress, reduceMotion]`, matching the house convention already
  used in `momentum-bar.tsx`'s effect — no eslint-disable needed) sets:
  - reduced-motion → `progress.value = 1` immediately (final state, no animation);
  - otherwise → `progress.value = withDelay(index * MotionDuration.stagger, withTiming(1, { duration:
    MotionDuration.feedback, easing: Easing.bezier(...MotionEasing.physical) }))`.
  `useAnimatedStyle` maps `progress` to `{ opacity: progress.value, transform: [{ translateY: (1 -
  progress.value) * 12 }] }` — transform/opacity only, per ADR-6.
- **Coach hero breathe**: pass `breathe` to `FrostCard` — the component's own contract already
  specifies its internal reduced-motion handling (static glow, no pulse); this packet does not
  reimplement that.
- `CIAPresenceOrb state="idle"` — already-landed component already gates its own breathe on
  `useReducedMotion()` internally (verified in the landed file); this packet just renders it.
- Mood chips / action rows / pinned-mission rows use the existing house convention for press feedback
  — a plain `Pressable` function-style `style={({ pressed }) => [...]}` opacity dip (see
  `BalenciaButton`, `ErrorState`'s retry button) — **not** a Reanimated animation, so no separate
  reduced-motion branch is needed for these (matches existing codebase precedent, which does not
  special-case these either).
- Haptics: `Haptics.impactAsync(Haptics.ImpactFeedbackStyle.Light)` fires **only** when an action row
  transitions from not-done → done (the one true "confirm" on this screen) — computed and fired in the
  event handler **before** calling `setDoneActionIds`, never inside the state-updater function itself
  (updater functions can be invoked more than once by React and must stay pure — firing a haptic
  inside one risks a double-fire). No haptic on navigation-only taps (FAB, "View all", mood chips,
  pinned-mission row) — not requested by scope, do not invent it.

### Color roles (60/30/10) and honesty states

- Purple (`glow="cia"`, `CIAPresenceOrb`) appears **only** inside the coach card — the one Cia surface
  on this screen. Nowhere else on the screen uses purple.
- Orange (`glow="you"` implicitly via `MomentumBar`'s default, `StatusChip tone="orange"`, mood-chip
  active state, `FABQuickLog`) is the primary/effort color.
- Green appears only where the already-landed components resolve it themselves (e.g. `ProgressRing`
  auto-switches to green at 100% completion; `ProvenanceChip`'s `real` tone) — this packet does not
  hardcode green anywhere new.
- Every metric already carries its honesty state through the untouched adapter — this packet's job is
  to route `Metric<T>`/`Provenance` values into the viz components' `state`/`metric` props unchanged,
  and to write matching honest-null copy for the **structural** empty cases (empty arrays) that the
  adapter surfaces as `[]` rather than a `Metric`. Never invent a numeric value, countdown, or XP
  amount anywhere in this file.
- `GlassStatCard`'s `variant` for the 3 vitals cards must resolve to `'metric'` in practice this batch
  — see the `VITALS_SPARKLINES`/`densityShows` mechanism below. Never pass a fabricated `sparkline`
  array.

### Density tiers

`TodayScreen` accepts an optional `densityTier?: 'low' | 'medium' | 'high'` prop (default `'medium'`)
— must stay fully optional so `src/app/(tabs)/today.tsx`'s `<TodayScreen />` (zero props) keeps
compiling. Use the new pure `densityShows(tier, 'sparkline')` from `today-logic.ts` to gate whether a
`GlassStatCard` in the Vitals row is *allowed* to resolve to `variant="sparkline"`. Because
`TodayVM.pulse.metrics` carries no historical/trend array this batch (ADR-3: adapters unchanged),
declare a module-level `VITALS_SPARKLINES: Partial<Record<'energy' | 'recovery' | 'stress',
number[]>> = {}` (intentionally empty, documented as a forward-compat hook) and compute each card's
`sparkline` as `allowSparkline ? VITALS_SPARKLINES[entry.key] : undefined`, then
`variant={sparkline ? 'sparkline' : 'metric'}`. This wires the density gate for real (it is exercised
by `densityShows`'s own unit tests) without ever fabricating chart data — today it always resolves to
`'metric'`, and a future packet that adds a real trend field to the adapter only needs to populate the
lookup, not invent a new gating mechanism.

### Provenance chips

`GlassStatCard` already renders its own `ProvenanceChip` internally from `metric.provenance` (see its
contract above) — do not add a second, redundant `ProvenanceChip` around it. The header level chip
intentionally does not carry a separate `ProvenanceChip` (it is minimal header chrome, not a metric
card); its honesty is expressed through the muted tone + `"—"` fallback display instead.

### 44px targets and a11y labels

- Mood chips, action-row check circles, and pinned-mission rows all use `minHeight: TouchTarget` (and
  `minWidth: TouchTarget` for the mood chips specifically, since they are short-label pill buttons).
- `accessibilityRole="checkbox"` + `accessibilityState={{ checked: done }}` on each action row;
  `accessibilityRole="button"` + `accessibilityState={{ selected: active }}` on mood chips;
  `accessibilityRole="button"` on the pinned-mission row with a label stating the mission title and
  rounded percent complete.
- The TopBar row is wrapped in a single `accessible accessibilityLabel={...greeting + level...}`
  container so screen readers announce it as one unit (the underlying `StatusChip` primitive does not
  set its own accessibility props).

// Pure logic for the Today screen (BIOS-004 packet S1 — S12 hi-fi parity).
// No react-native, '@/constants/theme', '@/constants/motion', or reanimated
// imports here — vitest.config.ts runs src/**/*.test.ts under environment:
// 'node', and this file (or anything it imports) must stay importable there.
// The only import below is a type-only import of MissionVM, whose source
// file (src/services/adapters/missions.ts) itself has zero runtime
// react-native dependencies (verified: it only imports types from
// '@/services/api/dto/goals').
import type { MissionVM } from '@/services/adapters/missions';

/**
 * Time-of-day greeting phrase. Boundaries: hour 0-11 -> morning, 12-17 ->
 * afternoon, 18-23 -> evening (matches `Date().getHours()`'s 0-23 range).
 * Capitalization ("Good Morning" with a capital M, not "Good morning") is a
 * deliberate, verbatim match to the hi-fi spec's quoted exact copy
 * (architecture-plan.md S12: 'Copy (exact): greeting "Good Morning,
 * {name}"'; scope-hifi-today-missions.md S12: 'greeting "Good Morning,
 * Amira"') — overriding the general sentence-case copy convention for this
 * one quoted string only, per source-hierarchy precedence.
 */
export function greetingForHour(hour: number): string {
  if (hour < 12) return 'Good Morning';
  if (hour < 18) return 'Good Afternoon';
  return 'Good Evening';
}

/**
 * Selects up to 2 pinned missions for the Today home summary (architecture-
 * plan.md ADR-3 / §4.1: "Pinned Missions ... `useMissions()` primary
 * missions (top 2)"). Sort: isPrimary missions first, then descending
 * progress. Pure — does not mutate the input array.
 */
export function pickPinnedMissions(missions: MissionVM[]): MissionVM[] {
  return [...missions]
    .sort((a, b) => {
      if (a.isPrimary !== b.isPrimary) {
        return a.isPrimary ? -1 : 1;
      }
      return b.progress - a.progress;
    })
    .slice(0, 2);
}

export type DensityTier = 'low' | 'medium' | 'high';
export type DensityFeature = 'sparkline';

/**
 * Density-tier feature gate (COMPACT-CANON: "every screen defines
 * low/medium/high density variants"; architecture-plan.md ADR-3: "Density
 * tiers ... gating sparkline presence and optional sections"). Today gates
 * exactly one feature this batch: whether a GlassStatCard variant is
 * ALLOWED to resolve to 'sparkline' at all.
 *
 * Honesty note: TodayVM.pulse.metrics carries no historical/trend array
 * this batch (ADR-3: "adapters unchanged") — so today-screen.tsx also keeps
 * an empty `VITALS_SPARKLINES` lookup and only renders variant='sparkline'
 * when BOTH this gate is true AND a real array exists for that metric.
 * Right now that second condition is never true; this function exists so a
 * future packet that adds a real trend field only has to populate the
 * lookup, never invent a new gating mechanism.
 */
export function densityShows(tier: DensityTier, feature: DensityFeature): boolean {
  if (feature === 'sparkline') {
    return tier !== 'low';
  }
  return true;
}

function StaggerSection({
  index,
  reduceMotion,
  children,
}: {
  index: number;
  reduceMotion: boolean;
  children: ReactNode;
}): JSX.Element {
  const progress = useSharedValue(reduceMotion ? 1 : 0);

  useEffect(() => {
    if (reduceMotion) {
      progress.value = 1;
      return;
    }
    progress.value = withDelay(
      index * MotionDuration.stagger,
      withTiming(1, {
        duration: MotionDuration.feedback,
        easing: Easing.bezier(...MotionEasing.physical),
      }),
    );
  }, [index, progress, reduceMotion]);

  const animatedStyle = useAnimatedStyle(() => ({
    opacity: progress.value,
    transform: [{ translateY: (1 - progress.value) * 12 }],
  }));

  return <Animated.View style={animatedStyle}>{children}</Animated.View>;
}
