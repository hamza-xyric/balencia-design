## S49 — Progress photos

### Live defects

1. **Demo/personal state and analysis consent are ambiguous.** The screen displays precise personal-looking weight, BMI, measurements, body-fat, dates, and CIA correlation (`S49ProgressPhotos.tsx:62-64,83-114,120-139`) while only the chart is called “Illustrative” (`:97-99`). The opening copy explains that storage and analysis are separate but never states whether analysis is opted in (`:45-60`). This violates the spec’s requirement that analysis appear only after explicit opt-in (`49-progress-photos.md:96-102`) and keeps the old audit’s primary finding live (`VISUAL-001/audit/F1-health-fitness-nutrition.md:43`).
2. **Controls are present but not operational or complete.** Manage privacy, Export photos, Delete set, and Turn analysis off are native buttons with no handler or link (`S49ProgressPhotos.tsx:57-59,146-155`). Export/delete/revoke are visible, but category/scope/freshness/confidence/retention are absent. The spec requires export, hide, delete, revoke analysis, and delete-all to remain available (`49-progress-photos.md:101-108`).
3. **Required actions remain presentation-only.** `SectionTitle` renders `meta` as a span (`kit/chrome.tsx:78-83`), so “See all” and “Compare” are inert (`S49ProgressPhotos.tsx:117,131`). Checkpoints are non-interactive div rows (`:134-142,182-206`). The spec requires compare/log/consent/delete sheets and timeline actions (`49-progress-photos.md:91-94,119-125`).
4. **Range tabs are static and likely too narrow at 390px/125%.** They have correct 44px height but only `px-2.5` and no state handler (`S49ProgressPhotos.tsx:69-80`); short labels therefore do not guarantee the 44px width required by the spec (`49-progress-photos.md:130-134`). At 125% text scaling, the three-column metric row (`S49ProgressPhotos.tsx:105-115`) and compact range control are the primary wrap/collision risks.
5. **Surface/provenance hierarchy is incomplete.** The data-dense chart uses `GlassCard` (`S49ProgressPhotos.tsx:66-103`) although canon reserves `SolidCard` for charts/data density (`COMPONENT-CATALOG.md:15`). The CIA sentence correlates weight with photos but cites only wearable/logged sources (`S49ProgressPhotos.tsx:62-64`), omitting consented photo-timeline evidence/confidence.
6. **HIFI-49-01 has no explicit disposition.** The active slot requires privacy-safe, non-identifiable media (`_IMAGE-SLOTS.md:24`; `49-progress-photos.md:127-128`). Code-native icon checkpoints intentionally avoid real bodies (`S49ProgressPhotos.tsx:166-168,185-203`), which is a defensible privacy-safe direction, but the screen has no deterministic asset-disposition marker or waiver.
7. **Delete/revoke safety is missing.** “Delete set (3 photos)” and “Turn analysis off” act directly as inert buttons (`S49ProgressPhotos.tsx:146-155`) rather than opening the plain-language confirmations required by the spec (`49-progress-photos.md:123-125`).
