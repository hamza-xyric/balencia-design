# 2. Purpose
To capture missing user profile data (Date of Birth, Gender, optionally First/Last Name) immediately following a social authentication flow where the OAuth provider omitted these fields. This data is required for Balencia to deliver age-appropriate and gender-personalized health coaching. 

# 3. Entry & exit
* **Entry Paths:** Stack push directly from Social Auth success on Sign Up [03], triggered automatically when the OAuth callback detects null values for DOB or gender.
* **Primary Exit:** Consent [03c] via stack push (profile successfully completed or skipped).
* **Secondary Exits:** "Skip for now" link navigates directly to Consent [03c] without requiring data entry.
* **Correction from Brief:** The brief states "No Back Button" because the account is already created. However, to respect native iOS/Android UX and allow users to reference their OAuth account screen or read system prompts, a standard read-only `TopBar` (transparent, no back action) is used as an anchor.

# 5. Components
* **GlassCard:** Not used (form requires legibility over atmosphere).
* **SolidCard:** Form container (`--surface-2`, 28px radius, `rgba(255,255,255,.06)` border).
* **TopBar:** Transparent, no back chevron.
* **SectionHeader:** Overline labels for form fields inside the SolidCard (e.g., "DATE OF BIRTH").
* **GlassPillInput:** Name inputs. Variant: text. Height 52, radius 14 (corrected to 14 for inputs per Canon).
* **NEW: DateTrayInput:** A read-only input styled like GlassPillInput (radius 14) that triggers a native iOS/Android date picker wheel. *Rationale: GlassPillInput only covers typed text; date selection requires a native system wheel for mobile UX.*
* **NEW: SheetTriggerInput:** A read-only input styled like GlassPillInput (radius 14) that opens a bottom `Sheet`. *Rationale: Standardized trigger visual for bottom sheet selections.*
* **Sheet:** Bottom sheet `.glass-frost` (top-radius 28) for Gender selection. Variant: `action` (list of ListRow).
* **ListRow:** Used inside the Gender Sheet (56px min height, hairline separators).
* **CIAInsightCard:** Purple-tinted glass (`glow-cia`) with spark glyph. (Used for CIA Note to maintain cross-app consistency instead of a custom bubble).
* **ProgressBar:** `segmented` variant, 8px track. Fill logic: orange.
* **BtnPrimary:** "continue" CTA.
* **BtnGhost:** "Skip for now" link.

  * **Honest-null:** 0 of 2 ready to personalize. (Progress bar is empty track, app remains perfectly functional).

# 9. All states
* **Default:** Inputs blank, BtnPrimary fully interactive (correction from spec: CTA never hard-blocks). Progress 0%.
* **Skeleton:** SolidCard contains `SkeletonState` shimmer blocks for inputs. CIA card has shimmer for text.
* **Empty:** Native state. The absence of data yields a neutral, welcoming UI without error styling.
* **Error:** 
  * Validation: Hairline border under invalid field turns orange `#FF5E00`. Inline error text drops down (Caption size, paper-50% opacity).
  * System/Network: Top-mounted `OfflineBanner` (glass-pill) warning of lost connectivity or failure to save.
* **Success:** BtnPrimary flashes `--glow-done` (Forest Green) for 350ms. Brief success glow on CTA, then immediate stack push navigation to Consent [03c].
* **Disabled:** Only the `BtnPrimary` enters a disabled state (40% opacity) *during the loading/submitting phase*. Inputs remain editable.

# 10. Motion & interaction
* **Physical easing:** Standard physical easing `cubic-bezier(0.32, 0.72, 0, 1)`. Never linear.
* **Feedback:** Tapping inputs yields 150ms border depth scaling. Pressing CTA causes a micro-scale `.98`.
* **Glow behavior:** The `glow-cia` on the CIA card slowly breathes (4s ease). The success glow on CTA flashes 350ms.
* **Haptics:** Light `selectionChanged` feedback on native picker scroll. `success` notification haptic on valid submission.
* **Reduced-motion path:** All staggered fade-in/translation on screen mount and error slide-downs are instant (0ms). Glow breathing is static.
