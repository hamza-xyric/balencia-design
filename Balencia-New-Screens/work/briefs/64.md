# Functional Content Brief: Report / Block Modal

## 1. Purpose
Provides a low-friction, safety-oriented flow for users to report harmful content and simultaneously block the offending user. It captures moderation context at the exact moment harm is encountered, balancing thoroughness with a calm, non-shaming user experience. 

## 2. Entry & Exit Paths
**Entry Paths (Modal Bottom Sheet):**
*   **Community Chat [40]:** Message long-press → "report"
*   **Competitions [47]:** Participant options overflow → "report"
*   **Recipes [56]:** Recipe card overflow → "report"
*   *Requirement:* Entry is blocked if the user is rate-limited or if no entity context is passed.

**Exit Paths:**
*   **Success:** Auto-dismisses 1.5s after submission confirmation → returns to source screen.
*   **User Cancellation:** Tapping "cancel", drag-down/swipe-down on the sheet, or tapping the dimmed backdrop.

## 3. Complete Information Architecture
**Z-39 Backdrop:** Dimmed background blocking interaction with the source screen.
**Z-40 Sheet Container:** 
1.  **Drag Handle:** Top-center visual affordance for dismiss gestures.
2.  **Sheet Header:** "cancel" (left), "report" (center title).
3.  **Reported Entity Card:** Context anchor confirming who/what is being reported.
4.  **Section Eyebrow:** "WHY ARE YOU REPORTING THIS?"
5.  **Report Reason List (Focal Point):** Single-select list of 6 categorization options.
6.  **Description Field:** Textarea for free-form context (revealed/calculated for keyboard space when "other" is selected).
7.  **Block Toggle Row:** Opt-in switch to block the user.
8.  **Submit Button:** Action anchor; disabled until a reason is selected.
9.  **Success Checkmark:** Replaces sheet content upon successful submission.

## 4. Features & Capabilities
*   **Contextual Entity Tracking:** Automatically pulls the user ID, content ID, content type, and source screen to attach to the report payload.
*   **Categorized Moderation Routing:** 6 distinct radio buttons for accurate, low-friction triage.
*   **Variable Text Context:** Optional textarea (500 char limit). Auto-focuses and opens the keyboard specifically when "other" is chosen, but remains accessible for all other reasons.
*   **Frictionless Blocking:** Co-located toggle allowing the user to block a user simultaneously without navigating to their profile.
*   **Offline Queuing:** If offline, the sheet allows submission, queuing it locally to send when connection is restored.
*   **Duplicate Report Updating:** Detects if a user is re-reporting the same content and updates the existing report rather than generating a duplicate.
*   **Defensive Validation:** Prevents empty submissions (button disabled), enforces character limits visually, and includes rate-limiting protections.

## 6. Data Fields & Metrics
*   **Reported Entity (User ID / Content ID / Content Type):** *Source: Passed dynamically via context object from triggering screen.*
*   **Source Screen Identifier:** *Source: Passed dynamically via context object.*
*   **Report Reason:** *Source: User selection (static list of 6).*
*   **Description Details:** *Source: User text input.*
*   **Block State:** *Source: Local UI state (Boolean).*
*   **Character Counter (0/500):** *Source: System calculation of text input length.*

## 7. Screen States
*   **Default Initial:** Form visible; submit button disabled; block toggle defaults to OFF.
*   **Reason Selected:** Radio button filled; submit button enabled.
*   **Description Field Active:** Keyboard visible; border focused.
*   **Character Warning:** Input reaches 480-500 chars. Counter transitions to error state.
*   **Loading / Submitting:** Submit button text hidden, replaced by an indeterminate spinner.
*   **Submission Error:** Form remains; submit button shakes horizontally; error text appears below.
*   **Rate Limited:** Sheet aborts presentation; source screen displays a partnership-framed toast.
*   **Offline:** Sheet remains interactive; offline banner displayed; submission queues locally.
*   **Defensive - Deleted User/Content:** Sheet presents normally; entity card swapped for generic placeholder + contextual reassurance text.
*   **Duplicate Report:** Submit button text changes to "update report".
*   **Success:** Checkmark icon scales in; confirmation text displayed; auto-dismisses after 1.5 seconds.

## 8. Interactions, Gestures & Motion
*   **Sheet Presentation:** Backdrop fades in; sheet slides up from bottom. Internal modules cascade in with a subtle fade and upward translate.
*   **Radio Selection:** Tapping a reason animates a filled inner circle scaling in (0 to 1.0). Previous selection animates out. Label weight promotes.
*   **Toggle Activation:** Tapping the row or switch slides the thumb left/right. Track background crossfades. If toggled ON, sub-label text fades and expands in height. 
*   **Submit Failure Shake:** On error, the submit button executes a high-frequency horizontal rattle animation.
*   **Success Auto-Dismiss:** Checkmark scales in with a slight bounce overshoot; text fades in; after 1.5s, the entire sheet slides down off-screen as the background backdrop fades simultaneously.
*   **Gestures:** Tap backdrop/swipe down/drag handle to dismiss. Tap outside text areas to close keyboard.

## 9. Free vs Premium Gating
*   **Not Applicable:** As a critical safety and moderation utility, all reporting, blocking, and rate-limiting mechanisms are identical regardless of a user's subscription tier. 

## 10. Cross-Domain Hooks
*   **Not Applicable:** Intentionally omitting cross-domain hooks (e.g., CIA insights, habit correlations, AI life-area suggestions). This screen represents a localized utility modal designed to reduce friction during sensitive moderation flows. Injecting unrelated data surfaces here would erode user trust and distract from the primary safety action.

## *Flagged Source Contradiction*
> **CONTRADICTION RESOLVED (Block Toggle Default):** The source text initially implies the block toggle co-location is designed to heavily pair the actions ("users who report almost always want to stop seeing..."). However, later audit integration sections strictly mandate that the block toggle must default to **OFF** to preserve explicit user consent (opt-in). This brief honors the **Audit Decision (OFF)** as the overriding source of truth.
