## Screen contracts

Common pattern for every screen:
```tsx
const { data, status, refetch } = useX();
if (status === 'pending') return <BalenciaScreen ...><SkeletonState variant="card" /></BalenciaScreen>;
if (status === 'error')   return <BalenciaScreen ...><ErrorState message="Couldn't load … " onRetry={refetch} /></BalenciaScreen>;
// success: render VM; each Metric renders value OR HonestNullState/'—' + ProvenanceChip per its provenance
```
NEVER substitute fixture data on error. `data.source` badges ('api'/'demo') die with use-pilot-data.

**Today** (`useOverview` → `TodayVM`): hero = Life Power — `lifePower.value` number + label when real, `HonestNullState title="Life Power isn't calibrated yet" detail="Track a few days and Cia will map it."` when null-kind. Pulse card: 3 metrics (energy/recovery/stress) each showing `metric.display` + `ProvenanceChip`; respect `hasWearable:false` (those metrics arrive null-kind — render them as such, no zeros). Daily brief card only when `headline` non-null. Priorities list (max 3). Momentum row: streak/xp/level via `Metric.display`. Coach prompts → quiet chips (purple accents allowed here ONLY on Cia-related prompt chips). Keep existing layout skeleton/visual structure where feasible — this is a rewiring batch, not a redesign.

**Missions** (`useMissions` → `MissionsVM`): tier colors — life=gold `#D4A017`-ish existing token if present else `BalenciaColors.orange`, main=silver `#B9BCC4`, side=bronze `#B08D57` (if the current screen already has a tier-color map, keep it but re-key to `life|main|side`). Status chips active/blocked/complete. Empty → `HonestNullState title="No missions yet" detail="Create your first mission with Cia."`. Summary row from `summary` (real counts).

**Life Areas** (`useLifeAreas` → `LifeAreasVM`): list areas with `score` Metric (display + ProvenanceChip), checkin streak (real number), `averageMomentum` header Metric. NO trend arrows, NO drivers (server has none — render nothing rather than inventing). Empty → `HonestNullState title="No life areas yet"`.

**Fitness** (`useFitness` → `FitnessVM`): `planCount` + `activePlan` card (name, week X of Y, workouts/week, completionRate Metric) when present; score/recovery/weeklyMinutes render as honest-null metric tiles ('—' + null-kind chip). Empty plans → `HonestNullState title="No workout plans yet"`.
