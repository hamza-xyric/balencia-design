# FUNCTIONAL CONTENT BRIEF: Notification Permission

## 1. Purpose
To dramatically improve iOS push notification opt-in rates by using a pre-permission interstitial. It frames the request around concrete benefits and provides a "soft exit" so users who aren't ready don't permanently burn the one-shot iOS system prompt. 

## 2. Entry and Exit Paths
**Entry Paths:**
*   **First Launch (Stack Push):** CIA Onboarding [07] / Initial Plan Summary [08] → Notification Permission [66].
*   **Re-entry (Modal Slide-up):** Triggered contextually from Settings [21], Accountability Partners [46], or Reminders [61] when a feature requires notifications but access is undetermined or denied.

**Exit Paths:**
*   **Allow:** Taps CTA → Allows in OS dialog → Auto-dismisses → Navigates to Home [12] or requesting screen.
*   **Deny (System):** Taps CTA → Denies in OS dialog → Brief acknowledgment → Navigates to Home [12] or requesting screen.
*   **Skip:** Taps "Not now" → Dismisses immediately without triggering OS dialog → Navigates to Home [12] or requesting screen.

## 3. Information Architecture
**Layout Behavior:** Fixed, single viewport. No scrolling. 
**Regions (Top-to-Bottom):**
1.  **Status Bar Zone:** System status bar area.
2.  **Top Spacer:** Fixed vertical breathing room to center content (compresses slightly on smaller screens like iPhone SE).
3.  **Illustration Area:** Visual anchor containing the bell and floating notification chips.
4.  **Title Block:** 3-word value proposition.
5.  **Subtitle Block:** Contextual explanation of the request.
6.  **Benefits Block:** Three rows of feature-specific reasons to enable notifications.
7.  **Flexible Spacer:** Pushes the bottom actions to the thumb zone.
8.  **Primary Action Zone:** Full-width CTA button.
9.  **Secondary Action Zone:** Skip text link.
10. **Bottom Padding:** System safe area for home indicator.

## 4. Features & Capabilities
*   **Pre-Permission Priming:** Intercepts the user before triggering the irreversible native OS dialog.
*   **System Dialog Trigger:** Directly calls `UNUserNotificationCenter.requestAuthorization` (iOS) or `PermissionsAndroid.request` (Android) upon CTA tap.
*   **Prompt Preservation (Skip):** Bypasses the OS system dialog entirely if the user taps "Not now", preserving the one-shot OS prompt for a future session.
*   **Deep-Link Fallback:** If OS permission is already permanently denied, the screen acts as a gateway, deep-linking the user directly to the Balencia settings page in the native OS Settings app.
*   **Contextual Subtitles:** Adapts the subtitle copy if presented from the Accountability Partners screen (e.g., noting the partner is waiting).
*   **State Re-checking (Modal):** If deep-linked to OS settings, the app re-evaluates permission status upon user return, auto-dismissing the modal if access was successfully granted.

## 6. Data Fields & Metrics
*   **Notification Permission Status:** OS-level state (`.notDetermined`, `.authorized`, `.denied`). *Source: Native OS APIs.*
*   **`notification_prepermission_skipped` (Boolean):** Tracks if the user bypassed via "Not now". *Source: App User Preferences.*
*   **`notification_prepermission_skipped_at` (Timestamp):** Time of skip. *Source: App User Preferences.*
*   **`notification_system_denied` (Boolean):** Tracks if the user hard-denied the OS prompt. *Source: App User Preferences.*
*   **`notification_system_denied_at` (Timestamp):** Time of hard-deny. *Source: App User Preferences.*

## 7. Screen States
*   **Standard (First Launch / `.notDetermined`):** Full visual content, CTA reads "Enable Notifications".
*   **Loading:** Illustration ghosts to 40% opacity, benefit text becomes skeleton shimmer, CTA shows spinner, loading copy visible.
*   **Success (Already Granted / Edge Case):** CTA crossfades to green fill with a checkmark, success copy visible.
*   **System Denied (Hard Blocked):** CTA text changes to "Got it" briefly, dims to 40% opacity, then screen transitions out. (Re-entry variant changes CTA to "Open Settings").
*   **Error (System Dialog Unavailable):** CTA reverts to Default state, inline error copy visible below CTA. No red borders/errors.
*   **Offline:** CTA dimmed to 50% opacity, no CTA glow pulse, offline copy banner visible below subtitle.

## 8. Interactions, Gestures & Motion Intents
*   **Tap (CTA):** Triggers medium haptic. Prepares system dialog. If successful/denied, provides success/neutral UI feedback and exits.
*   **Tap ("Not now"):** Triggers light haptic. Dismisses screen immediately without OS prompt. 
*   **Swipe Right (Edge):** Blocked during first-launch onboarding (cannot go backward).
*   **Swipe Down:** Dismisses modal *only* on re-entry context (behaves like "Not now"). Disabled on first launch.
*   **Motion Intents:** 
    *   *Entrance:* Staggered fade-in and slide-up for content blocks over ~1.1 seconds. Bell illustration springs in, followed by floating chips (staggered), then text rows sliding from left.
    *   *Idle:* Gentle, continuous bell swaying. Notification chips float continuously. CTA maintains a subtle, calm, continuous warm-glow pulse.
    *   *Reduced Motion:* Disables all entrance, idle, and pulse animations. Elements appear instantly in their final positions. Static glow remains.

## 9. Free vs Premium Gating
*   **Applicability:** None. This is an infrastructure-level screen shown to all users regardless of subscription tier.

## 10. Cross-Domain Hooks
*   **CIA (AI Coach):** Directly promoted in Benefit Row 1 and default subtitle. Tied to the AI persona persona domain.
*   **Gamification / Streaks:** Promoted in Benefit Row 2. Tied to the habit-building/streak-loss-aversion domain.
*   **Accountability / Social:** Promoted in Benefit Row 3. Tied to the partner-dependency domain.
