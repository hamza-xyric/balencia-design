Here is the functional content brief for the Force Update screen, with all CIA renames applied and visual styling stripped.

### 1. Purpose
Enforces a mandatory app version floor to ensure backend API compatibility, critical security patching, and App Store/Google Play compliance. It functions as a calm, non-punitive, brand-forward system gate that completely blocks app usage until the user successfully updates.

### 2. Entry and Exit Paths
*   **Entry Paths (System-Triggered):**
    *   *Cold Start:* Local version check against the config endpoint returns `force_update: true`.
    *   *Mid-Session:* Any authenticated API request returns a `version_deprecated` flag/header, injecting this screen as a full-screen overlay (z-index above all navigation and modals). 
*   **Exit Paths:**
    *   *Success:* Tapping "Update Now" opens the external App Store/Play Store to the Balencia listing. After updating, the user relaunches the app, bypassing this screen.
    *   *No Secondary Exit:* The screen cannot be dismissed, bypassed, or navigated away from within the app. 

### 3. Information Architecture
The layout fits a single, fixed, non-scrolling viewport. Elements stack top-to-bottom:
1.  **Status Bar Zone:** System status area.
2.  **Top Spacer:** Breathing room.
3.  **Balencia Wordmark:** Brand trust anchor.
4.  **App Icon Cluster:** App icon combined with an overlapping Update Arrow Badge signifier.
5.  **Update Message Block:** Title and subtitle explaining the situation.
6.  **What's New Section:** Optional server-driven motivational preview card.
7.  **Flexible Spacer:** Pushes the CTA to the bottom thumb-reach zone.
8.  **CTA & Version Info:** Full-width action button followed by technical version metadata.
9.  **Home Indicator Zone:** System safe area.

### 4. Features and Capabilities
*   **Mandatory App Blockade:** Hard-blocks all background app processes and navigation until resolved.
*   **External Store Handoff:** Deep-links the user directly to the correct mobile storefront (iOS App Store or Google Play Store) for the Balencia app.
*   **Update Motivation/Preview:** Dynamically displays 2-3 new features or improvements to incentivize the user to update.
*   **Resilient Fallback Loading:** If triggered offline or via a stale cache, the screen still renders (without the "What's New" data) using cached version requirements.
*   **Accessibility Parsing:** Full VoiceOver/TalkBack screen reading integration.
*   **Android Hardware Back Override:** Consumes Android hardware back button presses to prevent dismissal, showing a supportive toast on repeated attempts.

### 6. Data Fields and Metrics
*   **App Version (Current):** The user's installed build version. *(Source: Local app build config)*
*   **Required Version (Minimum):** The lowest acceptable app build. *(Source: Config endpoint or API response)*
*   **What's New Items:** 2-3 feature strings previewing the update. *(Source: Server-driven array)*
*   **Override Strings:** Contextual title/subtitles (e.g., security vs. major release). *(Source: Server-driven config)*
*   **Store URL:** Dynamic deep link to the platform store. *(Source: Hardcoded platform URL schemes: `itms-apps://` or `market://details?id=`)*

### 7. Screen States
*   **Cold-Start / Day-1:** Renders immediately in default state. Never blank or skeleton for text/icon/badge. 
*   **Empty / Partial:** "What's New" section collapses entirely (0pt height, no placeholder) when server provides no items. All other text renders normally.
*   **Loading:** 
    *   *Fetch Loading:* "What's New" card shows subtle shimmer placeholders while fetching.
    *   *Deep-Link Loading:* CTA shows a spinner and a toast reading "Opening the store."
*   **Error:** CTA text temporarily changes to "Try Again". Error toast appears above the button. No red color is used (error is environmental).
*   **Offline:** Screen renders normally. Optional offline banner appears at the top. CTA remains tappable but will trigger the Error state if the store is unreachable.
*   **Success:** App backgrounds when the store successfully opens. If the user returns without updating, CTA resets to default.
*   **Contradiction Flag:** The base spec details a "8-State Interaction Model" strictly for the button. The Premium Craft section explicitly supersedes this with a screen-level state model (Cold-start, Empty, Loading, Error, Offline). The screen-level model is the source of truth.

### 8. Interactions, Gestures, and Motion Intents
*   **Tap (CTA):** Triggers medium haptic impact. Resolves and opens external store deep link. On failure, triggers an error haptic (triple pulse) and shows Error state.
*   **Tap (Outside CTA):** Inert, no action.
*   **Swipe Down / Swipe Right (Edge):** Blocked. Pull-to-dismiss and iOS back-gesture are explicitly disabled.
*   **Hardware Back (Android):** Blocked. Event is consumed. A second press within 2 seconds triggers a supportive toast.
*   **Motion Intent (Entrance):** Choreographed staggered fade-ins. Screen fades in, followed by wordmark, icon scale-in, badge spring-in, and text cascade (~1.0s total). 
*   **Motion Intent (Persistent):** The CTA maintains a subtle, infinite sinusoidal glow pulse to draw the user's eye to the sole available action.
*   **Motion Intent (Reduced Motion):** Entrance animations and persistent pulses are instantly neutralized to static, fully-visible elements.
