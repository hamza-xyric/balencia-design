# FUNCTIONAL CONTENT BRIEF: WhatsApp Enrollment (Screen 03e)

## 1. Purpose
The WhatsApp Enrollment screen is the optional, skippable bridge between user consent and onboarding. It verifies the user's phone number to activate a proactive WhatsApp coaching channel (reminders, check-ins, tips) driven by the CIA persona.

## 2. Entry and Exit Paths
*   **Entry Paths**: Stack push from Consent screen [03c] (user toggled WhatsApp coaching on).
*   **Primary Exit**: Stack push to CIA Onboarding Conversation [07] (Phone successfully verified).
*   **Secondary Exit**: Stack push to CIA Onboarding Conversation [07] (User taps "skip" — WhatsApp not configured).
*   *Note on Persona*: All references to the coaching persona (SIA/S.I.A.) in the source have been mapped to **CIA**.

## 3. Complete Information Architecture
The screen is a single-view, two-phase flow with no scrolling (fits all device sizes including iPhone SE). No tab bar is visible.

**Phase 1: Phone Entry**
1.  **Top Action Row**: Skip link (right-aligned).
2.  **Brand Anchor**: Balencia symbol (centered, remains static across both phases).
3.  **Value Proposition Copy**: Heading and Subtitle explaining the benefit.
4.  **Opt-out & Privacy Reassurance**: Context setting user expectations for messaging frequency and how to opt out.
5.  **Phone Input Group (Primary Focus)****: Country code picker (left) and Phone number text field (right).
6.  **Primary CTA**: Submit button.
7.  **Value Preview List**: Bulleted breakdown of coaching features.

**Phase 2: SMS Verification**
1.  **Top Action Row**: Back chevron (left) + Skip link (right).
2.  **Brand Anchor**: Balencia symbol (centered, unchanged).
3.  **Instructional Copy**: Heading and Subtitle (displaying the masked phone number).
4.  **SMS Code Input Group (Primary Focus)**: 6 individual digit boxes.
5.  **Resend Mechanism**: Circular visual progress indicator paired with text link.
6.  **Primary CTA**: Verify button.

## 4. Features and Capabilities
*   **Optional Enrollment**: Users can bypass the screen entirely without losing progress.
*   **Country Code Selection**: Auto-detects locale, provides searchable list of dialing codes.
*   **Phone Validation**: Validates input before triggering SMS.
*   **SMS Code Auto-Management**: Auto-advances to next box on digit entry, backspaces to previous box, supports pasting a 6-digit string.
*   **Resend Cooldown**: Enforces a 60-second wait period between SMS requests, visualized via a circular progress indicator.
*   **Keyboard Handling**: Phase 1 raises a phone-pad; Phase 2 raises a number-pad.
*   **Fraud/Spam Prevention**: Disables inputs and enforces a 5-minute cooldown after too many failed verification attempts.

## 6. Data Fields and Metrics
| Field / Metric | Source / Trigger | Notes |
| :--- | :--- | :--- |
| **Phone Number** | User Input | Validated locally and via API. Retained in Phase 1 field if Phase 2 SMS send fails. |
| **Country Code** | Device Locale / User Select | Defaults to +1 (US) if locale detection fails. |
| **SMS 6-Digit Code** | User Input | Validated against backend. |
| **Masked Phone Display** | System (Phase 1 input) | Displays country code and last 4 digits (e.g., +1 *** *** 4567). |
| **Resend Countdown** | System Timer | 60-second countdown. |
| **Attempt Cooldown** | System Timer | 5-minute cooldown triggered by repeated code failures. |

## 7. Screen States
*   **Day 1 / Cold-start**: Phase 1, empty phone input, country code auto-detected, CTA disabled.
*   **Focused**: Input borders highlight; keyboard raised.
*   **Disabled (CTA)**: 40% opacity until valid phone (P1) or 6 digits (P2) are present.
*   **Loading (Send)**: CTA shows spinner; overlay copy: "Sending your code — one moment."
*   **Loading (Verify)**: CTA shows spinner, SMS boxes show skeleton shimmer; overlay copy: "Verifying your code — one moment."
*   **Error (Input)**: Red borders on inputs; shake animation (3 oscillations) for wrong SMS code; inputs clear and reset focus.
*   **Error (Network/Spam)**: Toast banners at top of screen; total lockdown for 5-minute spam penalty.
*   **Success**: Green glow flash on CTA, followed by immediate navigation to [07].

## 8. Interactions, Gestures, and Motion
*   **Taps**: Select inputs, trigger APIs (send/verify), skip flow.
*   **Typing**: Auto-advance digits; backspace clears previous box; paste auto-populates remaining boxes.
*   **Edge Swipe (iOS)**: Swiping right in Phase 2 triggers a crossfade back to Phase 1. Swiping right in Phase 1 does nothing (must use Skip).
*   **Motion / Transitions**: 
    *   Phase 1 -> Phase 2 is a single-screen content **crossfade** (not a page navigation).
    *   Balencia symbol remains completely static during the crossfade to anchor the user visually.
    *   Reduced Motion accessibility setting: Crossfades and animations become instant swaps, disabling the circular countdown ring and relying solely on text.

## 9. Free vs. Premium Gating
*   **Not Applicable**: This is a pre-authentication, pre-motivation onboarding screen. No premium features or motivation tiers are evaluated or established here. WhatsApp enrollment is standard for all users who opt in.

## 10. Cross-Domain Hooks
*   **Not Applicable**: Because this is a pre-auth utility screen, there are no AI insights, life-area correlations, or health chart hooks displayed. The only future hook is the mention that users can manage this setting later in the "Settings" area.
