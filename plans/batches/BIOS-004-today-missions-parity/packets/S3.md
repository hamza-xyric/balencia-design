# Packet S3 — Mission detail (hi-fi S14) with ALL FIVE accordions (amendment A1 — binding)

## Objective

Build the mission-detail screen (hi-fi spec 14-goal-detail, canon-governed by
`COMPACT-CANON.md`/`COMPONENT-CATALOG.md`) as a root `Stack.Screen` push at
`/mission/[id]`. This is the **detail** surface for a single `MissionVM` drawn
from the already-landed `useMissions()` query (ADR-3: no new adapter/query —
reuse the existing missions list, select by id). It implements:

- ADR-1/ADR-2 viz composition (`ProgressRing` hero, `GlassStatCard` KPI row,
  `TrendChart` inside the Progress accordion) — every metric renders through
  the honesty-typed `Metric<T>` contract, never a bare number.
- ADR-4 complete surface: `useCompleteMission()` for `source: 'life'|'health'`
  only; career/finance render an honestly-disabled control (no server
  complete endpoint exists for those sources — `scope-server-missions.md` §1.4/1.5).
- ADR-4 XP honesty: **no XP is ever predicted**. A confirmed positive
  `xpDelta` navigates to `/celebration`; a `null` delta (the common case —
  life/health XP is usually an async ≤15-minute achievement job) stays
  in-place with an honest "confirms later" line, never a fabricated toast.
- **A1 (Fable acceptance amendment, architecture-plan.md §11):** ALL FIVE
  accordions render this batch. "All actions" and "Progress" are data-backed
  (using the ONLY real signals the unified goal VM carries — see
  `scope-server-missions.md` §3: no action list, no milestone list, no
  progress-history series exist server-side). "Milestones" is honest-null
  (canon §8 "No milestones yet" — never invented checkpoints). "Cia
  reasoning" and "Cross-domain links" render **visible-but-gated** with
  provenance copy (those lanes ship in BIOS-005/006) — visible, honest, never
  silently dropped.

```ts
import { useQuery } from '@tanstack/react-query';

import { apiFetch } from '@/services/api/client';
import type { UnifiedGoalsResponseDto } from '@/services/api/dto/goals';
import { queryKeys } from '@/services/query/keys';

export function useMissions() {
  const { status } = useSession();

  return useQuery({
    queryKey: queryKeys.missions(),
    queryFn: () => apiFetch<UnifiedGoalsResponseDto>('/v1/goals/unified'),
    enabled: status === 'authenticated' || status === 'refreshing',
    staleTime: 60_000, // 1 minute
    select: toMissionsView,
  });
}
```

```ts
import { apiFetch } from '@/services/api/client';
import { ApiError } from '@/services/api/errors';
import { createLifeMission, completeLifeMission, completeHealthMission } from '@/services/api/missions';
import type {
  CreateLifeGoalRequestDto,
  LifeGoalResponseDto,
  LifeGoalDto,
  HealthGoalDto,
  UnifiedGoalsResponseDto,
  UnifiedGoalDto,
} from '@/services/api/dto/goals';
import type { GamificationStatsResponseDto } from '@/services/api/dto/gamification';
import { queryKeys } from '@/services/query/keys';

export type CreateMissionInput = CreateLifeGoalRequestDto;

export type CompleteMissionInput = {
  id: string;
  /** Only life+health have a wired complete surface this batch (ADR-4). */
  source: 'life' | 'health';
};

export type CompleteMissionResult = {
  goal: LifeGoalDto | HealthGoalDto;
  /**
   * Confirmed POSITIVE XP delta only, or `null`. `null` covers: no
   * pre-complete gamification snapshot was cached yet, the refetched total
   * is unchanged (the common case — life/health XP is usually an async
   * ≤15-min achievement job, ADR-4), or (defensively) a non-positive delta.
   * Never fabricated — a caller (S42 celebration, this packet) must only
   * render a reward state when this is a positive number.
   */
  xpDelta: number | null;
};

// ...createLifeMission/useCreateMission unchanged, not used by this packet...

export function useCompleteMission() {
  const queryClient = useQueryClient();

  return useMutation<CompleteMissionResult, ApiError, CompleteMissionInput, { previousData?: UnifiedGoalsResponseDto }>({
    mutationFn: async (input) => { /* calls completeLifeMission/completeHealthMission, diffs gamification stats, returns { goal, xpDelta } */ },
    onMutate: async (input) => { /* optimistic status→'completed'/progress→100 flip + snapshot */ },
    onError: (_error, _input, context) => { /* rollback from context.previousData */ },
    onSettled: () => {
      queryClient.invalidateQueries({ queryKey: queryKeys.missions() });
      queryClient.invalidateQueries({ queryKey: queryKeys.gamification() });
    },
  });
}
```

`useCompleteMission()` returns a standard TanStack `UseMutationResult`. Optimistic
update, rollback, and cache invalidation are **already fully handled inside
this hook** — this packet's screen only needs to call
`.mutate(input, { onSuccess, onError })` with **per-call** callbacks (TanStack
Query calls both the hook-level and the call-level callbacks; this is
supported, standard API — do not modify `use-mission-mutations.ts` to add an
`onSuccess` there). `mutation.isPending` drives the button's pending copy.

```ts
export type Metric<T = number> = {
  value: T | null;
  display: string;
  provenance: Provenance;

export function realMetric<T>(
  value: T,
```

## Design requirements

**Section order (top to bottom), matching architecture-plan.md §4.3 + scope-hifi S14 + amendment A1:**

1. **Chrome** — a row containing: a 44×44 `Pressable` back control
   (`accessibilityRole="button"`, `accessibilityLabel="Back"`, calls
   `router.back()`, renders the `chevron.left`/`arrow_back` `SymbolView` at
   `tintColor={BalenciaColors.paper100}`), and — only once `mission` has
   resolved — a tier-metal badge (a small local, non-exported `TierBadge`
   subcomponent: `borderColor`/`text color` = `MissionMetalColors[mission.tier].solid`,
   `backgroundColor` = `...soft`, label from a local `TIER_LABEL` map using
   **Title Case** — `'Life Mission'`, `'Main Mission'`, `'Side Mission'`,
   `'Weekly Mission'`, `'Daily Mission'`, `'Group Mission'` — matching the
   already-landed interim tier labels in `src/features/missions/missions-screen.tsx`).
   This row renders in every state (loading/error/loaded) — the back control
   must always be reachable, never trapped behind a loading/error view.
2. **Hero** — `ProgressRing` (`size={120}`, `stroke={8}`,
   `centerLabel={\`${Math.round(mission.progress)}%\`}`, `glow={mission.status === 'complete' ? 'done' : 'you'}`,
   default `animateOnMount` — do not pass `state`), then the mission title as
   a Display-style `Text` (`fontSize: 34, fontWeight: '800'`, centered), then
   a row of exactly 2 `ChipDomainTag`s (domain label Title-Cased from
   `mission.domain`; source label from a local `SOURCE_LABEL` map:
   `health→'Health', life→'Life', career→'Career', finance→'Finance'` — both
   non-interactive, no `onPress`), then — only `mission.dueDate ? ... : null`
   — a due-date line reading `` `Due ${mission.dueDate.slice(0, 10)}` `` (no
   `Intl`/`Date` formatting — the ISO date's calendar-date substring only;
   omit the line entirely, do not render a placeholder, when `dueDate` is `null`).
3. **KPI row** — 3× `GlassStatCard`, each wrapped in its own `flex:1` `View`,
   each `glow="you"`:
   - **Progress**: `realMetric(mission.progress, { source: 'server', label: 'system calculated', format: (v) => \`${Math.round(v)}%\` })`.
   - **Target**: `mission.target ? realMetric(\`${mission.target.current}/${mission.target.target} ${mission.target.unit}\`, { source: 'server', label: 'system calculated' }) : nullMetric<string>('No target set for this mission')`.
   - **XP**: `xpKpi(mission)` from the logic file (always honest-null this
     batch — see Contracts above; **never** compute or display a predicted
     number here).
4. **CIAInsightCard** — `headline={null}`, `gated={{ reason: 'Cia reasoning arrives with the coach lane' }}`
   (exact string, no trailing period — copy this literally).
5. **Error toast** (conditionally rendered, only when a complete attempt just
   failed) — `<ToastBanner message={completeError} tone="error" onDismiss={...} />`,
   placed directly above the ActionCheckCard.
6. **ActionCheckCard** (local, non-exported subcomponent) — see below.
7. **Five `ExpandableSection` accordions, in this exact order:**
   - **"All actions"** — data-backed. Body: a single row rendering
     `mission.title` with an open-circle (`○`) or check (`✓`) glyph matching
     `mission.status === 'complete'`, plus a caption line reading exactly
     `Multiple actions arrive with the domain lanes` (no fabricated
     multi-item list — `scope-server-missions.md` §3 confirms the unified
     goal VM has no action list).
   - **"Progress"** — data-backed. Body: `<TrendChart points={progressPoints(mission)} state="real" height={120} />`
     (renders as a single dot per the `<3 points` rule — never a fabricated
     line) plus a caption line reading exactly
     `One reading available — trend history isn't tracked yet`.
   - **"Milestones"** — always `<HonestNullState title="No milestones yet" />`
     (no server milestone data exists for any source this batch — do not
     invent a milestones list).
   - **"Cia reasoning"** — `gated={{ reason: 'Cia reasoning arrives with the coach lane' }}`,
     no children (same exact reason string as the standalone `CIAInsightCard`
     in section 4 — both surfaces are honestly gated for the same reason).
   - **"Cross-domain links"** — `gated={{ reason: 'Cross-domain links arrive with the life areas lane' }}`,
     no children.

**ActionCheckCard (local subcomponent) exact behavior:**
- Reads `canComplete(mission)` to decide the button's `disabled` state and
  the subcopy line.
- **If `mission.status === 'complete'`:** render the done state — check
  glyph, green-tinted card (`BalenciaColors.greenSoft` background,
  `rgba(52, 168, 83, 0.32)` border — the same green-glow recipe
  `glass-stat-card.tsx`'s `glowDone` style uses), and a subcopy line: if the
  completion just happened in THIS session with a `null` xpDelta (tracked via
  local `justCompletedNoXp` state, set `true` in the mutation's `onSuccess`
  when `result.xpDelta` is not a positive number), show exactly
  `XP confirms within about 15 minutes`; otherwise show `Mission complete`
  (a mission that was already complete before this screen ever mounted —
  never claim a specific confirmation window for something that may have
  already resolved).
- **Else (not complete):** render the open-circle glyph, the mission title,
  a subcopy line (`Tap mark complete when you finish this` when
  `canComplete(mission).allowed`, otherwise `canComplete(mission).reason`
  verbatim), and exactly one `<BalenciaButton tone="primary" disabled={!canComplete(mission).allowed || completing}>`
  reading `Mark complete` (or `Marking complete...` while
  `completeMutation.isPending`). For career/finance missions this renders the
  button **disabled** with `canComplete`'s reason
  (`Completing this mission type arrives with its domain lane`) shown as the
  subcopy — never hidden, never silently omitted.
- `onPress` (only reachable when enabled): fire the haptic, clear any
  previous `completeError`, call `completeMutation.mutate({ id: mission.id, source: mission.source }, { onSuccess, onError })`
  — guard `mission.source !== 'life' && mission.source !== 'health'` with an
  early `return` first (this duplicates part of `canComplete`'s check but is
  required for TypeScript to narrow `mission.source` to the
  `CompleteMissionInput['source']` union at the call site — `canComplete`'s
  boolean return cannot narrow through an external function call).
  - `onSuccess(result)`: if `result.xpDelta !== null && result.xpDelta > 0`,
    `router.push({ pathname: '/celebration', params: { xpDelta: String(result.xpDelta), title: mission.title } } as Href)`
    and stop (no further local state change needed — the screen is being
    navigated away from). Otherwise, `setJustCompletedNoXp(true)` (the
    optimistic update inside `useCompleteMission` has already flipped
    `mission.status` to `'complete'` in the query cache by this point, so the
    component naturally re-renders into the done branch above).
  - `onError(error)`: `setCompleteError(error.message || "Couldn't mark this mission complete. Try again.")`.

**Loading / error / missing-mission states (rendered below the always-present Chrome row):**
- `status === 'pending'` → `<SkeletonState variant="hero" />`.
- `status === 'error'` → `<ErrorState message="Couldn't load your missions." onRetry={refetch} />`.
- `status !== 'pending' && status !== 'error' && !mission` (deep link / stale
  cache / bad id) → `<ErrorState message="This mission isn't available." onRetry={refetch} />`.
  **Never render an indefinite skeleton for this case** — a missing mission
  must resolve to the ErrorState + retry, not silently spin.
- Otherwise → the full body (sections 2–7 above).

**Color roles (60/30/10):** orange (`glow="you"`) is the default tone for the
hero ring pre-completion and all three KPI cards (this is the user's own
mission — "effort/streak/active metric" per canon). Green (`glow="done"`)
appears only once status flips to `'complete'` (hero ring + ActionCheckCard).
Purple appears **only** on the two Cia-gated surfaces (`CIAInsightCard`,
the "Cia reasoning" accordion) — nowhere else on this screen. Tier-metal
colors (gold/silver/bronze/steel/sage) are their own separate accent, used
only on the chrome `TierBadge`.

**Honesty states — every metric, explicit:**
- Progress KPI: always **real** (`MissionVM.progress` defaults to `0`, never
  `null`, per the landed adapter).
- Target KPI: **real** when `mission.target` is present, **honest-null**
  (`'No target set for this mission'`) otherwise — never a placeholder number.
- XP KPI: **always honest-null** (`'XP confirms after completion'`) — the
  unified goal VM carries no XP field at all this batch; never compute, sum,
  or guess one.
- Progress accordion chart: **real**, single dot, never an invented
  multi-point history.
- Milestones accordion: **always honest-null** — no per-domain milestone
  fetch exists this batch (do not add one — out of scope, see below).
- Cia reasoning / Cross-domain links: **visible-but-gated**, not hidden.

**Provenance chips:** `GlassStatCard` renders its own `ProvenanceChip` from
each `Metric`'s `.provenance` automatically — no extra work needed from this
packet beyond passing honest `Metric` values.

**44px targets:** the back `Pressable` (44×44), the `BalenciaButton` (already
`minHeight: TouchTarget` internally), `ExpandableSection`'s header (already
handled internally by the component).

**a11y labels:** back button `accessibilityLabel="Back"`; the ActionCheckCard's
row exposes `accessibilityLabel={\`${mission.title}, ${isDone ? 'complete' : 'not complete'}\`}`
on its outer container (with the glyph/title `Text` children marked
`importantForAccessibility="no-hide-descendants"` on that same container, so
the label isn't read twice); the `BalenciaButton`'s own `accessibilityLabel="Mark complete"`.
`ProgressRing` and `ToastBanner` already carry their own accessibility props
internally — nothing extra needed from this packet for those two.

**Motion:** none added by this screen directly (see the `motion.ts` note in
Import surface above) — every animation on the page is already handled
inside `ProgressRing`, `TrendChart`, and `ExpandableSection`, each with its
own reduced-motion-safe internal implementation.
