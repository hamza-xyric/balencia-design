## Objective

composition-layer primitives every later BIOS-004 screen packet (4a Today, 4b Missions board, 4c
mission detail/create/celebration) depends on: **ChipDomainTag, SegmentedTabs, FABQuickLog,
CIAInsightCard, ExpandableSection, FrostCard**. This is packet **K1** in the wave sequence (the
architecture-plan.md §5 table's packets `1f`/new-kit-additions equivalent — the viz kit (ProgressRing,
TrendChart, GlassStatCard, CIAPresenceOrb, MomentumBar) and GlassNavBar have already landed per
`architecture-plan.md` ADR-1–ADR-5, ADR-10; this packet is the remaining shared-chrome layer those
screen packets compose against). Binding sources: architecture-plan.md §3 (component contracts —
this packet's six components extend that same contract discipline), §4 (composition maps — Today §4.1
references ChipDomainTag/FABQuickLog; Missions §4.2 references SegmentedTabs/ChipDomainTag; Mission
detail §4.3 references CIAInsightCard/ExpandableSection accordions per **A1**; Celebration §4.5
references FrostCard), and ADR-6 (shared motion constants — every animation in this packet is built
from `MotionDuration`/`MotionEasing`/`MotionSpring`/`MotionBreathe`, never a local magic number).

The six `declare function` signatures in the contract below (K1 CONTRACT) become real implementations.
Prop interfaces are **byte-identical** to that contract — do not add, rename, widen, or narrow a single

## Contracts (verbatim)

This is the exact, binding K1 contract. Copy these six interfaces/signatures into
`composition-kit.tsx` unchanged and implement each `declare function` as a real exported function
component with an identical prop type.

```ts
import type { ReactNode } from 'react';

export interface ChipDomainTagProps {
  label: string;                  // domain name, sentence case
  active?: boolean;               // selected: orange border + orange text; inactive: hairline + paper70
  onPress?: () => void;           // when provided, wraps in a >=44px pressable hit target
  testID?: string;
}
export declare function ChipDomainTag(props: ChipDomainTagProps): JSX.Element;

export interface SegmentedTabsOption<T extends string = string> { key: T; label: string }
export interface SegmentedTabsProps<T extends string = string> {
  options: SegmentedTabsOption<T>[];
  value: T;
  onChange: (key: T) => void;
  accessibilityLabel?: string;
  testID?: string;
}
export declare function SegmentedTabs<T extends string = string>(props: SegmentedTabsProps<T>): JSX.Element;
// pill track (inkBrown800), active segment = orangeSoft bg + orange text, 44px height, press feedback scale .96 (reduced-motion: no scale)

export interface FABQuickLogProps {
  onPress: () => void;
  accessibilityLabel: string;     // e.g. 'Create mission'
  testID?: string;
}
export declare function FABQuickLog(props: FABQuickLogProps): JSX.Element;
// 56px orange circle, plus glyph (paper100), absolute bottom-right, bottom offset clears GlassNavBar
// (BottomTabInset + safe area), press scale .96 + light haptic; reduced-motion: haptic yes, scale no.

export interface CIAInsightCardProps {
  headline: string | null;        // null => honest-null line ('Cia has no insight for this yet'), NEVER fabricated
  body?: string | null;
  gated?: { reason: string } | null; // visible-but-gated: lock glyph + reason copy, content area empty
  testID?: string;
}
export declare function CIAInsightCard(props: CIAInsightCardProps): JSX.Element;
// THE Cia surface: purple accents allowed HERE ONLY (purpleSoft glow border, purpleText label, mini CIAPresenceOrb 28px).

export interface ExpandableSectionProps {
  title: string;                  // rendered as overline-style section header
  subtitle?: string;
  initiallyOpen?: boolean;        // default false
  gated?: { reason: string } | null; // visible-but-gated: lock replaces chevron, body renders reason copy, not expandable
  children?: ReactNode;
  testID?: string;
}
export declare function ExpandableSection(props: ExpandableSectionProps): JSX.Element;
// accordion: open/close via withTiming(MotionDuration.accordion=200ms, Easing.bezier(...MotionEasing.physical)),
// chevron rotates 180deg; header is a >=44px pressable; reduced-motion: instant open/close, chevron still flips.

export interface FrostCardProps {
  glow?: 'done' | 'cia' | 'you';  // done=greenSoft, cia=purpleSoft (Cia surfaces only), you=orangeSoft
  breathe?: boolean;              // hero-only; default false; reduced-motion => static glow (no pulse)
  breatheConfig?: { durationMs: number; opacityMin: number; opacityMax: number }; // default MotionBreathe
  children: ReactNode;
  testID?: string;
}
export declare function FrostCard(props: FrostCardProps): JSX.Element;
// glass card variant with stronger surface + soft glow border of the given tone; breathe animates border/glow
// layer OPACITY only (transform/opacity rule).
```

**Composition note (not in the type signatures, binding on the implementation):** `CIAInsightCard`
MUST be built by composing this same file's `FrostCard` with `glow="cia"` and `breathe={false}` — do
not hand-roll a second purple-glass surface. This is the one and only place `FrostCard`'s `'cia'` glow
branch is exercised in this packet, and it is why `CIAInsightCard` needs no `breathe` prop of its own:
spec S42's Motion section is explicit that a screen's CIA glow "stays static/calm" while at most one
*other* hero card breathes ("two breathing glows would read busy") — so this component never breathes,
by design, regardless of which screen embeds it.

### `src/components/balencia/button.tsx` (FULL — `Pressable` press-feedback recipe: opacity .86 + scale .98)

```typescript
import type { ReactNode } from 'react';
import { Pressable, StyleSheet, Text, View } from 'react-native';

import { BalenciaColors, Radius, Spacing, TouchTarget } from '@/constants/theme';

type BalenciaButtonProps = {
  children: ReactNode;
  onPress?: () => void;
  tone?: 'primary' | 'secondary' | 'quiet' | 'danger';
  disabled?: boolean;
  accessibilityLabel?: string;
};

const toneStyles = {
  primary: {
    backgroundColor: BalenciaColors.orange,
    borderColor: BalenciaColors.orange,
    textColor: BalenciaColors.ink950,
  },
  secondary: {
    backgroundColor: BalenciaColors.inkBrown700,
    borderColor: BalenciaColors.hairlineStrong,
    textColor: BalenciaColors.paper100,
  },
  quiet: {
    backgroundColor: 'transparent',
    borderColor: BalenciaColors.hairline,
    textColor: BalenciaColors.paper70,
  },
  danger: {
    backgroundColor: 'rgba(255, 107, 107, 0.16)',
    borderColor: 'rgba(255, 107, 107, 0.32)',
    textColor: BalenciaColors.danger,
  },
};

export function BalenciaButton({
  children,
  onPress,
  tone = 'primary',
  disabled,
  accessibilityLabel,
}: BalenciaButtonProps) {
  const colors = toneStyles[tone];

  return (
    <Pressable
      accessibilityLabel={accessibilityLabel}
      accessibilityRole="button"
      disabled={disabled}
      onPress={onPress}
      style={({ pressed }) => [
        styles.button,
        {
          backgroundColor: colors.backgroundColor,
          borderColor: colors.borderColor,
          opacity: disabled ? 0.55 : pressed ? 0.86 : 1,
          transform: [{ scale: pressed && !disabled ? 0.98 : 1 }],
        },
      ]}>
      <View pointerEvents="none">
        <Text style={[styles.label, { color: colors.textColor }]}>{children}</Text>
      </View>
    </Pressable>
  );
}

const styles = StyleSheet.create({
  button: {
    minHeight: TouchTarget,
    borderWidth: 1,
    borderRadius: Radius.md,
    alignItems: 'center',
    justifyContent: 'center',
    paddingHorizontal: Spacing.three,
    paddingVertical: Spacing.two,
  },
  label: {
    fontSize: 15,
    fontWeight: '800',
    textAlign: 'center',
  },
});
```

`ChipDomainTag`'s press feedback (when `onPress` is provided) reuses this exact recipe — plain RN
`Pressable` function-style, `opacity: pressed ? 0.86 : 1` + `transform: [{ scale: pressed ? 0.98 : 1 }]`
— no Reanimated needed for that one component (no spec gives it a specific animated-duration press
state; `SegmentedTabs` and `FABQuickLog` DO use Reanimated because their contracts explicitly name
`scale .96` as a governed motion value — see Design requirements).
