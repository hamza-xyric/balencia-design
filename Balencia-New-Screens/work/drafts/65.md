- **Screen ID:** 65
- **Name:** 65-force-update

### 2. Purpose
Enforces a mandatory app version floor to ensure backend API compatibility, critical security patching, and App Store/Google Play compliance. It functions as a calm, non-punitive, brand-forward system gate that completely blocks app usage until the user successfully updates.

### 3. Entry & exit
- **Entry paths (System-Triggered):**
  - *Cold Start:* Local version check against the config endpoint returns `force_update: true`.
  - *Mid-Session:* Any authenticated API request returns a `version_deprecated` flag/header, injecting this screen as a full-screen overlay above all navigation and modals.
- **Exit paths:**
  - *Success:* Tapping "Update Now" opens the external App Store/Play Store to the Balencia listing. After updating, the user relaunches the app, bypassing this screen entirely. 
  - *No Secondary Exit:* The screen cannot be dismissed, bypassed, or navigated away from within the app.

### 4. Layout anatomy
The layout fits a single, fixed, non-scrolling viewport. Elements stack top-to-bottom:
1. **Status Bar Zone:** System status area.
2. **Top Spacer:** Breathing room.
3. **Balencia Wordmark:** Brand trust anchor.
4. **App Icon Cluster:** App icon combined with an overlapping Update Arrow Badge signifier.
5. **Update Message Block:** Title and subtitle explaining the situation.
6. **What's New Section:** Optional server-driven preview card.
7. **Flexible Spacer:** Pushes the CTA to the bottom thumb-reach zone.
8. **CTA & Version Info:** Full-width action button followed by technical version metadata.
9. **Home Indicator Zone:** System safe area.

### 8. Data & honesty states
Every metric ships three states (real, low-confidence, honest-null). Never a fabricated number.

**1. What's New Items (Server-driven array)**
- **Real:** Bullet list of features. `Provenance chip: "from the latest update"`.
- **Low-confidence:** N/A (Server strings are static, not quantitative metrics).
- **Honest-null:** Section collapses entirely to 0pt height. No placeholders are rendered.

**2. Version Metadata (Local vs Required Build)**
- **Real:** "v2.1.0 → v3.0.0 required". `Provenance chip: "local build config"`.
- **Low-confidence:** N/A (Local build numbers are absolute integers).
- **Honest-null:** "Update required" text fallback if the config endpoint fails to parse minimum version numbers before timing out.

### 9. All states
- **Cold-Start / Day-1:** Renders immediately in default state. Never blank or skeleton for text/icon/badge. 
- **Empty / Partial:** "What's New" section collapses entirely when the server provides no items. All other text renders normally.
- **Loading:** 
  - *Fetch Loading:* "What's New" card shows subtle shimmer placeholders while fetching.
  - *Deep-Link Loading:* CTA shows a spinner, width locked, and a toast reads "Opening the store."
- **Error:** CTA text temporarily changes to "Try Again". Error toast appears above the button. No red color is used.
- **Offline:** Screen renders normally. Optional offline banner appears at the top. CTA remains tappable but will trigger the Error state if the store is unreachable.
- **Success:** App backgrounds when the store successfully opens. If the user returns without updating, CTA resets to default.
- **Disabled:** Not applicable. The CTA is never permanently disabled; it must always allow a retry attempt to hand off to the external store.

### 10. Motion & interaction
- **Physical easing:** Standard physical easing (ease-in-out). 150-250ms duration for state transitions (loading spinners, toast appearances).
- **Entrance:** Choreographed staggered fade-ins. Screen fades in, followed by wordmark, icon scale-in, badge spring-in, and text cascade (~1.0s total).
- **Glow behavior:** The CTA maintains a subtle, infinite sinusoidal glow pulse (`--glow-you`) to draw the user's eye to the sole available action.
- **Haptics:** Medium impact haptic on Tap (CTA). Error haptic (triple pulse) on failure.
- **Gesture Intercepts:** Swipe down/right (edge) are explicitly blocked. Android hardware back is consumed; repeated presses trigger a supportive toast.
- **Reduced-motion path:** Entrance animations and persistent CTA pulses are instantly neutralized. The UI renders statically, fully visible, relying on high-contrast copy rather than motion to direct the user.
