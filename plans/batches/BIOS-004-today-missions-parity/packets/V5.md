import { useEffect, useRef, useState } from 'react';
import type { JSX } from 'react';
import {
  AccessibilityInfo,
  Animated,
  Easing,
  LayoutChangeEvent,
  LayoutRectangle,
  Pressable,
  StyleSheet,
  Text,
  TextInput,
  View,
  ViewStyle,
} from 'react-native';

import { BalenciaColors, Radius, Spacing, TouchTarget } from '@/constants/theme';

// ─── Hook: useReducedMotion ─────────────────────────────────────────────
export function useReducedMotion(): boolean {
  const [reduceMotion, setReduceMotion] = useState(false);
  useEffect(() => {
    const handle = (isReducedMotion: boolean) => setReduceMotion(isReducedMotion);
    AccessibilityInfo.isReduceMotionEnabled().then(handle);
    const sub = AccessibilityInfo.addEventListener('reduceMotionChanged', handle);
    return () => sub.remove();
  }, []);
  return reduceMotion;
}

**§1 — Plan-vs-live correction (the `Honesty` type name).** The plan's §3 block declares `export type Honesty = 'real' | 'low' | 'null';` inside `ProgressRing.tsx` (packet 1a) and every other component — including this one — references the bare name `Honesty` in its prop signature without re-declaring it, implying one shared export. But §5's dependency table lists packet **1e (this packet) as depending on W0 only**, not on 1a — `ProgressRing.tsx` is not guaranteed to exist when this file is authored or typechecked standalone, and if it does exist, a future barrel (`export * from './progress-ring'; export * from './momentum-bar';`) would hit a duplicate-export collision if both files independently declare a type literally named `Honesty`. **Resolution for this packet:** declare the identical three-value union under a locally-scoped, differently-named export — `MomentumHonesty` — so this file typechecks standalone per its real W0-only dependency and never collides with a same-named export elsewhere. TypeScript is structural for string-literal unions, so `state?: MomentumHonesty` is fully contract-equivalent to `state?: Honesty` for every caller: passing `'real' | 'low' | 'null'` type-checks identically regardless of the alias name. Whoever authors the shared barrel (packet 1f) or `ProgressRing.tsx` (1a) later is free to reconcile naming; that reconciliation is out of scope here.

**§2 — Track color (the `chartTrack` vs. `StatBar` choice).** Packet F1 added `BalenciaColors.chartTrack` (`'rgba(255, 255, 255, 0.08)'`) and scoped its own comment explicitly to "ProgressRing track, TrendChart gridlines" — the SVG arc/line siblings, not `MomentumBar`. ADR-1 groups `MomentumBar` with `StatBar` (not with `ProgressRing`/`TrendChart`) as the "box/fill" family. This packet therefore reuses `StatBar`'s existing literal (`'rgba(254, 250, 243, 0.08)'`) for the track, matching its direct architectural sibling rather than the arc/line viz chrome token. **§4 — Honesty-state behavior (mechanical, derived from ADR-2 + COMPACT-CANON §7 — no invention left to the worker):**
- **`state === 'real'` (default):** `percent = clamp(0, 100, max > 0 ? (value / max) * 100 : 0)`. Render the fill at that percent, full opacity, color = `glow === 'done' ? BalenciaColors.green : BalenciaColors.orange`. If `label` is provided, render it above the track at full `paper100` weight.
- **`state === 'low'`:** same `percent` computation and fill color, but fill **and** label opacity reduced to `0.64` — this exact figure is not invented; it is COMPACT-CANON §3's own number for a low-confidence `GlassStatCard` KPI ("KPI at 64%, `estimated · low confidence` Caption"), reused here so the whole viz kit shares one "muted" magnitude. The component does **not** auto-append the string `"estimated · low confidence"` — per ADR-2's explicit precedent for `ProgressRing` ("honest copy via caller"), the caller supplies whatever copy belongs in `label`; this leaf component only applies the muted styling.
- **`state === 'null'`:** `value`/`max` are **never read** for sizing — no fill element renders at all (not a ghosted/dimmed fill, no fill). This is the literal ADR-2 requirement: "`null` → HonestNullState — no invented geometry: ... MomentumBar empty track. Never a fabricated number." The track itself still renders (empty). If `label` is provided it renders in `paper70`/regular weight (matches `HonestNullState`'s "Body-light" treatment in `states.tsx`/COMPACT-CANON §2, without importing that component). If `label` is omitted, no text renders — the component must never invent honest-null copy itself.

**§5 — Motion (ADR-6 + ADR-1, reconciled).** Animate the fill's *progress* via **`transform: [{ scaleX }]`** with `transformOrigin: 'left'`, driven by a Reanimated `useSharedValue`/`withTiming` — **not** the CSS `width` property. ADR-1's "(width/opacity/transform)" phrase for this component family is read as "the available toolkit," while ADR-6 is the binding, more specific rule for this batch's shared motion system: "Animate transform/opacity only (no color/blur/shadow animation)." A `transform`-driven fill on top of a fixed-width container satisfies both: visually identical to animating `width`, but GPU-composited and non-layout-thrashing (also required by the parent repo's `yhealth-app/CLAUDE.md` §9: "Animate only `transform` and `opacity` on hot paths"). Duration = `MotionDuration.bandFill` (250ms — this is literally the duration named for this component's context: spec S13 "Board Summary Band fills L→R (250ms)"). Easing = `Easing.bezier(...MotionEasing.physical)` (import `Easing` from `'react-native-reanimated'`, per `motion.ts`'s own guidance comment). **Reduced motion:** when `useReducedMotion()` is `true`, skip `withTiming` entirely and set the shared value straight to the target (ADR-6: "skip to final static state"). The fill's warm-glow shadow (`shadowColor`/`shadowOpacity`/`shadowRadius`, same idiom as the existing focus-glow in `auth-inputs.tsx`) is a **static** style, not animated — ADR-6 bans animating shadow, not merely having one present.

**§6 — Non-interactive; the "44px" rule is N/A here.** `MomentumBarProps` has no `onPress`/handler of any kind — it is a passive, read-only progress indicator (matches its usage sites: S12 Today's Actions and S13 Board Summary Band both show it as a display element, never a control). Do not add a `Pressable`/`TouchableOpacity`/`onPress` — none is in the contract and inventing one would be scope creep. The shared preamble's "44px min interactive targets" rule is therefore satisfied vacuously (no interactive element exists to violate it) — verified mechanically by the *absence* of `Pressable`/`TouchableOpacity`/`onPress` in the file (see Acceptance §7).

## Out of scope
