# Functional Content Brief: CIA Voice Mode (In-Chat)

## 1. Purpose
Provides a quick, hands-free voice input method directly within the existing chat interface, transcribing speech to text in real-time. Designed for short, practical inputs while maintaining full conversational context.

## 2. Entry and Exit Paths
*   **Entry:** Activated from CIA Chat [09] via mic button tap. This is a UI state change, not a navigation push.
*   **Primary Exit:** Returns to CIA Chat [09] text mode by tapping the stop/send button (sends transcription), swiping down, or tapping cancel (discards).
*   **Secondary Exit:** Automatic exit after 3 seconds of silence (auto-send) or 8 seconds of total silence from start (auto-cancel). 
*   **Tab Navigation:** Bottom tab bar remains visible and tappable at 40% opacity; tapping a tab gracefully exits voice mode.

## 3. Information Architecture
**Layout is structured top-to-bottom as:**
1.  **Status Bar:** System status.
2.  **Top Bar:** Unchanged from CIA Chat [09]. Displays "CIA" title and highlighted Voice icon.
3.  **Chat Message Area:** Compressed upward (~148pt). Retains conversational history and auto-scrolls. Hosts the Draft Transcription Bubble.
4.  **Voice Interface Panel:** Replaces the keyboard area (~200pt height). Contains:
    *   Status Label
    *   Waveform Visualization
    *   Cancel Button (Left) & Stop/Send Button (Right)
5.  **Bottom Tab Bar:** Dimmed (40% opacity).
6.  **Home Indicator:** System gesture area.

## 4. Features & Capabilities
*   **Real-time Speech-to-Text:** Streaming transcription that appears character-by-character as the user speaks.
*   **Draft Transcription Bubble:** Displays transcribed text inside a provisional chat bubble. 
*   **Auto-Send Timers:** Automatically sends the transcript after 3 seconds of silence or at the 60-second maximum recording limit.
*   **Idle Auto-Cancel:** Automatically cancels and dismisses the voice panel if no speech is detected for 8 seconds.
*   **Manual Control:** Explicit controls to cancel (discard) or stop and send the transcription.
*   **Accessibility-Forward:** Screen reader live-regions announce transcription text and dynamic button states.

## 5. UI Copy (Verbatim Strings)
*   **Status Indicators:** "listening." / "processing." / "say something, or tap cancel."
*   **Action Buttons:** "cancel"
*   **Error - Silence:** "No voice detected. Try again or tap cancel." (Toast)
*   **Error - Transcription:** "Couldn't hear that. Try again."
*   **Error - Network:** "Connection lost."
*   **Error - Permissions:** "Microphone access needed." / "Enable in settings"
*   **Screen Reader (Enter):** "Voice input mode active. Microphone listening. Speak now or tap stop to send."
*   **Screen Reader (Send Button):** "Stop recording and send voice message" (Active) / "Send voice message" (Ready)
*   **Screen Reader (Cancel Button):** "Cancel voice input and return to text mode"

## 6. Data Fields & Metrics
*   **Transcription Text:** User's speech. *Source:* Streaming Speech-to-Text API.
*   **Audio Input Levels:** Microphone volume. *Source:* Device microphone (sampled at 30-60fps).
*   **Silence Timer:** Tracks continuous silence. *Source:* Local device timer.
*   **Max Duration Timer:** Tracks total recording time. *Source:* Local device timer (caps at 60s).

## 7. Screen States
*   **Cold-Start (Day 1):** Panel slides up; waveform idle; status "listening.".
*   **Active/Listening:** Text appears in draft bubble; waveform bars dance; status pulses.
*   **Processing:** Speech stops; waveform morphs to a spinner; status reads "processing."; draft border transitions from dashed to solid.
*   **Ready-to-Send:** Spinner disappears; send button glows; draft bubble appears as a solid user message.
*   **Sent:** Draft merges into chat; CIA thinking indicator appears.
*   **Error - Transcription Failed:** Waveform greys out; status reads "Couldn't hear that. Try again.".
*   **Error - No Speech Detected (8s):** Auto-cancels; toast appears "No voice detected. Try again or tap cancel."
*   **Error - Mic Permission Denied:** Waveform greys out; stop button disabled; status reads "Microphone access needed." with an orange "Enable in settings" link.
*   **Error - Network/Offline:** Waveform freezes; status reads "Connection lost."; send button disabled; partial draft text retained.
*   **Reduced-Motion:** All animations and loops are instantly resolved to their final settled visual state.

## 8. Interactions, Gestures & Motion
*   **Taps:** Tap Stop/Send to finalize; Tap Cancel to discard; Tap "Enable in settings" to fix permissions.
*   **Swipes:** Swipe down on the voice panel to dismiss/cancel.
*   **Motion (Enter/Exit):** Panel slides up 200pt (280ms) replacing the keyboard. Tab bar dims simultaneously. On exit, panel slides down.
*   **Motion (Elements):** Draft border solidifies over 160ms. Stop icon crossfades to Send icon over 160ms. Waveform bars draw vertically in real-time based on audio input.
*   **Motion Constraints:** No urgency animations (flashing, rapid pulses). 

## 9. Free vs. Premium Gating
*   **CONTRADICTION FLAG:** The source documents do not explicitly define a premium gate for the in-chat voice mode. The base spec states "Voice mode is a universal input method—it doesn't adapt by motivation tier." However, the Audit Feedback explicitly requires privacy and raw-audio handling states. *Recommendation:* Treat real-time voice input as a baseline feature, but ensure consent and privacy gates do not block core functionality.

## 10. Cross-Domain Hooks
*   **Practical Life Logging:** The feature is explicitly designed to capture cross-domain raw data quickly (e.g., "I just did 30 pushups", "Log my prayer", "What should I eat for lunch?").
*   **CIA Processing Handoff:** Once the voice transcript is sent, the CIA (coach) takes over, utilizing the motivation tier rules and historical context from other life areas defined in CIA Chat [09] to generate a text response.
