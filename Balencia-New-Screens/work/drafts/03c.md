# Balencia Hi-Fi Screen Spec: 03c-consent

## 1. Header
* **Screen ID:** 03c
* **Name:** Privacy consent
* **Route(s) covered:** `/onboarding/consent`
* **Tab:** Hidden (Pre-auth)
* **Source:** Functional Content Brief: Privacy Consent
* **Batch:** 2

## 2. Purpose
The legal gateway requiring explicit, non-shaming acceptance of Terms of Service and Privacy Policy before onboarding proceeds. The account exists at this stage; progression is strictly gated by explicit user consent, unblocking the CIA persona on the next screen. 

## 3. Entry & exit
* **Arrives from:** 
  * OTP Verification [03b] via stack push (email registration path).
  * Complete Profile [03d] via stack push (social auth path).
* **Primary Exit:** CIA Onboarding [07] via stack push upon API success.
* **Abandonment:** Force-quitting the app returns the user to this screen on next launch (no back button). 

## 4. Layout anatomy
**Regions top-to-bottom:**
1. **Status Bar Zone:** System default, over atmosphere.
2. **Brand Anchor:** Balencia wordmark and 48x48pt symbol, centered.
3. **Header Zone:** Heading and supporting subtitle, centered. 
4. **Required Consents Card:** `SolidCard` housing two mandatory gating rows separated by a hairline. 
5. **Optional Consents Card:** `GlassCard` housing the marketing opt-in toggle.
6. **Acceptance Read:** Progress indicator and system messaging.
7. **Primary CTA:** Full-width submission button.
8. **Home Indicator:** System safe area.

## 5. Components
* **ConsentCard**: Used for the Optional Consents container (Variant: `default`).
* **SolidCard**: Used for the Required Consents container (Variant: `default`).
* **ListRow**: Used to layout the policy toggles (Variant: `interactive`).
* **Toggle**: Native toggle component used for the marketing opt-out (Variant: `default`).
* **BtnPrimary**: Full-width submission button.
* **ChipProvenance**: Displayed dynamically below the CTA if the user is offline.
* **NEW: ConsentCheckbox:** A custom 24px checkbox utilizing an orange fill (`#FF5E00`) and paper-50 check. *Rationale:* The component catalog lacks a dedicated legal checkbox; custom creation ensures the 44pt touch target expands independently of the visual 24px bounds while cleanly toggling state.

## 8. Data & honesty states
**Consent Acceptance Count (Derived Local State):**
* **Real:** Value displays as "2 of 2 · ready" (Provenance: `local state`).
* **Low-confidence:** *Not applicable.* (Booleans do not have estimation; a checkbox is explicitly checked or unchecked).
* **Honest-null:** "0 of 2 required" (Displays on cold start. Never fakes a pre-checked box).

**Network Sync Status:**
* **Real:** Connection established, `POST /api/auth/consent` resolves successfully. 
* **Low-confidence:** *Not applicable.* 
* **Honest-null (Offline):** Accept requires a *network* connection. Accompanied by a ChipProvenance chip: `offline`.

## 9. All states
* **Default (Cold Start):** Both required boxes unchecked. Optional toggle OFF. Acceptance read shows "0 of 2 required". CTA is at 40% opacity and non-interactive.
* **Partial Accept:** One required box checked. Acceptance read shows "1 of 2 required". CTA remains disabled.
* **Gate Ready (Pre-submit):** Both required boxes checked. Acceptance read turns Forest Green showing "2 of 2 · ready". CTA becomes fully opaque.
* **Loading:** API POST is in flight. CTA text crossfades to a 24px spinner. CTA becomes non-interactive. Width locked.
* **Success:** Brief 250ms forest green flash on the CTA, then stack push navigation.
* **Inline Error:** Triggered if gate logic is somehow bypassed and an invalid state is submitted. CTA shakes horizontally 10px. Error text slides down below CTA.
* **Network Error / Server Error:** Triggered on API failure. Reverts CTA to default gate-ready state. Error toast slides down from top status bar.
* **Offline:** Device loses connection. CTA text changes to "Accept requires a *network* connection". CTA is disabled. 

## 10. Motion & interaction
* **Physical Easing:** `cubic-bezier(0.32, 0.72, 0, 1)` for all entrance and toggle transitions.
* **Timing:** 150-250ms for snappy tap feedback on checkboxes and toggles. 
* **Screen Entrance:** Staggered fade-in moving downwards. Logo (0ms) -> Header (50ms) -> Cards (100ms) -> CTA (150ms). 
* **Checkbox/Toggle Interaction:** Snappy fill animations. Tapping the label text triggers the checkbox exactly as tapping the box does. The 44pt touch target expands invisibly around the row.
* **CTA Enable/Disable:** Smooth 200ms opacity and fill crossfade based on gate state.
* **Error Messaging:** Slides down 10px and fades in when appearing; slides up and fades out when dismissed.
* **Success:** Brief 250ms forest green flash before navigation.
* **Glow Behavior:** The Optional Consents card bleeds a subtle `--glow-you` that brightens by 10% when the marketing toggle is flipped ON. 
* **Haptics:** Light impact haptic on checking the second required box (Gate Ready).
* **Reduced-motion path:** All staggers and slides collapse to simple opacity fades. Success flash is a static color swap.

## 11. Motivation-tier adaptation
* **Low Density (Privacy-First):** Optional marketing consent card is collapsed into a single ghost-link reading "Email preferences" to minimize cognitive load and dark patterns. 
* **Medium Density (Canonical):** Default spec. Optional consent expanded, clear 2-of-2 read.
* **High Density (Enterprise/Strict):** The Acceptance Read expands into a segmented `ProgressBar` illustrating exactly which legal document is pending, and adds a tertiary ghost button linking to a centralized "Data Control" center.

## 12. Accessibility
* **Contrast:** Paper-100 (#FEFAF3) on `--surface-2` (#211008) exceeds AAA contrast (16.5:1). Paper-64% on `--surface-2` passes AA strictly. 
* **Touch Targets:** ConsentCheckbox visual is 24px, but the entire `ListRow` provides a minimum 52px vertical touch target. Toggle thumb target expands to 44px via invisible padding. 
* **Screen-reader labels:** 
  * Terms Checkbox: `Checkbox, unchecked. Accepts Terms of Service. Button.`
  * Privacy Checkbox: `Checkbox, unchecked. Accepts Privacy Policy. Button.`
  * Links: `Link. Opens Terms of Service in webview.`
* **Dynamic Type:** Honored up to `accessibilityExtraExtraLarge`, at which point the layout safely enables vertical scrolling.
