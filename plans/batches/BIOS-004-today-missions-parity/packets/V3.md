# Packet V3 — GlassStatCard (flush-mode metric/ring/sparkline workhorse tile)

## Objective

Create the **GlassStatCard** component — the canon "workhorse" stat tile (`COMPONENT-CATALOG.md`: "Overline label · KPI (tabular-nums, 28–40) · delta · ChipProvenance · semantic glow"). It is honesty-driven: every value it renders comes from a `Metric<T>` and must resolve to one of three visible states (real / low-confidence / honest-null) — **never a fabricated number**. It supports three variants (`metric`, `ring` embedding `ProgressRing`, `sparkline` embedding a mini `TrendChart`), a semantic glow (`you`/`done`/`cia`, one per card, meaning-stated — never decorative), and a **flush** sub-mode (no border/blur/shadow) used by the S42 celebration screen to inherit its parent `FrostCard`'s chrome.

This is packet **1c** in architecture-plan.md §5's wave-1 decomposition. Per this batch's explicit target-path override (below), it creates exactly **one** file.

```typescript
import type { Provenance } from '@/components/balencia/states';

export type Metric<T = number> = {
  value: T | null;
  display: string;
  provenance: Provenance;
};

type RealSource = Extract<Provenance, { kind: 'real' }>['source'];

export function realMetric<T>(
  value: T,
  opts: {
    source: RealSource;
    label?: string;
    format?: (v: T) => string;
  },
): Metric<T> {
  const format = opts.format ?? ((v: T) => String(v));
  const label = opts.label ?? 'Real data';
  return {
    value,
    display: format(value),
    provenance: { kind: 'real', source: opts.source, label },
  };
}

export function nullMetric<T = number>(label?: string): Metric<T> {
  return {
    value: null,
    display: '—',
    provenance: { kind: 'null', label: label ?? 'Not enough data yet' },
  };
}

export function lowMetric<T>(
  value: T,
  label: string,
  format?: (v: T) => string,
): Metric<T> {
  const fmt = format ?? ((v: T) => String(v));
  return {
    value,
    display: fmt(value),
    provenance: { kind: 'low', label },
  };
}

export function fromNullable<T>(
  value: T | null | undefined,
  opts: {
    source: RealSource;
    label?: string;
    nullLabel?: string;
    format?: (v: T) => string;
  },
): Metric<T> {
  if (value === null || value === undefined) {
    return nullMetric<T>(opts.nullLabel);
  }
  return realMetric(value, {
    source: opts.source,
    label: opts.label,
    format: opts.format,
  });
}
```

### Resolved interpretation notes (binding — fill contract gaps the plan leaves implicit; do not deviate)

1. **Variant layout.**
   - `variant: 'metric'` (default): Overline row → KPI text + optional delta (same row) → `ProvenanceChip`. No embedded chart.
   - `variant: 'ring'`: Overline row → embedded `<ProgressRing progress={typeof metric.value === 'number' ? metric.value : 0} state={metric.provenance.kind} glow={glow} centerLabel={metric.provenance.kind === 'null' ? null : metric.display} animateOnMount={!reduceMotion} />` (no defaults overridden — use `ProgressRing`'s own `size`/`stroke` defaults) → optional delta row (if `delta` provided) → `ProvenanceChip`. No standalone KPI `Text` in this variant — the ring's `centerLabel` carries the number.
   - `variant: 'sparkline'`: Overline row → KPI text + optional delta (same row, as in `metric`) → embedded `<TrendChart points={(sparkline ?? []).map((y, i) => ({ x: i, y }))} state={metric.provenance.kind} height={56} />` (mini height, distinct from `TrendChart`'s own 160 default) → `ProvenanceChip`.
2. **KPI text rendering by honesty state** (drives opacity/color, not the text content — `metric.display` is rendered verbatim in all cases, already `'—'` for null per `nullMetric()`):
   - `real`: `color: BalenciaColors.paper100`, `opacity: 1`.
   - `low`: `color: BalenciaColors.paper100`, `opacity: 0.64` (catalog: "KPI at 64%" — literal, applied via RN `opacity` style, not a new color token).
   - `null`: `color: BalenciaColors.paper55`, `opacity: 1` (a distinctly muted color reads better on a bare em-dash than partial transparency — composer decision, not a literal catalog spec).
   - KPI style: `fontSize: 32` (mid of catalog's "28–40" range), `fontWeight: '800'`, `fontVariant: ['tabular-nums']` (matches the existing `auth-inputs.tsx`/`consent-screen.tsx` tabular-nums precedent — do not set `fontFamily`; no custom font is wired up in this app yet, house style is system font + `fontWeight`).
3. **Delta rendering — honesty-gated.** Render the delta element **only when `delta` is provided AND `metric.provenance.kind !== 'null'`** (never show a trend arrow next to an unresolved metric — this is a direct extension of the honesty invariant, not new scope). Tone → glyph + color (catalog: "delta (green ▲ / orange ▼ with meaning, never red-vs-green moralizing)"):
   - `'up'`: `'▲'` prefix, `color: BalenciaColors.green`.
   - `'down'`: `'▼'` prefix, `color: BalenciaColors.orange`.
   - `'flat'`: `'•'` prefix, `color: BalenciaColors.paper70` (not in the catalog literally — composer decision for the third tone value the contract's type requires).
   Render as `` `${glyph} ${delta.value}` ``, `fontSize: 13`, `fontWeight: '700'`.
4. **Overline style.** `fontSize: 12`, `fontWeight: '700'`, `textTransform: 'uppercase'`, `color: BalenciaColors.paper55` (matches the existing `card.tsx` `MetricTile` label style exactly, for visual consistency).
5. **Glow → chrome mapping** (non-flush only; applies to the outer container):
   | `glow` | background | border | shadow (iOS) / elevation (Android) |
   |---|---|---|---|
   | `undefined` | `BalenciaColors.inkBrown800` | `BalenciaColors.hairline` | none |
   | `'you'` | `BalenciaColors.orangeSoft` | `'rgba(255, 94, 0, 0.32)'` | `shadowColor: BalenciaColors.orange` |
   | `'done'` | `BalenciaColors.greenSoft` | `'rgba(52, 168, 83, 0.32)'` | `shadowColor: BalenciaColors.green` |
   | `'cia'` | `BalenciaColors.purpleSoft` | `'rgba(127, 36, 255, 0.32)'` | `shadowColor: BalenciaColors.purple` |

   Shadow, when a `glow` is set and `flush` is false: `shadowOffset: { width: 0, height: 0 }, shadowOpacity: 0.2, shadowRadius: 8, elevation: 2` (exact values from the `auth-inputs.tsx` focus-glow precedent embedded above — RN has no directional/anchored box-shadow, so this centered-shadow approximation is the established house pattern, not the CSS radial-gradient recipe in COMPACT-CANON §"Semantic Inner Glow", which is reserved for `CIAPresenceOrb`'s `expo-linear-gradient` orb per ADR-1's box/fill-vs-orb split). This glow is **static styling, not an animation** — it is not gated by `useReducedMotion()` (only the `ProgressRing` embed's `animateOnMount` is).
   Border width: `1` when not flush, regardless of glow; `borderRadius: Radius.xl` (see theme.ts note above); `padding: Spacing.three`; row `gap: Spacing.two` (matches the `card.tsx` `GlassCard` container's own `gap: Spacing.two`, for visual rhythm consistency).
6. **`flush: true`.** Overrides the entire glow table above to: `backgroundColor: 'transparent'`, `borderWidth: 0`, no `shadowColor`/`shadowOpacity`/`shadowRadius`/`elevation` keys at all (regardless of what `glow` is set to) — "inherits FrostCard chrome" (S42 spec). Padding/gap/KPI/delta/chip rendering are otherwise unchanged from the non-flush path.
7. **Breathing is a composition concern, not a GlassStatCard concern.** The contract has no `breathe` prop — do not add one. ADR-6 requires "one glow rhythm per screen" (never every glowing card breathing independently), so which card(s) breathe is decided per-screen by the composing screen (wave 4a/4b packets), not by this leaf component. This packet renders a **static** glow only.
8. **Skeleton state is not a GlassStatCard prop.** The catalog lists "skeleton" as one of GlassStatCard's states, but the given contract has no loading flag. Per the existing house pattern (`states.tsx`'s `SkeletonState`/`LoadingState`), callers swap in `<SkeletonState variant="card" />` in place of `<GlassStatCard>` while loading — this component does not implement its own skeleton branch.
9. **Not interactive.** The contract has no `onPress`. Render the outer container as a plain `View` (not `Pressable`/`TouchableOpacity`) — there is no touch target in this component, so the "44px minimum touch target" house rule does not create a mandatory `Pressable` here. If a future packet wraps this component in a `Pressable`, that wrapper (not this file) owns the 44px sizing.
10. **Accessibility.** Outer `View` gets `accessibilityRole="summary"` (data tile, not text/button) and a composed `accessibilityLabel`: `` `${overline}: ${metric.display}${delta && metric.provenance.kind !== 'null' ? `, ${delta.tone} ${delta.value}` : ''}. ${metric.provenance.label}.` ``. Pass `testID` straight through to the outer `View`.
