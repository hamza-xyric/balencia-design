# Balencia Screen Spec: 66-notification-permission

### 1. Header
* **ID:** 66
* **Name:** notification-permission
* **Route(s) covered:** Onboarding stack push (first-launch); Modal presentation (re-entry).
* **Tab:** N/A (Onboarding flow / Modal overlay).
* **Source:** Functional Content Brief: Notification Permission.
* **Batch:** 3

### 2. Purpose
To dramatically improve iOS push notification opt-in rates by using a pre-permission interstitial. It frames the request around concrete, cross-pillar benefits and provides a "soft exit" so users who aren't ready don't permanently burn the one-shot iOS system prompt.

### 3. Entry & exit
* **Entry Paths:** 
  * **First Launch (Stack Push):** CIA Onboarding [07] / Initial Plan Summary [08] → Notification Permission [66].
  * **Re-entry (Modal Slide-up):** Triggered contextually from Settings [21], Accountability Partners [46], or Reminders [61] when a feature requires notifications but access is undetermined or denied.
* **Exit Paths:**
  * **Allow:** Taps CTA → Allows in OS dialog → Auto-dismisses → Navigates to Home [12] or requesting screen.
  * **Deny (System):** Taps CTA → Denies in OS dialog → Brief acknowledgment → Navigates to Home [12] or requesting screen.
  * **Skip:** Taps "Not now" → Dismisses immediately without triggering OS dialog → Navigates to Home [12] or requesting screen.
* **Correction/Refinement:** The brief notes a "Success (Already Granted)" state where the CTA crossfades to green. As an entry path, this is illogical—if the app knows permission is already granted via OS APIs (`UNUserNotificationCenter.authorizationStatus`), it should never render this screen and block the user's flow. This state is recast strictly as a **transient success confirmation** (e.g., user taps "Enable", approves in the OS dialog, and returns to the app to see this state for 1.5 seconds before auto-navigation).

### 4. Layout anatomy
The screen is fixed to a single viewport (390x844) with no scrolling. The layout is structured top-to-bottom to anchor visual weight in the center while pushing actions to the ergonomic thumb zone.

**Regions:**
1. **Status Bar Zone:** System time/icons.
2. **Top Spacer:** 48px breathing room.
3. **Hero Illustration Area:** 160px high visual anchor containing the bell and floating chips.
4. **Title Block:** Value proposition.
5. **Subtitle Block:** Contextual explanation.
6. **Benefits Block:** Three list rows detailing feature-specific reasons.
7. **Flexible Spacer:** Absorbs remaining vertical space.
8. **Primary Action Zone:** Full-width CTA.
9. **Secondary Action Zone:** Skip link.
10. **Bottom Padding:** 34px safe area for home indicator.

### 5. Components
* **BtnPrimary** (Variant: default): Used for the primary CTA. Retains 52px height, but spans full container width minus padding.
* **BtnGhost:** Used for the "Not now" skip action.
* **NEW: NotificationIllustration:** Rationale: The catalog does not contain hero illustrations. This screen requires a custom 3D/papercraft-style glass bell visual with floating UI chips to anchor the pre-permission moment visually without using a dry system icon.
* **NEW: BenefitListRow:** Rationale: A standard `ListRow` is 56px and relies on chevrons/toggles. This educational context requires a custom two-line row (Title + Body-light desc) with domain-colored leading glyphs and no trailing actions, specifically tuned for reading hierarchy.

### 6. Visual treatment
* **Glass Tier:** This screen acts as a full-bleed atmosphere layer rather than relying on overlapping cards. The background uses the mandatory warm dark base with the top-center radial glow.
* **Semantic Inner-Glow:** The CTA button (`BtnPrimary`) utilizes the `--glow-you` recipe (bottom-anchored bleed). 
  * *Why:* This screen requests a fundamental, active modification to the user's system. The `--glow-you` color represents effort and user action, preparing them to interact with the OS.
* **Background Atmosphere:** `radial-gradient(90% 60% at 50% -10%, rgba(255,94,0,.18), transparent 60%)` layered over `--bg-base` (`#0A0A0F`). A 3% static grain overlay is applied globally to prevent banding in the dark gradient.
* **The Hero Type Moment:** The word *track* in the H1 title is set in Tiempos Medium _italic_ to anchor the focal hierarchy and break the geometric sans-serif grid with editorial warmth.

### 9. All states
* **Standard (Default):** Full visual content, CTA reads "Enable notifications". 
* **Loading:** Illustration ghosts to 40% opacity, benefit text becomes skeleton shimmer, CTA shows spinner (width locked), loading copy visible below button.
* **Success (Transient):** CTA crossfades to `BtnSuccess` (green fill) with a checkmark, success copy visible.
* **System Denied (Hard Blocked):** CTA text changes to "Got it" briefly, dims to 40% opacity, then screen transitions out. (Re-entry variant changes CTA to "Open settings").
* **Error:** CTA reverts to Default state, inline error copy visible below CTA. No red borders/error glyphs used.
* **Offline:** CTA dimmed to 50% opacity, CTA glow pulse disabled, offline copy banner visible below subtitle.
* **Disabled:** *Not applicable.* The screen either successfully accepts a tap or defers to the "Not now" ghost button.

### 10. Motion & interaction
* **Physical Easing:** Standard physical ease (`cubic-bezier(0.32, 0.72, 0, 1)`) for all UI slides.
* **Entrance:** Staggered fade-in and slide-up for content blocks over ~1.1 seconds. Bell springs in, followed by floating chips (staggered), then text rows sliding from left.
* **Idle:** Gentle, continuous bell swaying (3s loop). Notification chips float continuously (ease-in-out). CTA maintains a subtle, calm, continuous warm-glow "breathe" (opacity 0.8 -> 1.0).
* **Haptics:** 
  * Tap CTA: Medium impact haptic.
  * Tap "Not now": Light impact haptic.
* **Gestures:** Swipe down dismisses modal (acts as "Not now") *only* on re-entry context. Disabled on first launch stack push.
* **Reduced Motion (`prefers-reduced-motion: reduce`):** Disables entrance, idle bell/chip animations, and CTA pulse. Elements appear instantly in final positions. Static inner-glow remains visible to preserve premium aesthetic.

### 11. Motivation-tier adaptation
* **Low Density:** Benefits block is hidden. Layout relies strictly on the Hero Illustration and Title/Subtitle to convey value quickly for users who want to rush through onboarding.
* **Medium Density (Default):** Benefits block shown with two-line rows (Title + Body-light description). 
* **High Density:** Title font size reduces slightly; Benefits block expands to include predictive provenance chips (e.g., `protects: 14-day streak` next to Streak Protection).

### 12. Accessibility
* **Color Contrast:** 
  * `#FEFAF3` text on `--bg-base` (`#0A0A0F`) = 19.1:1 (AAA).
  * `--glow-you` (`#FF5E00`) on `--bg-base` = 5.2:1 (AA for large text/icons).
* **Targets:** BtnPrimary exceeds 44px minimum target height. "Not now" BtnGhost meets 44px minimum target height.
* **Screen Reader:** The `NotificationIllustration` is decorative and grouped with `accessibilityIgnoresInvertColors` / hidden from VoiceOver. Title and Subtitle are read sequentially. 
* **Dynamic Type:** The flexible spacer compresses as system font sizes scale up to `AX5`, preventing text truncation.
