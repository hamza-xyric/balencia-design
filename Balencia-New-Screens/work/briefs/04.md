### 1. Purpose
Facilitate fast, frictionless re-entry for returning users via manual credentials, social OAuth, or biometrics. Enforces strict validation and explicit trust preferences before granting access to the main application.

### 2. Entry and Exit Paths
*   **Entry Paths:** 
    *   Stack push from Welcome / Sign Up [03] (via "Already have an account? sign in").
*   **Exit Paths:**
    *   **Primary:** Home Screen [12] via root reset (successful authentication; auth stack is replaced by the main app).
    *   **Secondary:** Forgot Password [05] via stack push.
    *   **Tertiary:** Welcome / Sign Up [03] via stack pop (back button or "sign up" link).

### 3. Information Architecture (Top-to-Bottom)
1.  **Status Bar & Back Button Zone:** Device status bar; Back chevron (44x44pt target).
2.  **Brand Anchor:** Balencia symbol (48pt, centered).
3.  **Heading:** Emotional recognition copy.
4.  **Form Fields Group:** 
    *   Email Input Field
    *   Password Input Field (includes visibility toggle)
5.  **Recovery & Persistence Row:**
    *   Forgot Password Link (right-aligned).
    *   Remember Me Toggle (binary switch).
6.  **Primary Action:** "sign in" CTA button (hero element).
7.  **Alternative Paths Group:**
    *   Divider text.
    *   Social Auth Buttons (Google, Apple).
    *   Biometric Auth Button (conditional).
8.  **Navigation Link:** "Don't have an account? sign up".

### 4. Features and Capabilities
*   **Manual Authentication:** Email and password validation and submission.
*   **Password Visibility Toggle:** Ability to mask/unmask password characters.
*   **Session Persistence Toggle:** "Remember me" binary switch to extend session duration.
*   **Account Recovery:** Direct link to password reset flow.
*   **Social OAuth:** One-tap authentication via Google or Apple.
*   **Biometric Authentication (Face ID / Touch ID):** 
    *   *Auto-Trigger:* System native prompt fires automatically on screen mount if previously enabled.
    *   *Manual Trigger:* Dedicated biometric icon button to retry if auto-trigger fails or is dismissed.
*   **Biometric Opt-In Post-Login:** A bottom sheet prompt offering to enable biometrics for future logins, presented after a user's first successful manual or social sign-in.

### 6. Data Fields and Metrics
*   **Email Address**
    *   *Data Source:* User input (keyboard type: email-address, autocomplete: email).
*   **Password**
    *   *Data Source:* User input (secure entry).
*   **`rememberMe`**
    *   *Data Source:* Local UI state (boolean, sent with login request `POST /auth/login`).
*   **Biometric Cooldown Timer (429 Error)**
    *   *Data Source:* System/API rate-limit response (displays exact minutes remaining, updates dynamically).

### 7. Screen States Mentioned
*   **Cold-start / Day-1 (Empty):** Form is entirely blank; CTA is disabled. Biometrics are hidden. No error messaging.
*   **Disabled:** CTA renders at 40% opacity with no glow. Triggers when fields are empty, email format is invalid, or during the 429 rate-limit cooldown.
*   **Loading:** CTA text crossfades to a spinner. Optional loading toast: "Signing you in — one moment".
*   **Success:** Form collapses upward and fades out; success icon flashes briefly; root resets to Home Screen.
*   **Error - Wrong Credentials:** 2pt red borders and `✗` glyph on inputs. Error text below fields.
*   **Error - Account Not Found:** 2pt red border and `✗` glyph on email field only.
*   **Error - Network:** Error banner at the top. Form remains fully visible and interactive.
*   **Error - Too Many Attempts (429):** CTA disabled; Toast with red left-border, `!` glyph, and a continuous progress bar (MomentumBar) depleting toward re-enable.
*   **Biometric Triggered:** Form dims to 40% opacity; native OS biometric prompt appears.
*   **Offline / Cached:** All fields and CTA visible. Offline banner appears.

### 8. Interactions, Gestures, and Motion Intents
*   **Gestures:** Tap (focus fields, trigger links/buttons, toggle switches), iOS screen-edge swipe right (stack pop to previous screen).
*   **Motion Intents:**
    *   *Screen Mount:* Staggered fade-in of elements (logo first, then heading/form, then alternative auth paths).
    *   *Signature Animation:* The primary CTA "sign in" outline draws itself as a continuous animated stroke (520ms, ease-flow) upon load.
    *   *State Transitions:* Smooth dimming (160ms) when biometrics activate; snapping to 100% opacity on biometric dismiss; red icon pulse (400ms) on biometric failure.
*   **Accessibility Focus Order:** Back button -> Email -> Password -> Visibility toggle -> Forgot password -> Remember me -> Sign in CTA -> Google -> Apple -> Biometric icon (if present) -> Sign up link.

### ⚠️ Flagged Source Contradictions Resolved
1.  **CTA Enabled State:** The original layout spec ambiguously noted the CTA could be tapped with empty fields, while the component section mentioned disabled states. The Audit Feedback (Finding B02-F05) overrides both: **The CTA must be disabled (0.4 opacity, no haptic) until both email and password contain valid, non-empty input.**
2.  **"Remember Me" Default:** The IA spec hinted the toggle "may auto-trigger," contradicting the component state. The Audit Feedback (Finding B02-F06) establishes the source of truth: **The toggle defaults strictly to OFF**, making persistence an explicit user choice.
3.  **Persona Renaming:** Source text mentioned "SIA onboarding". This has been explicitly renamed to **CIA** per brief instructions. No occurrences of SIA remain.
4.  **Social Auth Marks:** The original ASCII wireframe described placeholders ("G" / "A"). The Audit Feedback (Finding B02-F07) overrides this: **Official, platform-compliant Google and Apple provider logos must be used.**
