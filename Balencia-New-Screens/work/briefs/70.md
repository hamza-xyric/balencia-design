### 1. Purpose
A searchable, filterable database of all available exercises allowing users to discover new movements, learn proper form, and select exercises for workout planning. Supports a backend database of 500+ exercises with muscle targeting, equipment requirements, difficulty levels, and instructional content.

### 2. Entry and Exit Paths
**Entry Paths:**
*   **Fitness Dashboard:** Via the "browse exercises" shortcut or FAB sub-action.
*   **Workout Detail (Planning Mode):** Via the "add exercise" button (passes context to enable the "Add to workout" CTA).
*   **Explore:** Via the Fitness section.

**Exit Paths:**
*   **Previous Screen:** Via stack pop (Back button).
*   **Exercise Detail (Modal):** Opens as a bottom sheet overlay.
*   **Workout Detail:** Via the "Add to workout" CTA within the detail sheet (when in planning context).

### 3. Information Architecture (Top-to-Bottom)
1.  **Navigation Header:** Back chevron + "Exercise Library" title.
2.  **Search Bar:** Real-time query input.
3.  **Muscle Group Filter Row:** Horizontally scrollable, single-select chips.
4.  **Equipment Filter Row:** Horizontally scrollable, multi-select chips.
5.  **Result Count:** Left-aligned dynamic text ("532 exercises").
6.  **Exercise Grid:** Virtualized 2-column masonry grid of exercise cards.
7.  **Exercise Detail Bottom Sheet (Modal):** Hero media, title, difficulty bar, muscle tags, equipment, instructional steps, common mistakes, variations, and target areas.
8.  **Conditional CTA (Fixed to Bottom of Modal):** "Add to workout" button (only when entered from Workout Detail).

### 4. Features and Capabilities
*   **Real-time Search:** Debounced (300ms) text search spanning exercise names, muscle groups, and equipment.
*   **Multi-axis Filtering:** 
    *   Muscle group: Single-select (AND logic with equipment).
    *   Equipment type: Multi-select (OR logic within equipment).
*   **Virtualized Browsing:** Grid handles 500+ items efficiently with pull-down-to-refresh.
*   **Exercise Detail Viewing:** Full instructional breakdown including numbered execution steps, common mistakes, variations, and a visual body outline target area.
*   **Contextual Workout Planning:** Direct injection of an exercise into an active workout plan via the detail sheet CTA.
*   **Offline Browsing:** Restricted search and viewing limited to locally cached exercises when network is unavailable.
*   **Accessibility:** Full screen reader labeling, focus rings, and 44pt minimum touch targets.

### 6. Data Fields and Metrics
*   **Total Exercise Count:** `[N] exercises` (Source: Local state / Exercise DB size)
*   **Exercise Name:** e.g., "Bench Press" (Source: `exercise.name`)
*   **Primary Muscle Group:** e.g., "Chest", "Legs" (Source: `exercise.muscle`)
*   **Secondary Muscle Groups:** e.g., "Triceps", "Shoulders" (Source: `exercise.secondaryMuscles[]`)
*   **Difficulty Level:** 1–3 ordinal scale dictating bar fill (Source: `exercise.difficulty`)
*   **Equipment Required:** e.g., "Barbell, flat bench" (Source: `exercise.equipment`)
*   **Instruction Steps:** Array of text strings (Source: `exercise.instructions[]`)
*   **Common Mistakes:** Array of text strings (Source: `exercise.mistakes[]`)
*   **Variations:** List of linked exercise IDs/names (Source: `exercise.variations[]`)

### 7. Screen States
*   **Cold-start / Hydrating:** 2-column skeleton grid with left-to-right shimmer. Empty difficulty track is present but unfilled.
*   **Loading (Per Card):** Track visible; fill animates from 0 to `level/3` as the card enters the viewport.
*   **Partial Load:** Successfully loaded cards render normally; failed cards simplify to name + muscle text only (omits image and difficulty bar). Silent retry on scroll-away-and-back.
*   **Empty:** Centered search icon + "No exercises found" message. Filters remain visible and active.
*   **Error (List Fetch):** Centered offline cloud icon + failure message + "retry" link. Filters visible but inert.
*   **Error (Detail Fetch):** Modal opens with skeleton, resolves to failure message + "retry" link after 5 seconds.
*   **Error (CTA Failure):** CTA flashes red border, changes to "Try again", triggers auto-dismissing error toast.
*   **Offline Mode:** Banner displayed below filters; grid restricted to cached data; search queries local cache only.
*   **Unknown Difficulty:** Ghosted (unfilled) track paired with "Unrated" text.
*   **Success (CTA):** Button text changes to "Added", flashes green glow for 600ms.
*   **Reduced Motion:** All bar rise animations, count-ups, and grid crossfades are bypassed; elements render instantly at their final state.

### 8. Interactions, Gestures, and Motion Intents
*   **Tap (Card):** Scales to 0.97, triggers light haptic, opens Detail Bottom Sheet. Sheet slides up (520ms, ease-flow).
*   **Tap (Filter Chip):** Toggles filter state, crossfades the grid content (280ms), count-up animation on result count text (280ms).
*   **Tap (Difficulty Row in Detail):** Expands to reveal plain-language gloss (160ms height expand).
*   **Tap (CTA in Detail):** Scales to 0.97, triggers medium haptic. On success, triggers success notification haptic.
*   **Drag Down (Detail Sheet):** Dismisses the modal (slides down, 280ms).
*   **Scroll (Grid):** Standard vertical scroll; StatBar fills animate their "rise" independently as they enter the viewport.
*   **Pull Down (Grid):** Triggers manual data refresh.

### 9. Free vs. Premium Gating
*   **Explicit Gating:** None defined on this screen. 
*   **Audit Hook:** Resolved decision Q19 notes that AI/voice features are gated to premium in the journal, but standard exercise browsing, searching, and viewing of details are fully available to free users. No visual lock icons or paywalls are present in this spec.

### 10. Cross-Domain Hooks
*   **Navigation Context:** The entire screen shifts behavior based on the *origin stack* (Workout Detail vs. General Fitness Dashboard), enabling it to act as both a standalone educational browser and an integrated planner module.
*   **Correlations / AI Insights:** None. This is strictly defined as a lightweight Product-Mode utility browser. AI insights, trend charts, and cross-life-area metrics (Finance, Nutrition, CIA) are deliberately omitted to prevent over-charting a catalogue screen.

### ⚠️ Source Contradictions & Resolutions
*   **Typography Sizing:** The detailed `## Typography` table dictates a `15pt` name and `12pt` muscle group. Later audit sections (`## Premium Craft` and the finalized wireframe) mandate an upgrade to `17pt` (name) and `13pt` (muscle/everything else) to match standard `CK-P3` locked tokens. **Resolution:** The 17pt/13pt standardized sizing supersedes the older table.
*   **Tab Bar Identity:** The initial ASCII wireframe contains a legacy typo (`SIA` in the bottom tab bar). **Resolution:** This has been renamed to **CIA** per global product rules; purple/identity UI elements for the CIA persona are deliberately excluded from this utility screen's data visualizations.
